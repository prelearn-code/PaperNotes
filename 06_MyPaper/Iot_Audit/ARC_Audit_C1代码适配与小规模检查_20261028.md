## 这次具体适配了什么

1. **S0 训练一次。** 使用真实 train1 前 21,600 条学习现有 SDA-GGD，得到 32 个字段组，冻结字段顺序、十进制尺度、FOR 最小值、位宽和 Base 位位置。train2 不参与训练。训练约 79.376 s；第二轮修正基线适配后复用了同一份 S0 分组，并记录训练输入、代码、种子与分组哈希来源，不把加载时间当作重新训练时间。
2. **固定规范与精确逃逸。** 新数据高于训练精度、超出位宽范围或训练常量发生改变时，使用逐字段精确十进制逃逸值；常规位串对应字段置零。逃逸值与时间、标签、私有编码信息一起加密。读取时恢复全部字段，并按精确数值与规范源核对。这个机制解决了旧逐日 FOR 坐标不能直接迁移的问题，但逃逸增加的成本也全部计入。
3. **跨文件 Base 库。** HMAC-SHA-256 对冻结规范与组身份下的 Base 位串产生 32 B ID；本地持久索引保存 ID、原始来源及页定位，按日查找历史项。只上传新 Base，多个小 Base 合并到最大 4,068 B 明文页，单个 Base 字节对齐且不跨页。已发布页不可改写。
4. **实际安全存储。** Base 页、偏差页和辅助信息页使用 AES-256-GCM；每日短引用表公开并被签名清单绑定；本地/云端保存同版 SHA-256 Merkle 索引；Ed25519 清单绑定版本、上一版本摘要、当前索引根和物理页承诺。单个归档内复用统一 BLS 参数，生成真实完整密文页标签。每个随机 epoch 派生加密密钥并使用唯一页 nonce。
5. **重启与解码。** 每日提交后重开 Store，用已持久化的 ID 索引继续追加；CloudReader 只从经签名/pin 验证的云端快照、引用与密文页解码。源 CSV 仅由计时外的评分器访问，不为恢复器补 Base。测试和实际数据均检查了历史页不变、引用与索引一致、完整记录无损。
6. **C1 对照入口。** 运行了 ARC-Shared、Batch-SDA-GGD、Per-field-GD、Block-CZ-256、RAW，并增加固定分组但独立 Base 的 FixedGroup-Independent，区分共享本身与冻结规范/分组的影响。旧方法只读复用现有表示和安全封装代码，按各自实际需求记账。RAW/Zstd 使用其独立布局描述，不能交给 SDA 容器解析器。

## 小规模结果：功能成立，当前空间成本偏高

单位均为实际字节。历史成本是该检查子集的 train1 三批累计，新增长度是 train2 四批累计；所有方法的范围相同。

| 方法 | 历史云字节 | train2 增量云字节 | 两文件累计云字节 | 本地部署状态字节 |
|---|---:|---:|---:|---:|
| ARC-Shared | 1,848,047 | 6,004,539 | **7,852,586** | 7,371,040 |
| FixedGroup-Independent | 1,913,644 | 6,819,514 | 8,733,158 | 8,249,504 |
| Batch-SDA-GGD | 114,418 | 154,972 | **269,390** | 145,752 |
| Per-field-GD | 119,543 | 161,992 | 281,535 | 157,593 |
| Block-CZ-256 | 91,261 | 122,581 | **213,842** | 1,645 |
| RAW | 148,627 | 198,221 | 346,848 | 1,582 |

ARC-Shared 相对同规范、同固定分组的独立 Base 对照减少了存储，说明复用机制确实运行；但当前检查里远高于原批次独立方案，**不能作为新方案空间收益已成立的证据**。子集太小、每日保留完整索引版本，以及 JSON/HMAC 定位元数据都影响比例，不能据此直接推断全数据规模的优劣。

ARC-Shared 累计云字节分解为：密文 **45,588 B**、BLS 标签 **2,688 B**、Merkle 索引/树 **7,340,333 B**、短引用流 **3,680 B**、Manifest/签名 **460,297 B**。分项合计恰等于 **7,852,586 B**。当前主要成本是**逐日保留的全量索引快照与清单**，尚未实现增量索引/紧凑二进制定位。所有这些实际文件都被计入，本地状态也包含保留的历史索引版本。

train2 四批共 2,563 次“按日去重后的编码 Base 查询”，历史命中 542 次，其中 422 次来自 train1。由于逃逸字段用零占位，独立复查又分出未受逃逸影响的查询：**2,515 次、历史命中 539 次，其中 train1 命中仍为 422 次**；48 个查询键只出现在含逃逸字段的组记录中。应使用后一组诊断理解真实训练坐标下的复用，避免把占位匹配当作原数值相等。全子集共有 748 个字段逃逸，其中 train2 为 488 个。

构建时间保留在逐批 CSV 中：新方案 S0 训练单列，其他逐批计时包括编码、查重、加密、标签、索引和提交；CSV 扫描、测试性重启和独立真值评分在测量外。旧基线逐日学习分组，不能只看新方案排除 S0 后的归档时间就宣称整体更快。峰值内存目前是整个进程指标，不作为单方法内存排名。
