日期：2026-10-21。本文件是下一轮研发规格，不是已完成实现、新颖性证明或投稿承诺。
本轮六个旧窗口均为开发数据；后续 raw 归因和宽码诊断仍须分别注明分析性质，不能转称独立确认。

## 1. 问题、当前取舍与可交付贡献

推荐问题：共享压缩记录有跨对象依赖；在真实存储开销和请求读取额度内，如何返回完整且通过认证的记录？
新目标写作 V = P(完整记录恢复成功 ∩ 认证通过 ∩ 本次计费读取字节 ≤ L)，而非只最大化无读取约束的可用性 U。
L 是公开指定的服务额度或实验横轴；存储预算 beta 是独立约束。不能用改变 L 掩盖不同方案的存储成本。
保留 raw CoAccess 为强基线；A 的几何/覆盖调整作为辅助候选；在线默认 eager。lazy 保留负结果消融，不作贡献。
本轮分组局部搜索在精确模型上的增量很小，不能把 raw Jaccard 的全部收益归为新算法。
有限码库最优不等于全域最佳；宽 RS 的可用性优势与读取放大必须共同展示。
候选贡献是“可验证的联合效用建模、实际限额执行、与该目标一致的布局优化”，三者必须连成闭环并各有证据。
Jaccard、改变 RS 参数、缓存、先取 parity、采用现成公开审计，均不单独构成新颖性。
完整数据、认证和恢复流程可复用；新颖性仍须对照 MOAT、PFP、TREAT、LRC 及自适应编码原始文献继续排查。

## 2. 固定存储布局与协议对象

每个不可变 snapshot 绑定一个部署布局 layout_id；包含原页长度/承诺、条带页序、k/r、parity 长度/承诺和格式版本。
布局一旦存储并签名，所有请求 L 的曲线都在这个固定布局上测量；请求到来不得免费换码、改分组或生成新 parity。
若研究多个服务等级，可提前部署多个布局并分别收费；若重新编码，计入转换读写、时间和共存存储峰值。
默认研究互不相交、满实际数据片的 MDS 条带，不引入虚拟零槽位充当物理故障对象。
主故障口径沿用均匀 fixed-count 擦除：N = 原页数 + parity 对象数，m = ceil(alpha × N)。
不同几何使用共同目标/随机 rank，先保留各自 N 个对象再取最小 m 个；记录每方法真实 N、m、m/N。
独立磁盘/节点故障、burst、热点损坏和恶意内容损坏另列故障模型，不把当前固定对象擦除的精确式直接迁移过去。
快照、数据窗口、目标权重、beta、代码库、规划工作量、L 网格、缓存策略和所有主次指标必须在新确认前冻结。

## 3. BudgetLedger：唯一的实际字节计量入口

建议接口：Ledger(policy, limit_bytes, metadata_mode, request_id)，由一个请求内所有原页/辅助页/parity/元数据读取器共享。
建议事件：reserve / receive / authenticate / cache_hit / reconstruct / abort；每个事件记录对象标识、来源、类别和累计计费字节。
receive 按实际收到的 payload 长度计费，包括 nonce/tag、短尾页和其它实际封装，不能把每个对象都假定成 4096 B。
所需原页、为修复额外读取的原页和 parity 全部收费；失败请求收到的内容同样收费。
坏哈希、坏 AEAD、错误签名、截断对象和无效 parity 的已接收字节均保留，不能在认证失败后从计数器扣除。
纯缺失若确实返回零 payload，则计零 payload；失败请求次数、状态头/协议开销另计，避免声称没有网络成本。
同一请求已有且已认证的缓存命中不再产生接收字节；本地重建结果不算新下载，但记录解码 CPU/内存开销。
一次失败读取后再次请求收到内容，必须再次计费；“对象去重计费”不能替代真实 receive 计费。
跨请求缓存由单独可控 cache_scope 提供；冷启动、缓存预热和重放顺序均需记录，各方法保持相同容量和驱逐规则。
计数至少包含 data_original / data_helper / parity / metadata / invalid_received / successful_received / failed_received。
invalid_received 是已收费字节的分类，不得再加一次；报表注明哪些字段互斥、哪些是交叉标签。
Ledger 汇总必须能对账至底层受控读取日志，所有总量非负且最终值等于事件累计。

## 4. 元数据口径与真正的 hard cap

同时报告 hot-metadata 和 cold-metadata 两种模式；可信 pin/本地密钥的预置条件要明确。
hot 模式把已验证元数据缓存作为前提，并列出其大小；cold 模式将实际获取的 manifest、签名等 payload 纳入请求账本。
若元数据按需获取，费用与实际读取路径相关；不能未经证明就把它替换成所有请求相同的常数。
存储开销另含原档、parity、manifest、签名、审计标签及必要索引；不要把热元数据“免费驻留”误写成零存储。
底层 fetch 必须支持限制实际读取的流式接口；先整块下载再判断超额，只能提供观测阈值，不能声称物理读取 hard cap。
在固定长度的有效对象上可按签名长度预留；短页用真实长度，不按最大页长预留而无故拒绝本来可完成的请求。
内容不可信时以实际 receive 为准，并限制读取剩余额度；超长响应、截断响应和分块边界需要专门测试。
若底层传输已经缓冲了额外字节，必须说明计量层；应用 payload 上限不等于网络线路总字节上限。
额度耗尽后返回明确 budget_exceeded；不发起额外辅助读取，不把已收字节清零，不发布半条记录。
认证失败、不可恢复、预算不足、超时和内部错误分别记录，避免将所有失败折叠成相同实验原因。
有限额度只能影响是否中止；默认保持固定 eager 调度，避免在线利用未来 D 或已知故障图来挑选便宜路径。

## 5. JointUtilityEvaluator：从等长片到真实短页

输入是所有者离线依赖集合 D_i、权重、签名长度、固定布局和公开故障分布；不得读取正式测试故障样本进行调参。
输出应同时含 U(alpha)、完整 V(alpha,L) 曲线、精确计数/分母、适用假设、运行时间和内存使用。
先实现 09 中等长片的二维生成函数：z 计擦除数，w 计成功路径接收的有效片数。
对一条 (k,r) 条带和 a 个所需原页，`G = w^a(1+z)^(k+r-a) + w^k Σ[j=1..r](C(k+r,j)-C(k+r-a,j))z^j`。
u 个未保护所需页必须幸存，其他自由原对象给出 (1+z)^F；全局乘积再取 z^m、w 不超过额度的系数。
对全部 w 系数求和，即令 w=1，必须逐项回到原精确 U；不能仅比较最终四舍五入概率。
无保护布局、D 为空、L=0、L 无穷、m=0、m=N、a=0、a=k、r=1 和异构条带都是边界测试。
第二步用真实 byte 权重替换片数权重，读取长度来自原页 descriptor 与 parity frame，4096 B 只作理想化例子。
纯擦除且 eager 成功时，所需原页全活则成本为这些原页长度之和；需要修复则为幸存原页长度总和加缺失原页数乘 parity 长度。
短页模型保持数据片位置/长度差异，不能用相同 a、k、r 的等长缓存键合并不同长度配置。
可采用稀疏多项式/动态规划和长度模式缓存；复杂度、截断规则、内存上限及回退策略必须实测并公开。
若按 byte 桶量化，只可标为近似并给出上下界/误差；不能继续称其为逐字节精确概率。
冷元数据若是固定且必取的一笔 M，可将 w 指数平移 M；按需、可失败的元数据需扩展状态或采用执行模拟。
本公式仅对纯擦除、正确认证设置、互不相交满 MDS、固定 eager 和适当缓存假设成立。
恶意损坏的无效下载、动态超时、重试、重叠码、LRC/再生码及跨请求缓存，不能直接套用当前 G。
这些场景可先做真实执行曲线；若要精确优化，需单独建立并核验相应状态模型。

## 6. 观测 CDF 与在线限额执行必须逐例对齐

先运行无限额的受控执行，得到成功标志、认证结果和真实计费字节 C；观测事件是 success 且 C ≤ L。
再在同一固定对象状态下用 hard-cap 执行器重放，检查是否与该事件一致，不能默认两者天然相等。
09 的路径无关论证只覆盖所列条件；预算改变调度、冷按需元数据、重试或缓存规则改变时要重新验证。
成功对齐要求目标、mask、布局、原片内容、额度、metadata 模式和缓存初始状态全部相同。
每个小图、每种短页长度、每种完整枚举故障和多个 L 边界，比较公式、无限额 CDF、hard-cap 三方。
实际大图用预先声明的请求与故障样本检查模型/执行一致性，完整保留不一致事件和原因。
认证损坏/截断测试只要求执行器正确计费并拒绝错误输出；不能用纯擦除公式替代这些安全测试。
只在假设满足且逐例对应已通过的场景，才将 V 称为该执行器的精确额度内成功概率。

## 7. 两条并行候选与公平规划工作量

S1：固定保护集合 P、每条带有序 k/r 组成和真实存储成本，仅优化分组；从强 raw CoAccess 与固定布局分别初始化。
S1 的候选可包含跨条带交换和有限块移动，但由 V 或预先声明的曲线目标评分，不能继续只按 Jaccard 排名后改名。
Jaccard 可作预筛选器，必须保留 raw-only 和无预筛选/不同代理消融，区分代理贡献和精确目标贡献。
S1 应检验在原 U 相同或近似时，读取额度下的完整恢复是否改善，以及优化开销是否值得。
S2：覆盖、几何与分组的有限联合搜索，允许改变 P、k/r 和条带数，每个候选重新计算真实 sidecar 成本与 N/m。
S2 从已资格化的强固定编码和 S1 分支起步；保留候选来源、接受/拒绝原因、评分次数和最终完整布局。
不要把 S2 的多阶段总评分预算与 S1 的单阶段预算都标成“相同预算”；同时比较等评分工作量和等时间版本。
本轮 18 配置可作起点，不能当人为硬约束；下一轮码库至少纳入宽 RS 的合理范围并说明 GF(256) 总长上限。
两分支均是有界启发式，除非另有证明，不声称全局最优、近似比、子模性或 NP-hard 结论。
返回固定布局及可复现证书：成本、布局 SHA、所用训练权重、效用曲线、风险检查和全部搜索日志。
接受规则只能用开发/训练信息；后续确认结果不得触发更换初始化、候选顺序、评分目标或 L 选择。

## 8. 目标函数、完整曲线和风险口径

为一份部署布局预先选定一个规划目标，例如固定服务等级的 V 或对公开预设 L 分布加权的 V；不要逐 L 免费重新布局。
同时展示完整的 V–L 曲线和未限额 U，并报告对应存储开销、读取字节、失败字节、尝试次数、CPU、内存和构建成本。
L 网格、范围、采样点、积分权重及尾部处理在新确认前声明；不得根据结果专挑 512 KiB 或另一有利上限。
若展示不同布局的 Pareto 前沿，清楚标注每点是另一份实际部署，说明转换成本；不可称作同一系统随 L 自动免费切换。
基线与候选的效用使用相同 record 权重；均匀单记录、热点请求和多记录请求分别定义，不交叉借用有利权重。
无读取约束的低风险 guard 可沿用相对固定参考布局，在所有 alpha∈(0,.01] 的两套 N 分段边界上作精确比值比较。
若引入 V 的风险 guard，必须另行定义参考、L 服务分布和 alpha 区间；U 无退化不能推出每个 L 的 V 无退化。
如果全曲线无退化不可行，就如实报告 Pareto 取舍，不在运行后放松约束或选择更容易满足的参考。
跨 N 的 nominal alpha 参考要报告实际 m/N；任何“低风险保证”仅针对指定分布的期望，不保证每一个故障样本。
相关故障、恶意坏块和多请求相关性均须单列，不用独立对象模型为其提供保证。

## 9. 在线接口：不使用未来完整依赖 D

恢复请求输入 snapshot pin、授权凭证/密钥、目标集合、layout_id、额度及缓存策略；不接受 owner 的离线 D 或测试 missing_mask。
第一阶段仅从公开几何与目标导出必要结构/引用页，经受控读取、认证和解密后获得真实 BaseID。
第二阶段依据已认证引用扩展依赖，所需页缺失时由固定条带 eager 恢复；两个阶段共享 Ledger 和请求缓存。
离线 D 仅供规划、公式评分和事后 oracle 检查；用于实际执行的上下文不得暴露其快捷读取接口。
辅助片与 parity 都经过统一受控 fetch；构建时的 owner_store 不得绕过在线故障注入、限额或计量。
重建密文须对原承诺验证，再通过 AEAD 和结构校验，只返回完整目标记录；独立规范真值的逐字段比较属于离线实验验收，不能输入在线恢复器。
不足 k 片、任一必要认证失败或预算耗尽都返回失败，不返回部分记录；已经收到的费用仍可审计。
多记录请求先声明原子整批返回还是逐记录状态；不同语义分别计量，不能将部分批次成功算整批成功。
任何未来自适应调度只能使用已获取并认证的信息；其新路径模型和与现有公式的差异另行证明/验证。

## 10. 强基线与全流程对照

必须同时保留旧 FD10、强固定 RS、raw CoAccess、raw 加局部优化、S1、S2，并明确是否同 P/几何/存储成本。
宽 RS 不能只算解析分数：先完成真实编码、签名 sidecar、短尾页、擦除解码、controlled-fetch 和预算资格化，再进入正式对照。
raw CoAccess 必须应用在强固定编码上；只在弱 RS(10,8) 上实现它不足以说明新方法的优势。
对比 PFP 时需真实实现其共享块/文件 parity 与恢复关系并正确计费；当前不相交 XOR/分组只能叫 adaptation，不能叫 PFP 复现。
若要声称普遍降低修复读取成本，应纳入适当 LRC 基线；LRC 和重叠码使用自己的恢复器和模型，不能套本轮不相交 MDS 公式。
加入 row-oriented 压缩和 block-oriented 压缩的可寻址全流程基线，保持同样的无损精度、认证要求和预算口径。
这类基线要计真实压缩数据、索引、密文封装、标签、sidecar、构建成本与查询读取，不能只比压缩率或裸字节读取。
加入有同等 cache 容量/策略的多记录请求，对齐目标批次、记录分布和请求顺序，检查共享页是否被公平复用。
当前 cold 单记录依赖读取较大，不能据此泛化到所有查询；报告不同记录数、热点强度和缓存状态的曲线。
使用原始/压缩无冗余、固定编码、保护覆盖与分组分解等消融，辨别收益来自格式、覆盖、编码、缓存还是目标优化。
对所有基线披露实现偏差、未实现模块和资源限制；不能用省略认证或只计用户所需页的低成本版本作不公平对照。

## 11. 公开审计与认证检索的系统闭环

现有 public audit、签名快照和授权检索可以复用，但本轮 tag=False 的恢复归档不能作为新布局已验证公开审计的证据。
先生成 tag-ready 快照，并明确标签绑定的是哪些原始密文页、块顺序、版本、挑战域和请求身份。
必须声明 sidecar parity 的审计范围：签名承诺可在读取时验内容，但不自动证明它在云端持续可取。
方案可选择为 parity 建立明确域分离的标签/审计路径，或仅声明按需验证；两者的安全与成本主张不同。
所有审计/读取路径要绑定相同 snapshot_id、layout_id 和版本；测试重放、旧布局替换、页重排与跨批次混用。
公开审计失败目前不能自动精确定位坏页；若要“审计→定位→修复→再审计”，须实现明确定位/读取协议并计入额外工作。
在定位模块完成前，只能声称审计与认证检索共享验证对象和版本，不宣称已完成自动自愈闭环。
Leak 定义需加入规划输出、条带组成、覆盖集合、访问/读取轨迹及其与私有依赖的关系，不能只列页数和证明大小。
若布局由私有 D 决定，需要说明哪些结构公开、由谁持有、泄漏如何进入安全游戏；不以加密内容代替布局泄漏分析。
沿用现成 PoR/PDP 时准确引用和限定假设；组合工程、请求绑定或新的性能目标不自动成为新 PoR 安全定理。
新贡献可落在验证边界一致和恢复正确性，不强凑新的密码学原语或 extractor 证明。

## 12. 实现交付与验收顺序

阶段一：只在新开发目录实现 Ledger、限额 reader、等片/短页 Evaluator 和 S1/S2，不改已冻结 runtime 或旧结果。
交付模块清晰分开：成本策略、统一传输计量、预算执行、解析评分、候选规划、布局验证、实验 runner 和独立分析。
单元/小图资格化覆盖计费守恒、缓存命中、坏块/截断、cap 边界、无部分输出、异构 offset、短页和所有 w 求和回 U。
逐例验证公式—无限额 CDF—hard-cap 一致性；对不适用场景给出显式拒绝或标记，不能静默使用错误模型。
宽码、raw CoAccess、row/block 基线和多记录缓存分支分别做真实端到端资格化，保留源码/输入/布局/结果哈希。
若改动 full/reduced 共用安全实现，按仓库 AGENTS 运行安全/调度/队列测试、两个 profile 的 qualify 与保收据 resume 检查。
阶段二：六个旧窗口可继续开发筛选；新增基线与归因均标 development/post-hoc，不冒充新的独立效果证据。
开发期间查看完整曲线，保留负结果；若强 raw 或宽码已经足够，不为了保留 S1/S2 名称而选择不公平设置。
确认前冻结所有候选、目标权重、存储/读取口径、L 网格、代码范围、risk、规划工作量、主要比较及统计方法。
阶段三：准备真正未见的数据/时间窗口和独立随机布局，冻结新 runtime/input，再开展确认；不在打开后补调参数。
采用同 case 的配对差值和适当保守区间；零 discordance 不能用退化 bootstrap [0,0] 宣称无风险。
重复布局/窗口按预设层次分析，不把同一 fault 下八个方法或同一请求多个 L 当独立样本扩充 n。
若结果只在部分额度/数据有效，按预设分析完整报告适用范围；没有预先的实际目标就不凭空设定“必须提升某百分比”门槛。
验收是正确性、安全边界、公平成本、可信区间与可复现性达标，并据新确认结果决定保留 S1、S2 或仅系统主线。
时延主张需要适当隔离/随机化运行；跨 run、与解析审计并行的耗时不能作为强配对性能收益。
阶段四：更新中英文主稿、补充材料、贡献列表、图表、威胁模型和实现说明，再做逐条 claim–code–evidence 自审。

## 13. 论文收敛与失败时的选择规则

主线候选：可寻址共享压缩 → 认证依赖发现 → 离线联合效用规划 → 固定布局存储 → 限额认证恢复 → 同版本公开审计。
若 S1 超过强 raw 基线且有一致解释，可将预算感知分组作为核心；若 S2 还有独立增量，再作为联合规划扩展。
若 S2 主要等于选择更宽的现成码，则保留为强基线/参数研究，不写成核心算法突破。
若二者未超越强 raw/宽码/LRC，则保留精确模型、可靠计费执行与系统证据，重新评估是否足以形成独立论文贡献。
若实际 cap 无法与模型一致，先修正模型或执行器；不能只展示无限额成功后的 CDF 就称完成 hard-cap 系统。
若 row/block 基线更适合查询，说明共享压缩的存储—读取取舍和适用工作负载，允许调整主线，不隐去基线。
稿件中区分已完成实现、条件性理论、开发证据和新确认结果；不得把下一轮规格写成已完成创新。
中科院分区、CCF 类别和录用均不是本轮技术验收的可保证结果；投稿定位应在完整证据形成后再核对当期要求。
