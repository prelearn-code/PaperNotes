This diagnostic is committed while the frozen Plan61 screening is still running.
At creation time, the author has not inspected this screening's recovery rates,
chosen uniform geometries, candidate gains, or test outcomes. It does not change
the running protocol, candidate planners, frozen runtime, or archive snapshots.

## Question and fixed scope

The original 18-code grid, with k <= 32 and r <= 3, is a small implementation
screening range. Those limits are not an application requirement and cannot
justify calling its best member the globally strongest fixed-code baseline.
This external probe asks whether wider fixed codes change the utility and
cold-decoding tradeoff enough to invalidate that comparison scope.

## Budget and physical object model

For each pair, admit the largest number S of full, disjoint stripes over the
FrequencyD prefix that fits the actual canonical serialized layout cost. Do not
reduce another baseline's stripe count to force equal parity counts.

Use the same compact uniform global-k/r manifest schema as frozen Plan61:
ARC-CIPHER-FLEX-RS-v1, snapshot digest, codec identifier, n/k/r, page_bytes,
and each stripe's page IDs and r base64 SHA256 commitments. Cost is the exact
canonical JSON length plus 128 bytes for signature/provisioned pin, plus
4096*r*S parity bytes. Commitments have the same fixed encoded length regardless
of their eventual contents. No parity file is generated by this probe, so this
is a deterministic serialization cost calculation, not a measured wide-code
sidecar. A subsequent implementation must reproduce this format and byte count.

The erasure population is N = original_pages + r*S. For nominal alpha, the
number missing is ceil(alpha*N), sampled uniformly in the abstract model.
Metadata and owner pins remain available, matching Plan61's fault model.

## Independent exact model and comparisons

The external script contains a generic integer implementation independent of
the production MixedEvaluator's geometry allow-list. For a stripe with a
required original pages, successful j-erasure subsets are counted by:

- C(k+r,j), when j <= r;
- C(k+r-a,j), when j > r.

Multiply these stripe polynomials and the free-object factor (1+z)^f; required
unprotected originals must survive. The coefficient of z^m, summed over all
record multiplicities, is divided by R*C(N,m). All counts are integers.

Compute every fixed missing count needed for alpha in (0,0.01], plus the
nominal 0.1%, 0.5%, 1%, and 5% views. Compare the full continuous low-alpha
interval against the frozen SafeFixedBest by taking the union of j/N
breakpoints for both populations and 0.01. Integer ratios, with no floating
slack, decide feasibility. Also report the analogous comparison against
Combined for transparency.

After the existing run is COMPLETE, independently recompute SafeFixedBest
and Combined from their saved layouts and verify their saved exact integer
numerators/denominators. Report all seven candidates, not just the winner.
Report raw-best and SafeFixedBest-risk-feasible best separately, along with
U5 differences, q, covered pages K, population, missing counts, and byte cost.

## Reading-cost statement and limits

For each wide configuration, report k as the cold, no-cache authenticated
fragment threshold for one successful full-stripe MDS decode. For the possibly
heterogeneous references, report the width distribution and min/max k.

This threshold is not mean read bytes, elapsed time, network latency, actual
fetch attempts, or full-record recovery cost. Erasures/authentication failures
can require more attempts; caching can reduce incremental reads; one record
can require several stripes. There is no actual wide-code recovery
qualification in this probe.

The diagnostic cannot turn the six previously inspected windows into
confirmation data. It produces no actual recovery rows and makes no novelty
claim from changing k/r. If wider fixed codes have materially better modeled
utility, the final research direction must explicitly examine reading budgets
and the utility/read-cost Pareto tradeoff. The 18-code winner cannot remain an
unqualified claim of the strongest fixed baseline. No post-hoc threshold or
extra candidate search will be introduced by this script.
