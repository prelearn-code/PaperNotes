# Plan65: joint coverage and repair layout with a 512 KiB safety gate

Preserve all Plan63/64 code and results. New sandbox, protocol, prepared data, frozen runtime and exclusive receipts. No shared secure implementation changes; no comparative latency claims.

The allocator considers pure coverage insertion, insertion coupled with relocation of an existing protected page, insertion coupled with a cross-stripe swap, and layout-only swaps. Structural ranking uses sum over records of a*(k-a), the single-erasure extra-page proxy in a stripe with k pages and a needed pages; this is not the actual multi-fault objective. Enumerate 64 then 48 proposals, round-robin across families. Retain an expansion-only branch for the second round. Exact low-loss certificates are always relative to original CoAccess, all averaged records, all preset hot/cold budgets, alpha [0,.01] at all ceil breakpoints, zero tolerance.

The hard repair-domain limit is 128 KiB. Use 512 planning targets with separate common-random fault draws for each of ceil(alpha*N), fixed ceil(alpha*N_Raw), and independent Bernoulli(alpha). At alpha .05 reject any paired Raw-success/candidate-failure at hot or cold 512 KiB. Also reject an increase in common-success bytes entering the final 4 KiB of the 512 KiB allowance. Retain a <=4096 B average common-success overhead and nonnegative finite-budget profile gain in each of four deterministic folds, both pooled and per fault model. Among feasible candidates maximize cold512, then hot512, then the seven-cap profile. These gates are empirical, not guarantees for new faults.

Select before independent calibration on 256 different targets across all three fault models. If calibration fails the same gates, fall back to Raw24 without searching alternatives. AExpand and AJoint receive the same safety/calibration gates. ANoGate removes these empirical gates and calibration, but retains the same structural pool and exact low-loss risk constraint. BestRaw uses the same training objective over the 25 predeclared raw geometries; FrequencyFill adds a 16-page one-parity tail. Preserve old CoAccess layouts on the two old windows; construct 24/3 CoAccess using the existing deterministic routine on each new archive.

Two old windows: 07-11/08-01 00:00-06:00. Two new six-hour slices: 07-12/08-02 12:00-18:00. Their time ranges do not overlap the six previously prepared utility windows. The algorithm and thresholds are frozen before evaluating new-window performance. Layout construction uses each archive's dependency graph and its own planning/calibration samples; this tests a frozen adaptive allocator on new windows, not zero-calibration layout transfer. Test targets exclude planning and calibration.

Each window: three fault models x three fresh seeds x [16,16,16,64] requests at alpha [.001,.005,.01,.05], plus four clean requests. Total 1,012 requests/window, 4,048 overall. Replay hot/cold caps [32,64,128,256,512,1024,2048] KiB and infinity using real recovery, canonical truth and the existing byte ledger. Qualify and intentionally stop/resume, preserving receipts. Use distinct physical CPU cores for concurrent windows.

Primary endpoint: cold512 at 5%. Report hot512, regression counts and the finite-budget profile separately. Stable improvement requires positive cold512 differences over Raw24, BestRaw and FrequencyFill in every new-window/model/seed stratum and a positive paired 95% interval, plus zero observed Raw24-to-A losses at hot/cold512. Pointwise stratified bootstrap is exploratory, not multiplicity-adjusted. Never count caps, aliases or model replays as independent evidence; summarize models separately. Do not extend, retune or select layouts after observing tests. Report fallback, identical ablations, uncertainty, and model dependence explicitly.

Validate exact integer risk against the previous evaluator, new candidate legality and loss gates, actual success-cost/CDF consistency, cold metadata authentication, all receipts/input hashes and old-file preservation. This remains an authenticated recovery study; public PoR tag integration is outside this version.
