# 核心方案：依赖感知审计与认证恢复 v3

版本：2026-09-16。正式论文为 [paper_cn.md](paper_cn.md)，单栏阅读版为 [paper_cn.pdf](paper_cn.pdf)。本文件记录工程接口与安全合同；旧 v2 目录回退实现只作历史基线。

## 1. 已实现的能力

完整链路为：真实字符串记录形成 → REP/DELTA/FALLBACK 类型隔离 → AEAD → RS 组件 → Merkle 证明 → 完整签名控制信息 → 公开审计或授权恢复 → 独立原值核验。

实现入口位于 [src/viability](../../../Exp/Iot_Audit_MY/src/viability/)：

| 模块 | 职责 |
|---|---|
| strict_snapshot.py | v3 发布、真实页与证明落盘、插入/替换/删除快照事务 |
| strict_runtime.py | 签名入口、严格规范解析、CSP 序列化接口、逐事件计量、公开审计、提取及恢复 |
| extraction_check.py | 固定应答模型的 1820 挑战穷举及提取阈值对拍 |
| real_formation.py / record_codec.py | 保留原始字段字符串的形成和解码 |
| c2_runner.py / evidence_v2.py | 同候选域预算比较、逐对象容量筛选 |
| layout_cost.py | 默认候选包含 b=7，保持历史布局解析模型 |

## 2. 可信输入与签名格式

验证者固定 Gateway 公钥以及对象标识、快照标识和数据版本，不能从同一个待验证控制文件自取可信公钥或预期版本。Recovery 另外持有 Owner 主密钥；Auditor 不需要解密密钥。

strict-snapshot-3 的 control 字段经确定性 JSON 编码，再使用 STRICT3 域的规范字节签名。控制信息绑定身份、版本、密钥时期、RS 参数、记录总数、Entry 总数、META 根、Entry 集合根和布局描述符。

FullDir 携带完整有序 Entry 规范字节；Paged 只携带有序页描述符，完整 Entry 只能从认证页解码。每个页描述符绑定页名、数量、页根和页内 Entry 根。不存在额外 stripe_map 或完整目录回退。记录映射来自已认证条带的 LocalIndex，gid 直接作为组件路径。

## 3. 容量与材料

RS 参数固定为 (16,8)。业务/META 消息 24576 B，每块 3072 B；页消息 4096 B，每块 512 B。Header 462 B、RecordBinding 446 B、Entry 493 B。

k 个 Entry 的页面为 20+514k B。满页 b=7 占 3618 B，b=8 占 4132 B，因此满页容量上限为 7。小对象名义 b>实际条目数时只是同一页面的参数别名。

v3 的签名控制和 PageDesc 使用实际 JSON 长度计量，不沿用历史 673 B PageDesc 常数。历史 E2/E4 的解析成本参数继续标记为模型。

## 4. 公开审计与恢复

公开冷启动审计先验证控制信息；Paged 通过至少 K 个合法块提取页并认证完整业务 Entry 集合；随后检查所有业务组件加 META，每组件 4 个无放回坐标。这是实际运行的固定覆盖基线。

五种目标抽样策略属于精确风险模型，对记录闭包、均匀条带和关键组件强制覆盖进行比较；不能将实际固定覆盖基线的字节账冒充各模型策略的测量。

授权恢复的处理顺序为：

1. 验证控制信息、公钥及预期身份版本。
2. 提取并认证 META，取得 JSON 编码的 FRAME 和字段位置。
3. 解析完整目录或各可用认证页；页缺失不回退。
4. REP 优先提取业务条带；逐块 opening 验证后 RS 解码，再重编码核对可信根。
5. 解析 Header/LocalIndex，检查身份、长度、类型、区间、重复 sid、密文承诺和代表上下文。
6. AEAD 解密并重建字段；输出成功记录及相对于签名总数的未恢复数量。

META 不可恢复时没有记录输出。代表失效只影响 REP 与 DELTA，独立 FALLBACK 仍可恢复。错误 opening 当作无效坐标，允许其他合法坐标补足。

## 5. 提取与安全合同

固定应答集合 S 在挑战前确定，i∈S 返回合法块及证明，否则失败。均匀 t 子集挑战接受概率为 C(|S|,t)/C(N,t)。当其严格大于 C(K−1,t)/C(N,t)，可推出 |S|≥K。提取器顺序查询 N 个坐标以内即可取得 K 个合法不同块，解码并核对根。

本实现具备该固定模型提取器；不是任意状态化应答者的通用 PoR。组件绑定依赖签名不可伪造、哈希抗碰撞、诚实形成和正确实现。字段恢复还依赖正确 Owner 密钥及保真编码。公开 META、长度、类型和访问模式存在泄漏，不声称整个数据集语义安全。

## 6. 更新合同

Owner 独占写入锁覆盖版本 CAS、操作验证、重形成与发布。每次尝试使用独立快照目录及新随机主密钥，最后原子替换 head。支持插入、替换、删除；形成对象至少两条记录，低于此阈值拒绝。

发布前失败保留旧 head；同一旧版本的两个并发写者至多一个成功；固定新版本的恢复者拒绝旧快照。该合同仅覆盖单机进程失败和并发可见性，不是突然掉电持久性、Owner 全状态防回滚或分布式共识。单记录更新仍完整重写快照。

## 7. 成本合同

Ledger 记录实际返回文件字节、缺失读取、实际序列化请求和响应。控制文件、数据块及证明均入账；恢复额外计 Owner 密钥读取。当前无缓存，无免费读取。

网络统计是应用层 JSON 消息，不包含 TCP/TLS；控制信息在本地读取，网络分发需额外计入。发布量是最终 v3 包所有文件的写入字节，包含 Owner 密钥；不包含形成临时工作区或操作系统元数据。不能写成全部磁盘物理 I/O。

## 8. 已验证结果

主证据位于 [p13-005](../../../Exp/Iot_Audit_MY/artifacts/viability_v3/p13-005/results.json)。

- 四真实窗口 × 两布局 × 六故障标签，48 配置均通过输出字段正确性和隔离检查；FullDir 页故障不适用。
- Paged 首页失效时，60 条窗口损失 60 条，300 条窗口损失 284 条；无完整目录回退。
- 五对象 × 两成本模式，每模式 64 候选；四顺序基线与联合选择风险均相等。
- 固定模型每个擦除档枚举 1820 个挑战，8 块擦除可提取，9 块擦除不可提取。
- 真实对象三次版本发布、修改/删除/插入、发布前失败和并发 CAS 均有验证。
- 回归 394 项通过；详细日志、文档门禁及逐节长度见 [Plan13](../../../Exp/Iot_Audit_MY/Plan/plan13/README.md)。
