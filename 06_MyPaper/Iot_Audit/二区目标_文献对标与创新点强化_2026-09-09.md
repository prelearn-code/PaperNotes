# 二区目标：文献对标与三项创新强化

日期：2026-09-09。对象：`核心方案2.md`。本文区分已知结果、当前设计和待验证研究目标；不把研究计划表述为已经完成的定理或实验。

## 1. 判断与修改方向

现有主题有研究价值，三项贡献可以继续保留，但目前仍是“合理模型＋可行结构＋待实现协议”，还没有充分证据判断创新强度已达到目标期刊的要求。投稿分区不是统一技术门槛，中科院二区和 JCR Q2 也不能混用；本次采用较强安全与系统论文的论证完整性作为对标，不给接收率或分区保证。

最需要补强的不是贡献数量，而是三个可以被复核的结果：

1. **同预算下，哪些业务损失能以多大概率被发现？** 不能仅定义共享代表的 Impact。
2. **为这种审计提供可信且可恢复的验证输入，实际要付出多少公共状态、通信和更新代价？** 不能仅提出分页 Merkle 树。
3. **为什么组件的安全保证能组合到当前业务对象？** 不能仅列接口，再以端到端流程图代替安全归约。

建议主线表述为：**有限公共状态和审计预算下，相似去重对象的业务恢复保障。** 保持当前 REP/DELTA/FALLBACK 场景，不增加新的密码原语、跨链治理或通用注册体系。

本次核读了本地 MIDAS、MPA、One Proof、Decentralized Data Archival 和 Merkle Mountain Ranges 论文中的相关章节，并结合先前相似去重及去重审计文献复核定位；补充检索了动态 PoR 和部分可恢复性。不是对整个 Zotero 仓库的穷尽查重。

### 两个不能忽略的已有研究边界

**部分可恢复性并非新概念。** Fisch 的 PoReps 文稿在部分可恢复性定义中，已经考虑按消息位集合覆盖刻画恢复要求，包括完整块恢复。因此不能声称“首次从字节转向完整单元恢复”或“首次以集合表达恢复”。本稿可能的增量是：相似去重共享依赖、验证状态启动与双预算共同约束下的具体算法和组合保证。集合覆盖概念的相似不等于当前完整方案已被覆盖，但要求逐项比较。[原文，部分可恢复性定义附近](https://research.protocol.ai/publications/poreps-proofs-of-space-on-useful-data/fisch2018a.pdf)

**相关去重论文并非完全不涉及完整性或恢复。** 先前核读的 Gao 相似去重工作包含下载完整性论证，BA-FGDIA 涉及重构矩阵与文件恢复。相关工作应比较恢复表示、攻击对象、验证状态可用性和资源预算，不使用“现有研究都只去重、不审计、不恢复”的概括。详见此前《创新性与完整性审查_2026-09-07.md》。

## 3. 贡献一：从损失定义升级到预算分配结果

### 3.1 可以继续使用的核心表述

> 建立相似去重对象的认证恢复依赖模型，将组件失效映射为不可恢复记录集合。在证明通信和服务器读取预算内，联合配置记录抽样和共享组件挑战强度，以降低给定业务损失阈值下的最坏情形漏检风险，并给出相对强基线的收益条件和退化边界。

这里“给出”是完成后的论文目标，当前应写“拟研究／目标是给出”。仅有均匀抽记录再展开闭包，还没有完成预算分配算法。

### 3.2 把要解决的问题写准确

对冻结的当前对象，设 S 为坏组件集合，D⁺(ℓ) 为记录 ℓ 的恢复及验证依赖闭包。先在每个坏组件不能通过规定恢复路径恢复的模型下定义

\[
L(S)=|\{\ell:D^+(\ell)\cap S\ne\varnothing\}|.
\]

不能将“删除少量编码块”直接等同于整个组件不可恢复：必须经过编码阈值或底层提取条件判断。这里也是规定路径损失，不排除对象外另有备份。公共可信入口按系统假设可用；若考虑其停机，应另列可用性实验。

令 θ 包含记录抽样数 r、REP/META/页面/普通条带挑战块数及预先固定的抽样策略。候选研究目标是

\[
\min_{\theta\in\Theta(B_{proof},B_{read})}
\sup_{S\in\mathcal S:\,L(S)\ge\lambda n}
\Pr[\mathsf{Accept}\mid S,\theta].
\]

- λ 是要保护的业务损失阈值，而非任意新增权重。
- 攻击集合 𝒮 必须公开定义，例如固定失效位置、指定组件内删除比例、选择性元数据删除；不能知道真实损坏位置后才调参。
- 可行集合 Θ 对每次挑战满足预算，而不只满足平均预算。先选择配置，再取不可预测随机数，不能遇到大闭包就重抽。
- PoR 检测强度取理论保证或明确故障模型中的解析概率；实测拟合可以辅助调参，不能代替对恶意证明者的安全保证。
- 建议先对当前单代表、有限组件类别和有限挑战参数做可复核枚举优化。枚举最优仅指声明的候选集合，不等于通用最优或新的优化原语。若其不足以形成实质增量，再判断是否需要结构性算法，不能先写近似比或复杂性结论。

### 3.3 第一项必须修补的公式问题

对只有 REP 失效、影响 L 条记录的情形，设 αrep 是 REP 被审计时的拒绝概率，r 次有放回记录抽样产生的共享 REP 只验证一次，则

\[
\Pr[\mathsf{Reject}]=\alpha_{rep}\left[1-(1-L/n)^r\right].
\]

因此 r 增大后收益会饱和于 αrep。不能把同一 REP 证明算成 r 次独立检测。这个现象本身不是足够强的新定理，但它给出了需要联合配置 r 和 REP 挑战强度的理由。

**尤其要面对固定 REP 强基线。** 如果对象只有一个代表，且每轮检查 REP 很便宜，固定 REP 审计可能相当或更优；如果闭包策略没有其他可量化收益，就应把记录闭包降为保证目标正确的必要机制，不能硬称最优检测算法。不能为了制造优势，给本方案免费 META/REP 保护而向基线收费。

第一项的验收结果应包括：固定故障模型中的检测界；挑战强度与抽样数的可执行配置；完整字节/I/O 成本；至少一个现实参数区域内优于强基线的证据，以及失败或持平区域。检测时间可由明确的重复挑战假设分析，但不能在自适应破坏或版本变化时直接套独立几何分布。

## 4. 贡献二：从分页结构升级到可启动性与成本边界

### 4.1 可以继续使用的核心表述

> 形式化外包验证状态的可启动条件，构造支持局部更新的认证元数据目录，并在公共状态预算下量化启动深度、完整证明与更新重处理成本；结合依赖闭包访问，确定可行页面配置及其适用区间。

### 4.2 新增一个必须面对的强基线

只公开根页的验证状态；根页保存子页验证状态，子页继续保存下一级。父页经认证或提取后，再启动子页。只要根入口可用、各层满足相应提取前提并且结构完整，这种递归目录也可以启动。这个结构性反例是本次分析提出的比较方案，不声称它是某篇论文的原样实现或新发现。

因此当前公开所有 PageDesc 的方案不是可启动性的必要形式；它可能换来较浅的访问深度和较低的逐层依赖开销。要比较的是成本，而不是谁“能启动”、谁“必然无法启动”。

| 方案 | 应给予的公平能力 | 需要统计的代价 |
|---|---|---|
| 公共全目录 | 本地读取验证输入 | 完整公共状态及副本、更新传播 |
| 单层外包元数据 | 支持条目 opening，不必每轮下载全文件 | 页内路径、元数据审计、静态或动态更新成本 |
| 公开页描述符分页 | 按需取得条目，独立保护被访问页 | 全部页描述符、页内证明、实际页重处理 |
| 仅公开根状态的递归目录 | 父页提供子页验证状态 | 各层 opening/PoR、冷启动交互深度、沿路径更新 |

设 N 个固定长条目，每项 a 字节，每页 b 项，描述符 d 字节。在固定长描述符、静态页预处理和近似满页的限定模型里，当前分页结构有

\[
S_{pub}(b)\approx\lceil N/b\rceil d+S_0,
\qquad U_{page}(b)=\Theta(ba).
\]

其中 S₀ 包含其他公共根、固定状态及明确纳入的辅助开销。单条 opening 的路径可能是 O(h log b)，但轻客户端再取公共目录证明时，O(h log(N/b))+O(h log b) 仍可为 O(h log N)，不能据此宣称渐近证明缩短。

对递归基线，若每层约 b 路、每节点静态重处理 Θ(ba)、描述符定长且树平衡，则根验证状态可为 O(d)，路径深度 O(log_b N)，一次叶更新可能重处理 O(ba log_b N)。这些只是该候选实现的条件性成本估计，不是所有递归目录的下界；动态原语、批更新、不同布局都可能改变结果。

这些分析应导出一个具体决策：在给定 Bpub、Bproof、Bread 和更新负载时，哪些 b、r 与挑战强度组合可行，为什么选这个配置。枚举页大小得到几张曲线属于基础工作；更有价值的是给出可行区间、访问深度限制下的必要条件，或一个明确模型内的成本保证。

**不要预先承诺普遍乘积下界。** “公共状态×更新成本至少为某值”需要严格限定允许的原语、编码、缓存、递归和摊销方式。若证明不出来，报告构造成本和实测权衡即可，并相应降低理论创新措辞。

## 5. 贡献三：从完整流程升级到真实安全组合

### 5.1 可以继续使用的核心表述

> 在固定当前快照下，给出认证依赖对象的可启动组合恢复论证，明确元数据、业务组件及局部版本的提取条件；实现一个有公开提取依据的 PoR adapter，并通过形成、更新、审计、破坏和恢复全过程验证安全边界与完整成本。

### 5.2 需要真正证明的接口缺口

1. **身份一致。** 审计的条带、页及 REP 来自当前认证映射；条目数量、范围及组件身份完整，不能只验证返回条目的成员资格。
2. **输入可启动。** 不能先调用需要 file state 的 extractor，再假设它会提取包含该 file state 的同一个页面。按合法顺序获得状态，并处理逐层失败。
3. **提取前提一致。** 固定快照下的重复查询权限、随机性、每组件接受率门槛与底层定理吻合；外层闭包条件化后的挑战分布不应未经证明地等同原始 PoR 挑战。
4. **更新一致。** 局部版本不引发不必要的全对象重打标签，但新根不能混入未经授权的旧映射；加密 nonce 与失败重试遵循现有设计。
5. **恢复含义一致。** 公开提取密文对象与 Owner 解密恢复记录分别陈述。审计通过、抽样覆盖、直接擦除恢复和密码学 extractor 是四件不同的事。

现有“所有组件满足提取前提⇒对象可恢复”的联合失败界可以作为基础命题，但如果只是调用每个组件 extractor 再拼接，独立理论增量仍有限。需要把启动解析、共享目标的挑战分布及当前版本绑定的缺口讲清并证明；无需虚构底层 PoR 的漏洞。

可以进一步研究“整体长期接受率⇒达到某比例记录可提取”的定量桥接，但这是一项更难的可选增强，不应成为当前方案的未兑现承诺。总体接受率高仍可能掩盖低抽样概率组件，必须处理组件抽中概率及各自提取门槛。已有部分可恢复性工作也需要进入该扩展的相关工作。

优先选定原文具备公开 extractor 的 PoR，再落实群、编码、file state 格式与挑战合同。MPA 的 PDP 实现不直接满足这个条件；SW 可作为候选，但具体实例、现代群实现和非交互转换均需明确映射。若非交互归约拖住主线，先完成交互随机挑战的固定快照实例，再扩展信标版本。

## 6. 实验怎样才足以支撑上述创新

| 要回答的问题 | 核心实验 | 不能省略的公平条件 |
|---|---|---|
| 依赖策略是否值得额外证明 | 固定 REP＋普通抽样、均匀条带、本方案；扫描共享比例、故障位置和预算 | 相同底层安全参数；所有目录、页面、META、证书和挑战都计费 |
| 分页是否只是转移开销 | 四种元数据方案，冷/热缓存，单条更新与批更新 | 真实描述符大小、实际填充率、完整网络字节；静态/动态 PoR 分列 |
| 是否真能恢复业务 | 删除 REP、DELTA、META、页、标签；过/不过编码阈值分别测 | 先声明故障模型；没有持有源数据的辅助程序偷偷补齐 |
| 组合绑定是否有效 | 旧版回放、映射错绑、遗漏组件、跨对象证明、并发更新、失败重试 | 成功路径和拒绝路径都可复现 |
| 相似去重是否有净收益 | 真实 IoT 记录＋可控合成数据；与无去重及普通压缩对照 | 加入 AEAD、纠删码、标签、恢复模板及全部元数据，不能只看 delta 大小 |

每图标明理论、模拟或实测；保存种子、配置、代码版本、重复次数和不确定性。PDP/PoR 的直接恢复实验与 extractor 实验分别报告。不要预设“降低 30%”之类阈值再调数据；看完整权衡和收益是否稳定。

## 7. 最短可行研究顺序与停止条件

**第一步：先做强基线和成本模型。** 实现或精确核算固定 REP 审计、单层目录和根状态递归目录，验证当前分页方案是否存在实际有利区间。这一步优先于链上部署。

**第二步：完成第一项的受限优化。** 用真实字节/I/O 成本表枚举 r 与组件挑战强度，在声明的固定故障集合下得到可核查结果。只有发现稳定结构，才投入更一般算法证明。

**第三步：冻结元数据布局与 PoR adapter。** 根据前两步结果选择页面方式，补齐启动和组合证明，同时实现更新与恢复。不要让页面设计和底层 file state 持续变化。

**第四步：再同步全文、实验和辅助部署。** `paper_cn.md` 的旧单轮通过语义及旧图片不能继续用于新版结论；BFT/信标成本单列，它们不是证明前两项创新成立的前提性实验。
