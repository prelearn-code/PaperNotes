# 核心方案实现修订 v1.3

日期：2026-09-22。本文是 [核心方案 v1.2](核心方案_修订稿_v1.2.md) 的实现级补充；未改动的安全范围、公式和限制继续沿用 v1.2。

## 1. 三项工作的最终实现边界

### C1：状态一致的跨层组合协议

C1 主流程固定为 `ROOT-HLA + 可替换位置后端`。它把外部预期请求、可信状态、完整搜索结果、文件描述、逻辑位置到 bid 的认证映射，以及共享数据响应放进同一接受条件。C1 的核心证据是组合安全定义和分层归约，不预设其相对等价直接组合具有性能优势。

`SEP-OPT` 和 `JOINT` 是认证轴消融。JOINT 只有在给出 ROOT-HLA 不具备的安全性质及相应证明后才可提升为主方案。Merkle 与 R03 PCS 是位置后端轴；后端性能差异不能重复记为 C1 创新。

验证入口固定为：

```text
Verify(public_params, expected_request, trusted_state, transcript)
```

proof 中回显的请求、认证模式、后端、参数版本和状态均不得替代外部输入。交互顺序为结果与状态认证、逻辑抽样、位置映射认证与冻结、发布独立数据系数、响应与最终验证。

### C2：认证重复类上的覆盖保持与系数生成

C2 默认作为 C1 的定理和实现模块。逐文件逻辑位置样本不变；位置到 bid 的映射认证并冻结后，验证者使用独立后发种子生成有效系数。`POS-FOLD-NZ` 是强基线，`UNIQUE-NZ` 是本文实现，二者共用无负载公开 verifier。

只有当理论上出现独立性质，或集成查询相对 POS-FOLD-NZ 达到预注册收益门槛时，C2 才作为独立性能贡献；否则写入 C1 的覆盖保持引理和工程优化。

### C3：跨结构授权变化集

C3 的方案对象固定为 `AUTHORIZED-DELTA`，而非 Merkle/PCS 页面本身。补丁统一绑定：

```text
(U, txid, old_version, old_root, operation, affected_range,
 old_boundary, ΔRef, ΔObj, ΔKW, new_boundary, new_root)
```

Owner 只为新唯一对象生成数据标签；Server 验证授权、旧边界、对象和引用差分、关键词差分及新根。提交采用局部写时复制或 WAL，先持久化变化对象和事务记录，再原子发布新状态，最后按快照规则回收零引用对象。

`LOCAL-PATH` 是相同页面后端上的强基线：分别完成局部结构更新并提交状态，但不具有本文统一变化集消息时，需要明确其安全语义差异。若加入相同补丁后两者完全一致，就合并为一个配置，C3 只保留为系统动态扩展。

## 2. 正交配置

实现必须分别选择：

- `auth_mode = ROOT-HLA | SEP-OPT | JOINT`
- `reference_backend = MERKLE-MP | PCS-PUB | PCS-CUSTOM-EXPERIMENTAL`
- `challenge_mode = POS-RAW | POS-FOLD-NZ | UNIQUE-NZ`
- `transition_mode = FILE-REBUILD | LOCAL-PATH | AUTHORIZED-DELTA`
- `witness_mode = NONE | NOPRE | IMMEDIATE | LAZY`

Merkle 配置不得建立 PCS 多项式、SRS 页面参数或见证；PCS 配置必须完整计入相应对象。自定义 PCS 分支在证明完成前不得进入主结果。

## 3. 当前重构落点

截至 2026-09-22 的第三轮重构，代码已经具备正交配置类型、后端专用 C1 构建、消费式 Owner/Server/Verifier 角色拆分、版本化状态签名、五段查询状态机、六类规范应用消息编码、规范长度块编码、目录查询后 TagGen、C1 映射后的 C2 独立系数挑战、不读取负载的公开验证公式，以及 C3 授权变化集和受影响项回滚。独立进程与反序列化、持久化事务、状态非成员证明、网络栈计量和更新消息编码仍是下一阶段实现项。

新增验收覆盖：六种认证/后端组合的同语义查询、请求/状态/后端替换、两阶段 C2 挑战、公开公式篡改、短块与尾零区分、复用已有对象时 TagGen 为零、Merkle 配置 PCS 页面计数为零。

## 4. 论文主张约束

- C1 不使用 C2 的挑战生成收益或 PCS/Merkle 差异作为自身性能收益。
- C2 不把 POS-RAW 作为唯一主 baseline，也不把有限线性恢复写成一般 PoR。
- C3 不把 FULL-REBUILD 作为唯一主 baseline，不把后台见证工作排除在总成本外。
- 所有性能主张必须在实现通过 G0 后重新产生；2026-09-21 的 pilot 仅保留为旧实现历史记录。
