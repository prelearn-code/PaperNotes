# 三个贡献的 30–60 分钟可行性评估 v1.0

日期：2026-09-22。当前执行配置替代 v2.0 的主实验调度量；v2.0 的功能合同、强基线公平性和正式贡献验收门槛仍适用。本轮用于决定是否值得继续投入论文，不将小样本结果标为正式论文验收通过。

## 固定配置与时间预算

配置：`Exp/Search_Audit/workloads/feasibility_60m.json`。
入口：`Exp/Search_Audit/scripts/run_feasibility.py`。

目标约 30–60 分钟，实际以运行日志为准。按用户最新要求，3600 秒仅作为目标记录，不设置运行超时；超过 60 分钟继续执行，直到全部实验与统计完成。遇到执行错误或正确性检查失败仍停止并记录失败，不将部分结果记作完成。不根据观察到的收益调整样本、不删除负结果。单进程串行，避免同机并行对时延造成竞争。

| 内容 | 固定配置 |
|---|---|
| 公共 | BLS12-381、4 KiB 数据块、133 个扇区、真实协议与持久化路径；D=0.5；每文件 5 个关键词 |
| 主点 | 3 个数据种子 × 均匀独立/偏斜两种分布；分层报告，不混合种子与重复测量 |
| C1 | 40 文件 × 32 块，匹配 10 文件，每文件抽 8 块；引用/关键词页 16/16；每种子预热 1 次、测量 8 次 |
| C1 对照 | ROOT-HLA、SEP-OPT、JOINT × Merkle/PCS，全部 6 组；保持 TCP 进程边界 |
| C2 | 同一 C1 数据中取 10 文件 × 32 块，每文件抽 8 块；POS-RAW、POS-FOLD-NZ、UNIQUE-NZ；预热 1 次、测量 8 次 |
| C2 受控点 | q=256，q/u=1/2/4/8/16/32；概率模拟每点 1000 次；覆盖恒等、小域分布、压缩/提取检查保留 |
| C3 主点 | 4 文件 × 64 块，100 次更新，查询:更新=50:50，uniform；页容量 16/16；LAZY 阈值 8；预热 1 次 |
| C3 对照 | FULL-REBUILD、LOCAL-MERKLE、AUTHORIZED-DELTA-MERKLE、LOCAL-PCS 的 NOPRE/IMMEDIATE/LAZY，全部 6 组 |
| C3 探索点 | 仅均匀独立、seed-0：uniform 的 95:5/10:90；hot-80-20 的 95:5/50:50/10:90；共 5 个附加点 |
| C3 更新语义 | 修改/插入/删除/splice=40/25/25/10%；关键词不变/增/删/混合=70/10/10/10%；逐步 Oracle 开启 |
| C3 持久化 | 每 100 次更新 checkpoint；保留攻击检查、最终重启恢复和查询终点检查；另跑真实 kill 的集成测试 |

总计 23 个实验单元：C1 六个、C2 六个、C3 十一个。C3 共 6600 次更新、27132 次混合查询，另含每变体 100 次终点查询。与原任务的 1620 万更新、约 1.09 亿混合查询相比显著缩小。主点有重复种子；探索点单种子只能发现明显权衡，不能出具稳定性或显著性结论。

## 输出及实现验收

每次使用独立结果目录，保存配置快照、设计哈希、计划、逐单元命令和耗时。新任务不得覆盖旧结果。旧 `main_v2_20260922` 已停止，保留原始文件；未产生 `COMPLETED` 的部分单元不能混入新统计。

1. `v2_acceptance` 与 `c3_process_recovery` 串行通过。
2. C1 所有诚实查询通过，已有攻击全部拒绝；每单元 6×8 行测量。
3. C2 覆盖/分布检查通过；每单元 3×8 条自然查询核心测量，6×3×8 条受控 q/u 测量。
4. C3 每单元 6×100 条 Oracle 字节/关键词检查通过，6 条恢复记录根与数据精确一致，18 条攻击记录拒绝且未改变状态。
5. 只有单元完成并通过上述检查才写 `COMPLETED`。失败立即中止；不以超时或进程存活冒充正确性。
6. 自动输出主点与探索点各自的 seed summary、时间聚合、配对收益；另输出 `c2_controlled.json`。原始通信、存储、资源、攻击与恢复数据保留在单元目录中。3 种子 bootstrap 区间仅供探索；1 种子无可用种子区间。

## 怎样判断贡献是否值得继续

| 贡献 | 本轮应读出的证据 | 支持继续研究的信号 | 必须保留的限制 |
|---|---|---|---|
| C1 状态绑定的搜索—位置—共享内容审计 | 诚实/攻击、六种配置的阶段耗时、真实消息字节 | 完整语义可执行且关键绑定攻击被拒绝，成本可接受；能够明确陈述组合机制和安全定义 | 相同直接组合不构成竞争算法；实验不能证明组合新颖性或安全定理；没有规模扫描 |
| C2 覆盖保持的重复感知聚合 | 受控 q/u=4/8/16 对 POS-FOLD-NZ 的配对核心时间、运算计数及自然负载核心时间 | 三种子大多同向，收益超过种子波动，并在强基线上保留优势 | C1 当前只用 UNIQUE-NZ，缺少切换三策略的完整查询配对计时；故本轮不能确认 v2 的集成查询 ≥10% 门槛。优势小则作为引理/优化并入 C1 |
| C3 授权增量状态迁移 | 对 LOCAL-MERKLE 的更新/查询配对时间、六变体的通信/存储/恢复，探索比例和热点权衡 | 相对强基线有可解释的工作量或授权语义差异；更新收益接近/超过 20% 且查询无明显恶化，值得扩样 | 小规模/100 更新不足以确认扩展性、稳定 p95 或长期摊销；探索点单种子不能确认 v2 全矩阵门槛；只胜 FULL-REBUILD 不算独立贡献 |

结论只允许：有积极信号、收益不明显/建议合并、正确性失败、证据不足。三个模块均运行通过不等于三项独立创新均成立，更不等于足以发表。正式判断仍需安全论证、与文献的机制差异、可比基线，以及对积极信号补充规模与多种子实验。不得因缩减配置降低创新标准。

## 执行

从 `Exp/Search_Audit` 目录运行：

```bash
# 仅打印冻结计划
python3 scripts/run_feasibility.py --root results/feasibility_new
# 执行；使用新目录，防止覆盖
python3 -u scripts/run_feasibility.py --root results/feasibility_new --execute
```

`status.json` 保存当前单元、完成数量、总耗时与结束状态；`background.log` 保存本次后台命令输出。`complete` 只代表上述紧凑任务完成，不能解释为 v2.0 全套正式实验完成。`timeout_enabled=false` 表示已取消时长上限；`target_seconds=3600` 仅作时间目标。
