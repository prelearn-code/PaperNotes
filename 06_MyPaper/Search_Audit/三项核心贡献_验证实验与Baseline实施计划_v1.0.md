# 三项核心贡献：验证实验、Baseline与代码实施计划

> 2026-09-22：实施优先级、baseline 配置、参数矩阵和验收标准已由 [实验实现设置与验收标准 v2.0](实验实现设置与验收标准_v2.0.md) 替代。本稿保留历史文献笔记；其中 ROOT-HLA 的角色、论文文件可用性和旧门槛不再作为当前配置依据。

版本：v1.0  
依据：核心方案精简初稿 v1.1（2026-09-21）  
用途：判断研究贡献是否成立，并指导原型、复现和论文实验；不是已完成实验报告，不包含模拟生成的性能结论。

## 1. 判定原则与当前判断

判断分为五个不同问题：算法能否正确执行；安全目标是否得到定义与证明；相对已有技术是否有独立增量；同安全/同功能下是否具有实际优势；三项是否在同一协议、同一实现和同一工作负载下成立。实验不能替代不可伪造性或提取证明，也不能通过选择弱基线制造创新。

- C1：去重兼容的搜索—完整性联合认证。存在可评估的完整构造，但必须与优化后的直接组合比较，尤其检验当前状态认证与文件/关键词标签之间的重复绑定。
- C2：保持审计强度的重复感知挑战与聚合。当前独立性风险最大。v1.1 已说明直接采样非零类系数与逐位置采样、合并并修复零和具有相同有效分布；优化基线同样可达到 O(q+us) 的映射和数据处理。仅节省中间系数不足以直接认定新的密码学原语。
- C3：块级局部更新。必须比较已具备位置无关标签、局部页、平衡认证树及见证维护的方案。只优于全量重建无法证明贡献。

下文的门槛是研究项目的建议验收条件，不是 TDSC 的官方数量标准。不存在“对比固定篇数或加速固定百分比就可录用”的判定规则。

## 2. 论文及应实现的部分

### 2.1 C1相关

**R1. Enabling Verifiable Search and Integrity Auditing in Encrypted Decentralized Storage Using One Proof.** M. Song et al., IEEE TC 2025. DOI: 10.1109/TC.2025.3569182。已有全文。

实现范围：关键词关联标签与状态链、Insert/Delete中的索引维护、Search、Verify.Search、文件数据认证和响应。首轮不实现链上部署、代币经济或整个周期调度。原文搜索响应对匹配文件的全部 n 个块计算；比较抽样版时必须标注为采样适配，不能把全扫与抽样差异说成联合认证算法的加速。其文件增删与插入前向隐私不能被写成“不支持动态”。原文群、扇区表示与本文不同，移植到统一密码后端必须记录改动，不能称逐字复现。

**R2. Compact Proofs of Retrievability.** H. Shacham and B. Waters, ASIACRYPT 2008；作者完整版，ePrint 2008/073。

实现范围：公开验证的多扇区同态认证器、挑战、Prove/Verify，以及小规模响应提取实验。用作本文数据层和安全直接组合的基础。未实现纠删码及全文件提取时称 SW-HLA-core，不称完整 PoR 实现。不能把公开块哈希当作负载，不能把多个独立扇区基改成已知离散对数关系的同底数。

**R3. Efficient polynomial commitment schemes for multiple points and polynomials.** D. Boneh, J. Drake, B. Fisch, A. Gabizon, ePrint 2020/081。

实现范围：多个多项式、不同位置集合的批量打开及验证；优先选与当前SRS和验证成本可对齐的双群元素版本。输入使用与本文相同的引用页、多项式次数和打开集合。完整记录额外G2 SRS、插值、消失多项式和多标量乘成本。不得把“跨页两个群元素”本身当作独立创新。

**R4. Pointproofs: Aggregating Proofs for Multiple Vector Commitments.** S. Gorbunov et al., CCS 2020, ePrint 2020/419。

实现范围：Commit、Open、跨承诺Aggregate和Verify；替换结构证明后端，保持文件秩路径、当前状态认证、搜索与数据标签模块一致。它只证明位置和值，不自动证明数据持有。第一轮可先实现R3；R4作为另一结构后端扩展，而非重复搭建完整存储系统。

### 2.2 C2相关

R2继续用作挑战响应和提取模型的主要基础。

**R5. Blockchain-Empowered Keyword Searchable Provable Data Possession for Large Similar Data.** Y. Miao et al., IEEE TIFS 2025. DOI: 10.1109/TIFS.2024.3516563。

当前只核对作者机构摘要，未取得足够正文。需要先补全文并检查：相似数据具体定义、与认证器匹配的索引、全部匹配文件的挑战方式、copy-summation对手和防御。再决定复现其挑战/认证核心还是只作安全模型对照。不能根据标题认定其已经支持本文的精确块级去重，也不能按摘要臆造算法。它已明确讨论copy-summation，因此不能把识别这类攻击本身称为首次贡献。

### 2.3 C3相关

**R6. MPA: Lightweight and Updatable Integrity Auditing for Decentralized Storage Using Merkle Trees and Polynomial Commitments.** Y. Xu et al., IEEE TIFS 2026. DOI: 10.1109/TIFS.2026.3664004。已有全文。

实现范围：单provider/单副本的块多项式标签、Merkle认证、ChalGen、Response、Verify和块修改/插入/删除；分别实现独立路径和标准多证明。原文承诺的是数据块扇区多项式，不是本文的块标识引用页。复用其动态结构作为组件时标为 MPA-core 或 MPA-adapted，不能悄悄加去重索引后仍称原方案。第一轮不实现多副本生成和链上随机贡献。多文件聚合应先做诚实正确性及抵消回归测试，不能用不满足比较安全目标的版本充当主性能基线。

**R7. FiDD: Secure Fine-Grained Deduplication and Dynamic Auditing Scheme for Cloud Storage.** L. Huang et al., IEEE TON 2026. DOI: 10.1109/TON.2025.3614191。已有全文。

实现范围：TagGen、跨文件重复块一致性判断、AuditProof/AuditVerify、DLL/Location Array、Modify/Insert/Delete、更新后再审计。钥匙服务器、CP-ABE和链上记录仅在完整协议复现时实现；只跑认证核须明确排除项，不拿更少功能所得时间声称全面优于FiDD。TA/KS的状态、通信和计算不能从系统总成本中消失。重点先检验：文件级密钥/公钥变动后未修改块的标签如何继续验证；中间插删位置数组的搬移不能只算两次指针修改。

**R8. Blockchain-Enabled Efficient Deduplication and Mixed Auditing for Dynamic Cloud Data.** C. Pan et al., IEEE TDSC 2026. DOI: 10.1109/TDSC.2025.3638157。Library中已有全文。

实现范围：用户侧块去重、唯一块AuthGen、ProofGen/VerifyProof、改进MHT和块级动态更新。采用全密文子情形对齐本文，不用混合明文加密占比降低计算量；保留原生密钥材料开销。所有权出售、费用结算和链上经济机制不进入第一轮认证核比较。先验证不同块认证指数下的多块验证公式能否在诚实输入上通过；如果原文/实现存在歧义，记录问题并停止该配置的性能比较，不静默修改。

**R9. Keyword-Based Remote Data Integrity Auditing Supporting Full Data Dynamics.** W. Shen, C. Gai, J. Yu, Y. Su, IEEE TSC 2024. DOI: 10.1109/TSC.2023.3339521。Library中已有全文。

实现范围：关键词标签、关键词匹配文件的审计、index switcher set、文件增删、块修改/插入/删除、虚拟块处理以及更新后审计。重点比较认证器维护与索引变化，核查虚拟块引入的实际抽样目标；不能把仅关键词触发审计直接等同于相同隐私目标的加密可验证搜索。

**R10. BalanceProofs: Maintainable Vector Commitments with Fast Aggregation.** W. Wang, A. Ulichney, C. Papamanthou, USENIX Security 2023. ePrint 2022/864。

实现范围：Commit/OpenAll/Open/Agg/Verify、UpdCom/UpdProof/UpdAllProofs、延迟更新日志、分桶及重建成本。采用公开协议支持的固定位置修改作为组件比较；文件中间插删需要本文共同的序列页封装，不能冒称其原生支持任意插删。必须测更新后的第一轮和连续多轮查询，将后台重建和滞后维护计入。用于挑战“页化就是新的低成本证明维护”。

### 2.4 已有理论/可选实现参考

**R11. Incrementally Aggregatable Vector Commitments and Applications to Verifiable Decentralized Storage.** Campanelli et al., ASIACRYPT 2020, ePrint 2020/149。已有全文。读取其位置绑定、增量聚合/拆分及PPCom/FastOpen；确需声称低辅助存储快速打开时再实现该后端，并完整统计消息编码和隐藏阶群成本。不必复现全部去中心化VDS。

**R12. Hyperproofs: Aggregating and Maintaining Proofs in Vector Commitments.** Srinivasan et al., USENIX Security 2022。作为R10的维护/聚合对照，首轮不用两套同时完整移植。

**R13. Dynamic Provable Data Possession.** Erway et al., CCS 2009，ePrint 2008/432。用于定义授权更新与提取安全、构造秩认证字典基线。实现结构组件时不必再开发整个版本控制系统。

**R14. Enabling Transparent Deduplication and Auditing for Encrypted Data in Cloud.** Song et al., IEEE TDSC 2024，DOI: 10.1109/TDSC.2023.3334475。已有全文。主要作为共享认证/批审计参考；其拥有者数量与代理重签名目标不在本文范围，非必选全系统性能基线。

### 2.5 控制复现工作量

首轮必须完成的是共同内核、优化直接组合、普通动态Merkle多证明、已发表多多项式打开和本文方案；R1/R7/R8/R9先做小规模核心一致性。不要一开始完整复现十四篇论文。建立 PaperSpec（原文）、Core（明确子集）、Adapted（加共同封装）三个标签，所有实验图注明类别和排除模块。

## 3. 真正决定C1是否成立的Baseline

### B1 SEP-OPT：同构造、优化分离验证

加密、去重、页面、索引压缩、当前状态、挑战位置、有效系数、缓存和结构证明均与本文一致。关键词和文件认证先作标准安全聚合，数据HLA证明单独验证；用成熟multi-pairing/shared final exponentiation优化。不能故意给基线逐文件逐标签串行验证，而本文只用一个聚合值。任何跨不同验证关系的批处理随机数须在相应响应固定后产生。

用途：隔离联合认证本身的收益，不把数据布局或抽样差异混进去。

### B2 ROOT-HLA：最小认证组合

保留v1.1已存在的可信状态签名、关键词根完整重建证明、文件状态成员证明、秩/局部打开和共享HLA。不生成每文件gamma与每关键词kappa，由状态根认证相应文件描述和关键词全集根。数据响应仍绑定从结构证明导出的相同bid。

这是对v1.1第3.4节和第6节作出的研究性基线设计，不是已复现的命名论文。它没有删除当前性、搜索无遗漏或位置认证。目的：检验gamma/kappa是否仅重复已有绑定；若该基线同样满足目标且更省空间/更快，应修改主方案或说明新增标签带来的不可替代能力。

### B3 MERKLE-MP：安全、可更新的哈希结构后端

只替换引用页的代数打开/结构后端，使用认证秩树与标准Merkle多证明；数据标签、搜索索引、有效系数和最终接受语义保持一致。可以缓存且预合并重复数据访问。不能只实现q条独立路径并复制全部共有兄弟节点。

### B4 PCS-PUB：已有紧凑批量打开

把跨页商证明替换为R3或R4的已发表构造；输入相同页面、多项式次数、位置、值和安全级别，统计所有公开参数及打开值。用于判断本文是否只是换一个“联合”名称调用常规批量打开。

### C1代码与测试

接口：BuildIndex、BuildFile、TagUniqueBlock、VerifyCurrentState、ProveReference、SearchAudit、JointVerify、RetrieveFile。Owner、Server、Verifier分进程，Server不能访问用户密钥、tau、原始文件oracle或其他baseline的副本。

正常例：不同逻辑ID但相同完整文件、同一块同一文件重复、跨文件重复、零关键词、空文件、合法bid=0、整页重复、最后一块补齐。

负例：遗漏结果、插入非匹配文件、重复ID、不同查询转录拼接、伪造当前根、旧gamma/旧kappa在新状态下回放、重排位置、伪造秩、漏页、伪造共享、字典未使用项、曲线点非法编码、错误子群、超界页长度、延迟z提前产生。

重要区别：相同内容标签在不同合法引用处复用必须接受；未抽中的损坏不能被要求必然拒绝。测试“错误数据被抽中后的拒绝”与“整体抽样命中率”必须分开。

性能实验：T_searchaudit总延迟、分阶段CPU、总网络字节、交互轮次、rho查表、MSM、Miller loops和final exponentiations、状态/秩/代数证明字节、索引和辅助存储、cold/warm缓存。

C1通过条件：有完整接受语义与组合安全论证；对已定义负例零确定性错误接受；相对B1/B2/B3/B4在目标负载有可解释的Pareto收益或实质新保证。若B2直接支配本文，先精简标签结构。若仅证明“一个群元素比r个群元素短”，但基线可标准聚合，独立增量尚未确立。

## 4. C2的强基线与实验

### C2-A POS-RAW

逐逻辑位置生成系数并直接处理数据，作为消融诊断，不作为唯一主基线。即使有缓存，也分别报告读盘次数与重复域/群运算。

### C2-B POS-FOLD-NZ（必须）

1. 使用与本文完全相同的逐文件无放回样本。
2. 对各逻辑位置生成非零随机系数。
3. 在任何密文读取、扇区运算或标签MSM前，按已认证bid合并。
4. 每类和为零时重采样该类。
5. 每个唯一块只读一次、计算一次。

该版本拥有与本文相同的有效系数分布，也具有O(q+us)处理结构。允许短种子、缓存和相同编译优化。C2不应将基线排除这些常规能力。

### C2-C UNIQUE-NZ（本文）

相同样本、相同认证映射，直接对u个唯一块生成独立非零系数。先固定映射再发放挑战。

### C2实验组

1. 覆盖恒等性：小规模穷举全部无放回样本，验证命中损坏逻辑位置与命中损坏唯一块完全等价。
2. 分布等价性：小素数域中穷举重复类系数，比较POS-FOLD-NZ与UNIQUE-NZ有效分布；实际大域中验证无偏采样、用途分离和转录绑定。
3. 固定损坏：随机唯一块删除、低引用块删除、高引用块删除、单个匹配文件的独有块删除、固定扇区改写。损坏集合在位置抽样前固定。
4. 任意压缩状态：只保留所有块固定和、按文件和、按任意预选组和、k条线性测量、历史合法响应，保留全部标签/结构而销毁其余负载副本。测预挑战状态规模和实际通过率；拒绝例不等于证明任意压缩均安全。
5. 小规模提取：在固定受认证支持集上收集新鲜独立有效响应，求秩并解线性系统，用隐藏于服务器的oracle比较恢复密文。仅支撑提取实现一致性，完整安全仍需证明成功概率与提取的联系。
6. 计算性能：固定q，改变q/u；固定u，改变重复位置数；再用真实查询测自然q/u。计入映射认证、系数生成、随机源、MSM及所有查询阶段。

概率：固定损坏条件下P_miss=prod_f C(n_f-d_f,c_f)/C(n_f,c_f)。固定非零错误矩阵的抵消界至多1/(p-1)。不要把这两个结论替代一般恶意程序的提取安全。

统计建议：每个主要概率点至少10^4次便宜抽样，使用精确公式/置信区间；真实密码恶意响应在代表性挑战上另测。小域故意构造零和用于逻辑回归，不把小域频繁抵消当作实际密码参数下的大概率攻击。

C2通过条件：针对明确安全目标的等价/提取证明成立，并相对POS-FOLD-NZ体现不只是省去几次PRF的独立增量。若效果一致、复杂度相同且剩余收益主要来自缓存/普通折叠，降级为C1的安全保持引理和实现优化，不硬保留一个“主要贡献”。

## 5. C3的强基线与实验

### C3-A FULL-REBUILD

每次对受影响文件结构和变化关键词列表完整重建；共享payload可复用，不能额外让它无理由重加密全库。用于显示局部化的总潜力，而非唯一竞争者。

### C3-B LOCAL-MERKLE

同样的共享块标签、稳定fid、认证秩树、多证明、分页压缩列表、copy-on-write、真实当前状态验证。普通局部更新只改目标页与路径。它已具备大多数常规局部化能力，是主动态比较对象。

### C3-C LOCAL-PCS

在相同页和索引框架内采用已有PCS/BalanceProofs维护算法，分别测立即维护、延迟维护和不预计算。支持固定位置修改的原语仅在共同序列封装中测试中间插删；不得宣称原论文本身提供该文件API。

### 更新追踪与Oracle

维护独立的明文参考模型（不属于服务器/性能计时），每一步都执行实际操作，完整恢复并比较字节、fid集合、关键词关系与抽样位置映射。查询返回的fid集合与oracle精确相等，不采用近似F1作为正确性的代替。

必须覆盖：修改成新块/已有块、头中尾整块插删、局部分裂/合并/借位、连续同页更新、跨页批量更新、最后一块删除、空文件、部分末块重组、关键词集合不变/新增/减少/增减混合、跨页重复fid攻击、未授权相邻子树变化、旧状态/新状态混搭、提交中断。

至少10^4次随机操作用于开发验收，10^5级长序列压力用于发现页占用、计数、磁盘增长和滞后见证问题。数值为建议执行规模，不是安全证明阈值。

计时代价：生成新块/标签、读取和验证旧路径、真正的页编辑、重平衡、关键词计算、压缩/加密页写回、状态根更新、见证维护，以及更新后的第一轮/第十轮/百轮查询。逐次和摊还成本都报告，不在实验结束时遗留未计费的后台工作。

根比较：相同确定性布局可要求增量根与重建根一致；不同合法树形的根本可不同，此时比较认证语义、完整恢复和受约束更新关系，不误把根不同当作错误。

C3通过条件：授权补丁只改变批准的关系；共享对象不破坏其他文件；最新状态绑定成立；相对LOCAL-MERKLE/LOCAL-PCS体现实际的更新—查询—存储权衡改善。如果仅优于全量重建或只计算一次KZG承诺乘法，应降为功能扩展。

## 6. 统一代码结构与最小接口

建议一个Rust密码和协议内核，Python仅用于数据准备、调度与统计；现有C++项目也可使用同样分层。所有主对比共用库、编译等级和序列化规则；不用Python模拟群运算对比C++真实配对。

```text
research/
  crypto/       # 域、群、真实配对、MSM、哈希到群、AES-SIV、HKDF、KZG
  auth/         # 共享标签、多类型认证、根签名、规范消息编码
  structure/    # 认证秩树、引用页、Merkle多证明、PCS后端
  index/        # 精确关键词列表、分页压缩、AEAD头部/页、完整重建
  state/        # 当前记录认证、成员/非成员证明、顺序提交
  protocol/     # SearchAudit状态机、阶段挑战、最终接受
  challenge/    # 无放回抽样、POS-FOLD-NZ、UNIQUE-NZ、分布测试
  update/       # 准备、旧状态核验、补丁、重平衡、索引差分、恢复
  storage/      # 可计数的持久化块表、缓存、实际读写、空间核算
  baselines/    # 组合开关与论文Core/Adapted实现
  adversary/    # 假结果、旧状态、错误映射、压缩负载、转录拼接
  tests/        # 已知向量、属性测试、状态机测试、完整文件oracle
  bench/        # 工作负载、重复种子、阶段计时、CSV/JSON输出
```

最小共同接口：

```text
setup/configure -> public_params, owner_state
outsource(files, keywords) -> committed_state
search_audit(token, expected_state, policy) -> result, proof, measurements
verify_search_audit(request, transcript) -> Accept | Reject | Incomplete
prepare_update(old_state, fid, operation, trusted_keyword_delta) -> patch
verify_apply_commit(patch) -> new_state
retrieve(fid, expected_state) -> authenticated_plaintext
```

密码后端必须执行真实群点运算、真实配对及子群验证。Prover只有SRS群元素不能保留tau；固定显式指数模型仅用于单元测试，不可计入性能。生成服务端证明时不得从验证oracle或其他配置的完好副本读取数据。

## 7. 共同工作负载与公平性约束

### 数据

1. Enron等公开语料，用于自然关键词分布和原始固定分块去重；记录原始文件、解析规范、版本和SHA-256。不要为了提高结果修改原始载荷的头部或尾部而不说明。
2. 一个可公开追踪的多版本文档/源代码快照集合，用于局部更新与共享内容。版本间字节变化、整块编辑追踪与人为整块编辑应分开标注。
3. 可控合成库，独立控制N、U、每文件块数、P、关键词结果数、重复频率偏斜和操作序列；随机均匀、共享前缀、重复模板、低频尾部等分开。合成重复率不得冒充真实观测。

### 参数建议

B取4/16/64 KiB；s由真实密文长度和可逆域编码决定，不独立随意缩小。b_R取64/256/1024，b_I取128/512/2048；r从1到1000按资源逐步扩展；N从10^4到10^6；全库重复率取0、0.25、0.5、0.75、0.9；实际q/u每轮测量；页容量按双方相同的搜索范围调优，不只给本文最优值。

概率参数与被挑战位置固定，所有算法重放相同oracle数据、同一次损坏和同一逻辑位置样本。原文全量扫描与本文抽样单列，不作为同强度性能结论。

实际读写环境至少报告cold与warm；固定CPU线程、内存预算、编译配置、库版本、SRS和缓存预算。网络测低/中/高RTT，例如0.5/20/80 ms；保留真实阶段数，不把多轮交互当一次调用。固定声明后的随机种子独立，不能预存最终响应作为查询缓存。

### 空间与统计

分别报告原始字节sum(L_f)、固定块填充后的NB_C、唯一密文UB_C、块ID/标签、文件引用、索引、认证树、最新状态、SRS、预计算见证、数据库/WAL和拥有者状态。读取后留存的索引明文缓存按实际配置计入峰值空间。

同功能基线对齐后用净差比较；同时报告相对原始文件的总放大系数，不只相对已填充密文。曲线大小不等于安全级别；参数需逐原语审查。不同信任模型与隐私目标不能汇总成一个无条件更优的柱状图。

性能在多个独立数据/查询种子上重复，报告中位数、尾延迟和置信区间；概率试验与性能重复分开。零错误观测不是不可忽略优势证明：独立T次伯努利试验零成功时，95%单侧上界为1-0.05^(1/T)，约3/T，而不是0。

## 8. 一篇完整论文的证据图谱

| 实验 | 核心问题 | 必需主对照 |
|---|---|---|
| E0 | 原文和本文基本正确性、真实配对合法性 | 独立oracle、逐项验证、负对照 |
| E1 | 搜索全集—位置—数据绑定及错误拒绝 | SEP-OPT、ROOT-HLA |
| E2 | 查询内联合验证的端到端收益 | SEP-OPT、MERKLE-MP、PCS-PUB |
| E3 | 全量存储是否因索引/见证反增 | 同功能非去重、ROOT-HLA、不同页容量 |
| E4 | 样本覆盖、系数等价与抵消界 | POS-FOLD-NZ、UNIQUE-NZ |
| E5 | 按唯一块计算的真实收益 | POS-FOLD-NZ与本文，cache一致 |
| E6 | 局部块/关键词更新的正确性与代价 | LOCAL-MERKLE、LOCAL-PCS、FULL-REBUILD |
| E7 | 更新后搜索、见证维护与状态一致性 | 同一完整协议基线，冷热查询 |
| E8 | 长期工作负载与性能/存储权衡 | 三种查询/更新比例、相同优化预算 |

消融以保留安全功能为原则：联合认证↔优化分离验证；直接唯一块系数↔POS-FOLD-NZ；局部更新↔受影响对象重建。可以形成2×2×2组合检查贡献交互，但另外保留LOCAL-MERKLE与ROOT-HLA等更强基线。去掉认证、改成固定挑战、故意忽略零和属于负对照，不能证明同安全性能优势。

每个配置执行完整外包→搜索审计→更新→新状态搜索审计→恢复。不能用静态最快结构得出C1图、改用另一不兼容动态结构得出C3图后宣称同一个系统。

## 9. 研究阶段与停留/继续条件

**P0 协议与文献可执行性（先做）**：建立paper-equation-to-code表；实现公开认证核心、规范编码和少量合法/非法示例；原文歧义形成最小反例。失败配置先修复或明确排除，不参与宣传性性能图。

**P1 完整小系统**：两/三进程，20—100文件，真实加密/配对/结构树/索引和可信状态；所有中间消息遵守阶段顺序，完整恢复与oracle一致。

**P2 C1裁决**：实现SEP-OPT、ROOT-HLA、MERKLE-MP以及PCS-PUB组件；如冗余认证被更简单安全组合支配，先改机制，不急着放大数据规模。

**P3 C2裁决**：同样本比较POS-FOLD-NZ与本文，形成覆盖/系数证明和压缩状态测试。若只有常数级随机源优化则并入C1，不硬写第二项大创新。

**P4 C3裁决**：真正的中间整块插删、受约束补丁和分页关键词更新；LOCAL-MERKLE/LOCAL-PCS；计算更新后持续查询与长期空间。

**P5 论文级评估**：固定实现，至少两个不同来源/特点的真实工作负载加可控合成；负例与统计按预先设定计划执行；完成统一安全模型、归约与参数；公开复现脚本和原始记录。

只有三项各自能说清“已有技术为什么还不够—改变了什么—怎样证明—相同条件下如何验证”，且在同一个系统中能一起运行，才有依据将其描述为三项完整研究贡献。如果最终两项实质成立、另一项只是优化，应按真实结果重写论文贡献；数量不优先于内容。

## 10. 最小交付件

- source/与锁定依赖、编译参数、运行环境和SRS生成说明；
- paper_map.csv：每篇论文每个公式/算法的代码路径、原生/子集/适配状态、假设差异；
