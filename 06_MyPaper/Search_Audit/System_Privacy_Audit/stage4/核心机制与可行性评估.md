# 动态合取结果集绑定审计：协议内核与可行性评估

日期：2026-09-06。此文接续文献复核，不替换原始方案。目标期刊为 TDSC/TIFS，但下述参考构造不声称达到其创新要求。

## 1. 本阶段结论

**可以构造并运行“完整结果认证 → 当前版本认证 → 新鲜聚合审计”的协议内核。当前提出的更新解耦与增量缓存也可实现，但可被普通组合基线直接复用，尚未形成独立的新密码机制。**

本目录完成了真实 SHA-256、AES-GCM、HMAC 和有限域运算的参考实现，测试了正确性、典型恶意响应和本机处理时间。它解决了上一轮仅有组件清单、没有验证方程的问题。

必须同时区分两层：

| 层次 | 本轮状态 | 可得结论 |
|---|---|---|
| 结果完整性、动态版本与私有验证聚合审计 | 已给出协议、可执行原型、攻击测试和计时 | 功能层面可行；条件化安全论证见下文 |
| 动态 SSE + 隐藏位置 lookup + 同样审计关系 | 接口与障碍已明确；未实现、未完成组合安全证明 | 不得使用本轮毫秒数宣称完整隐私方案性能可行 |

原型直接传输认证位图，所有者本地求交；不是 FDXT/CUBE，也不是可验证 SSE 的论文复现。这样做是为了首先检查完整性内核和自然强基线，不能将其描述成已经完成原选题的全部隐私要求。

## 2. 精确定义系统和状态

角色为可信单所有者/验证者 O、恶意存储服务器 S。所有者掌握认证密钥、可信当前状态，并授权更新。当前原型为固定容量 N、两个关键词的合取、每文件四个定长数据块；删除标记使文件退出结果集，空槽再插入递增 generation。增大容量和并发事务未实现。

关键词位图为 a、b，存活位图为 v，均为长度 N 的布尔向量。一个页含 512 位。每张位图建立位置绑定的 Merkle 树，根分别为 C_a、C_b、C_v。

每文件元数据为 `(generation, active, version_0,...,version_3)`，共 48 字节，叶子的位置就是文件槽位。元数据树根为 C_D。所有者保存可信状态：

`E = (epoch, C_a, C_b, C_v, C_D)`。

该状态由所有者本地持有，并非服务器自报的可信根。多客户端部署需要认证分发与防回滚机制；本轮没有用服务器签名或区块链替代这个前提。审计期间固定 E，更新发生后旧挑战不作为“当前状态审计”接受。

每个数据块的唯一认证名字：

`L_(i,j) = (file_slot=i, generation_i, block_index=j, block_version_(i,j))`。

块版本仅在内容更新时递增；generation 在槽位复用时递增。**不将全局 epoch 写入全部块标签**，否则无关更新也会造成全库重签。epoch 固定会话状态，局部版本固定标签语义，两者用途不同。

## 3. 具体密码内核

### 3.1 数据加密和标签

用 AES-256-GCM 加密每个 512 字节块，认证名字 L 作为 AAD。原型 nonce 为 `SHA256("nonce" || L)[:12]`，每个密钥下 L 不复用；随机碰撞风险仍遵循 96 位 nonce 的生日界，重启恢复必须保留版本。本原型没有持久化实现。

528 字节密文拆为 18 个不超过 31 字节的域元素 `m_(i,j,l)`。域为 `F_p, p=2^255-19`。所有者抽取秘密非零系数 `alpha_1,...,alpha_18` 和独立 PRF 密钥 K，标签为：

`t_(i,j) = F_K(L_(i,j)) + Σ_l alpha_l m_(i,j,l) mod p`。

F 由 HMAC-SHA256 映射到域实现。这个结构借鉴既有私有可验证同态认证器，不是新原语。[Shacham–Waters 原文入口](https://eprint.iacr.org/2008/073)。本轮没有实现纠删码或提取器，不能把参考代码称为已证明的 PoR。

### 3.2 完整结果认证

首次查询：服务器返回三张完整位图，验证者重算根并与 E 比较，计算：

`s_i = a_i AND b_i AND v_i`，`R = {i : s_i=1}`。

这不是只验证服务器提供的若干结果成员。所有位置的位图均认证，因此漏报结果无法改变验证者自己计算的 R。空集合可以被确认，但仅意味着“当前没有匹配文件”，不意味着验证了任意数据持有。

后续同一查询：验证者缓存完整位图及其树节点。服务器发送变化页；验证者应用变化并重算受影响路径，只有三棵树的新根全都等于可信 E 时才接受。遗漏其他变化页会使根不符，而非仅凭收到的变化页各自有成员证明就接受。更新失败时回滚本地修改。

这一点修复了一个常见逻辑漏洞：**证明所报告的更新合法，并不能自动证明没有漏报更新。** 这里由“从完整旧状态重建当前可信根”保证覆盖全部变化。

### 3.3 新鲜挑战与当前版本

验证者在得到 R 后进行 q 次独立有放回抽样：每次均匀选择一个匹配文件，再均匀选择其四个块之一。对抽中文件请求元数据的规范 Merkle 多重证明，并在固定 C_D 下验证，获得当前 L。

每次抽样独立选择非零随机域系数 beta_u，挑战为保存于验证者本地的 `(E, nonce, [(i_u,j_u,beta_u)], [L_u])`。服务器接收样本坐标、系数与会话字段；nonce 用来识别会话，实际防止旧聚合响应复用的代数因素是新鲜系数和当前标签名字，不能把 nonce 本身当作持有保证。

### 3.4 响应与验证方程

服务器返回：

`mu_l = Σ_(u=1..q) beta_u m_(i_u,j_u,l) mod p`，

`sigma = Σ_(u=1..q) beta_u t_(i_u,j_u) mod p`。

验证者检查状态、nonce 和域元素的规范编码，再检查：

`sigma = Σ_u beta_u F_K(L_u) + Σ_l alpha_l mu_l mod p`。

诚实正确性由代入标签方程直接得到。由于 L 来自当前根下的认证元数据，而抽样来自验证者计算的完整 R，协议连接了查询结果、样本文件和当前数据版本。不能允许服务器另选 R、挑战系数、标签名字或可信根。

聚合响应含 18 个 mu、一个 sigma 和 32 字节 nonce，为 **640 字节**。这不是整轮协议通信：位图、元数据多重证明和 q 项挑战仍有开销。

## 4. 更新算法与成本边界

| 更新 | 索引工作 | 数据认证工作 | 旧查询处理 |
|---|---|---|---|
| 修改一个关键词关系 | 更新一页和一条树路径 | 0 个数据标签 | 更新缓存页后复算相应交集页 |
| 修改一个数据块 | 关键词根不变 | 更新一个块标签和一条元数据路径 | 旧挑战失效；新挑战使用新块版本 |
| 删除一个文件 | 更新一个存活页及路径 | 更新 active 元数据，不必重签其他块 | 不再进入结果 |
| 复用槽位插入 | 更新存活页；调用者按需更新关键词页 | 新 generation，生成四个新块标签 | 旧 generation 的标签不能代表新文件 |

关键词集合修改与存活标记可在工程层组成事务；本原型每次调用是一个独立授权状态，尚未实现跨调用原子事务。复用槽位默认保留其关键词位，应用需明确设置新文件的关键词。

令页数 P=N/512，结果数 r，不同抽中文件数 u≤min(q,r)。首次位图传输为 `3N/8` 字节，缓存位图及树节点约 `3*(64P+32(2P-1))` 字节，不含 Python 容器。当前代码结果数组每轮重建，成本为 O(P+r)，不能将整轮查询写为 O(变化页数)。

改变 d 个页时，缓存维护上界 O(d log P)，还要传变化页。元数据证明可用 O(u log N) 作为宽松上界，实际共享路径更小。数据聚合 O(q*18)，验证 O(q) 次 PRF 加 18 次域乘法。首次建立标签要遍历所有密文；它不是免费的预处理。

所有者原型保留完整管理数据，内存是线性的。没有证明小客户端状态；基准中的文件也只有 2 KiB，不能直接外推到大文件、远程磁盘或百万文件部署。

## 5. 安全论证的实际强度

1. **结果完整性：** 在可信根真实代表所有者状态、位置绑定哈希抗碰撞的前提下，首次接收或增量重建出不同位图仍被接受会导致根绑定被破坏。完整且正确的位图逐位求交得到全部匹配文件。
2. **当前版本绑定：** 更换文件或块的坐标、generation、版本，都改变认证名字；元数据证明固定当前名字。旧根拒绝策略阻止将历史有效响应解释为当前有效响应。
3. **数据响应认证：** 使用既有 PRF 线性认证结构。代码的攻击测试是工程证据；它不替代自适应多轮伪造安全规约。论文仍须正式处理多版本标签、接受/拒绝反馈和挑战历史。
4. **存储检测：** 在缺失集合于挑战前固定、缺失数据无法及时重构，且攻击者不能伪造聚合响应的条件下，令第 i 个匹配文件损坏块比例为 rho_i，则单次命中概率 `p_F=(1/r)Σ rho_i`，q 次检测概率为 `1-(1-p_F)^q`，另扣密码学伪造项。该式不是任意编码存储策略的提取定理。

例如 5% 的匹配文件全部缺失，q=64 的抽样命中概率约 96.25%；若这 5% 文件仅各损坏四分之一，则降为约 55.29%。针对后者达到至少 99% 需 q=367。要求“任何一个文件缺失都高概率检出”时不能沿用这个群体比例保证。

不声称：独立多副本存储、公开审计、零知识、访问模式隐藏、前后向搜索隐私、文件可提取性、永续持有或恶意服务器下端到端搜索隐私。服务器原型可见位图和审计位置；本轮只验证完整性内核。

## 6. 为什么暂不把隐藏 lookup 填进实现

上一轮“隐藏索引证明”尚未定义清楚向谁隐藏。现在明确区分：

- 对可信所有者隐藏自己的查询结果没有实际需要。
- 若向第三方验证者隐藏结果身份，需要公开可验证认证器及隐藏关联证明，本轮的秘密 PRF 验证器不能直接转为公开验证。
- 若向服务器隐藏匹配位置，服务器生成普通 lookup/ZK 见证时已经读取这些位置，事后零知识不能消除服务器已知信息。还需私有检索或私有计算，不能把 Merkle 树换成 Caulk 就声称解决。

若后续确实采用隐藏关系，必须同时证明：`s=a*b*v` 的全域布尔约束；索引承诺与当前数据元组之间的坐标对应；样本来自 s 的规定分布；相同样本上的新鲜数据认证。单纯批量成员关系允许漏项、重复，不能替代完整交集证明。

CCS 2024 已经构造可更新 lookup 与 committed index lookup，因此“增加更新”也不是空白。[原文](https://eprint.iacr.org/2024/840)。在缺少这部分实际实现之前，不能把通用证明的预处理、生成时间、见证维护或可信设置费用记作零。

## 7. 最强自然基线比较与创新判断

基线 B0：本轮同样的认证位图完整求交、元数据证明、私有线性审计，每轮冷启动。

基线 B1：B0 缓存位图和树节点，授权更新后增量维护，局部块版本绑定标签。

候选 C：上一轮建议的索引/数据分离、结果绑定、新鲜聚合、变化页缓存，在本轮可执行层面恰好就是 B1。**C 与 B1 是同一算法，不能人为编造两个名称的性能差异。** 基准只报告 B0 与 B1，B1 的数字也就是当前候选的数字。

已有 Song 等工作明确支持搜索验证和数据审计的统一证明，因此不能把“联合验证”本身列为主要新贡献。[TC 2025 论文记录](https://research.polyu.edu.hk/en/publications/enabling-verifiable-search-and-integrity-auditing-in-encrypted-de/)。这不等于本轮复现了其系统，也不能依据这里的 Python 时间宣称超越它。

本轮最有价值的结果是把研究门槛收紧：**原来的三项候选贡献中，结果绑定、局部版本更新、新鲜挑战都已被自然组合解释；尚没有证据证明专用新机制优于该组合。**

## 8. 面向论文的下一项实质任务

可以保留此内核作为正式基线和安全接口，但暂不将其扩写为 TDSC/TIFS 主方案。下一步只值得检验一个更严格的问题：

> 在明确的既有合取搜索泄露函数下，恶意服务器如何证明“完整结果集合与当前数据挑战一致”，且更新后证明维护比可验证合取搜索与同态审计的直接组合更便宜？

这里的进展必须是一组可验证方程或专用证明算法，并给出与同泄露、同检测合同的基线差异，而不是增加区块链、副本、授权等功能。若隐藏证明也能由已有 committed index lookup 以相同代价实现，候选仍应判为无独立贡献。

本阶段完成的是一次可执行内核与性能可行性筛查。完整隐私协议及 TDSC/TIFS 所需的新技术贡献尚未成立，这个负面判断应进入研究记录，而不应被毫秒级原型数据掩盖。
