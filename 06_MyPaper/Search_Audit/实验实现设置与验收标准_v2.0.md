## 1. 研究问题与可支持的结论

| 方向 | 本轮后续实现要回答的问题 | 不预设的结论 |
|---|---|---|
| C1 状态绑定的搜索—位置—共享内容审计 | 同一预期请求和可信状态下，结果全集、逻辑引用及数据响应是否被完整绑定；组合成本来自哪里 | JOINT 更安全、更快，或最小直接组合本身具有新颖性 |
| C2 覆盖保持的重复感知聚合 | UNIQUE-NZ 与优化 POS-FOLD-NZ 是否覆盖等价、有效分布一致，以及实际节省多少工作 | 唯一块抽样等于逻辑位置抽样；相比折叠有渐近优势 |
| C3 授权增量状态迁移 | 是否只修改授权关系、正确维护共享对象，并将实际工作限制在变化集及相关路径 | 普通分页或一次承诺更新就是新的动态算法 |

验收分三层：**实现合格 → 实验结果可信 → 贡献得到支撑**。第一层通过不意味着第三层通过；负例测试不代替密码学证明，性能门槛是本项目的预注册研究目标，不是期刊录用标准。

## 2. 必须先实现的共同内核

以下 M01–M10 是所有主对照共享的功能合同。主配置只能更换表中声明的算法轴，不得通过减少功能获得优势。

| ID | 必须实现的内容 | 实现验收证据 |
|---|---|---|
| M01 角色隔离 | Owner 持密钥；Server 仅持密文、标签、公开结构；Verifier 仅持公开参数、合法令牌、外部请求和可信状态。通过序列化消息交互 | 独立进程小系统通过；Server/Verifier 无原始 Oracle、拥有者私钥、SRS 陷门或其他配置数据目录访问权 |
| M02 统一编码 | `len64(m) || m || pad_to_B`；AES-SIV；独立派生状态签名与数据认证密钥；用户域、类型、长度和参数版本明确绑定 | C1/C2/C3 编码一致；部分末块与尾零区分；跨用户、跨类型、畸形编码拒绝；真实曲线运算与反序列化检查 |
| M03 共享对象 | 稳定 fid、规范 bid、可信/可认证对象目录、标签复用、引用计数及保留快照规则 | 不同密文的 bid 碰撞不静默合并；同内容合法多处引用接受；不覆盖仍被引用的对象 |
| M04 当前状态与搜索 | 独立状态签名、版本和根；状态字典成员/非成员；完整有序关键词列表和文件描述；索引页按方案加密 | 未知关键词、已存在空列表、空文件行为明确；无遗漏、无重复、顺序和边界检查；历史合法签名不替代当前根 |
| M05 位置认证 | 稳定页 ID、带子树计数的秩树、有效页长度；可替换 Merkle/已发表 PCS 页后端 | 证明必须绑定同一文件根、位置和 bid；非法秩、错误页、字典闲置项和重复坐标拒绝 |
| M06 查询状态机 | `Verify(public_params, expected_request, transcript)`；先认证结果、再抽样、冻结映射、再发布数据系数及后端挑战 | 外部请求不由 proof 自带请求替代；参数/qid/版本/令牌替换拒绝；挑战不能提前暴露；不预存新鲜挑战响应 |
| M07 数据公开验证 | 直接从公开认证 bid 计算身份项，使用响应 mu 和公开扇区基；三种挑战策略使用独立用途域 | 正式 verifier 不接收原始 sectors/ciphertext/完整 block messages；有效数据群项按 u+s 计数，另列结构认证成本 |
| M08 增量更新 | 批准操作、旧版本/根、受影响范围及邻接见证、对象/引用/关键词差分、未变化边界、新根和授权签名 | 未修改内容不重新 TagGen；无全库 clone；无隐含全文件扫描；未经批准相邻记录不变 |
| M09 事务与恢复 | 局部写时复制或 WAL；先持久化再发布；重放拒绝；提交后安全回收；串行提交、快照查询 | 在各持久化边界杀进程并重启，状态只允许完整旧状态或完整新状态；无悬空引用及损坏共享对象 |
| M10 可审计计量 | 真实调用计数、规范消息序列化、分阶段时间、内存/磁盘/缓存/SRS/WAL/拥有者状态 | 不用插入对象数替代 TagGen 次数；不把模型字节称为实测；Oracle 与验证器分离且不进入计时 |

共享信任范围：同一拥有者域、单关键词、精确固定分块去重、单服务器、串行更新。当前主实验不包含跨拥有者去重、链上共识、多副本或前后向搜索隐私。可信状态分发的渠道固定并记录；不把服务器提供的最新声明视为可信。

统一密码设置：BLS12-381、31 字节可逆扇区、独立哈希到群的扇区基，默认 B=4096 字节，密文长度 B+8+16，s=ceil((B+24)/31)=133。B=16/64 KiB 时 s=530/2115。SRS 尺寸按所选后端的真实次数界生成，记录 G1/G2 元素数、生成和加载成本；陷门只存在于隔离 setup 过程，禁止提供给 prover。状态签名算法、编码与参数在实现前写入 manifest 并对所有配置保持一致。

## 3. Baseline 命名与实现标准

### 3.1 用独立配置轴代替旧的混合枚举

后续 runner 需要支持以下逻辑配置（本轮不创建配置程序）：

| 配置轴 | 允许值 | 含义 |
|---|---|---|
| auth_mode | ROOT-HLA / SEP-OPT / JOINT | 最小认证组合 / 优化分离认证 / 多类型联合标签 |
| reference_backend | MERKLE-MP / PCS-PUB | 标准去重多证明 / R03 已发表多多项式打开 |
| challenge_mode | POS-RAW / POS-FOLD-NZ / UNIQUE-NZ | 原始逐位置 / 先折叠修复零和 / 直接唯一块非零系数 |
| transition_mode | FILE-REBUILD / LOCAL-PATH / AUTHORIZED-DELTA | 受影响结构重建 / 普通局部路径更新 / 本文跨结构授权变化集 |
| witness_mode | NONE / NOPRE / IMMEDIATE / LAZY | Merkle 无 PCS 见证 / PCS 三种维护方式 |

合法性规则：Merkle 必须为 NONE，不能生成 PCS 多项式、SRS 或见证矩阵；PCS 指定其维护方式。v1.1 自定义跨页证明仅作 `PCS-CUSTOM-EXPERIMENTAL` 附加分支，完成可靠性论证前不进入主结论。

**主方案默认配置：ROOT-HLA + MERKLE-MP + UNIQUE-NZ + AUTHORIZED-DELTA + NONE。** 使用 PCS-PUB 的配置为结构后端扩展，同样完成搜索、更新及恢复。默认选择不是已证明 Merkle 最优，而是便于建立最小可验证系统；本方案不能与完全相同配置比较并宣称优势。

### 3.2 C1 主对照与消融

| 名称 | 必须实现 | 用途与限制 |
|---|---|---|
| COMPOSED-ROOT-HLA | ROOT-HLA + MERKLE-MP + UNIQUE-NZ；完整静态查询语义 | 与当前 C1 主流程相同的工程构造，用于定义成本和证明边界，不作为一条虚构的竞争曲线 |
| COMPOSED-PCS | ROOT-HLA + PCS-PUB + UNIQUE-NZ；其余同上 | 已发表结构组件对照；只比较后端时双方统一 challenge_mode |
| SEP-OPT | 与 JOINT 使用同一后端、有效系数和状态；关键词/文件标签分别标准聚合，数据 HLA 独立验证 | JOINT 的匹配消融；禁止逐文件串行验证制造弱对照；采用安全的 multi-pairing，计入最终幂 |
| JOINT | 与 SEP-OPT 同输入；实现多类型聚合与用途/转录绑定 | 可选扩展；须单独完成组合安全论证；不把少一个最终判断等同于少一次网络交互 |
| ROOT-HLA | 不产生 gamma/kappa，仅保留状态/结构/共享数据认证 | v1.2 主流程的认证轴；与 JOINT/SEP-OPT 比较冗余标签，不再称为独立竞争算法 |

必须分别做：①固定 ROOT-HLA、UNIQUE-NZ 比较 Merkle/PCS；②固定后端、UNIQUE-NZ 比较三种认证轴；③将 R01 Adapted 等文献核心按功能差异单独展示。C1 的主要证据是端到端组合安全定义、证明及完整系统可执行性，不再从与自身等价的“直接组合”中制造性能收益。不能把 C2 或后端收益重复归到 C1。已有共享构建必须拆开，各配置仅生成和保存自身对象。

### 3.3 C2 主对照

| 名称 | 必须满足的标准 | 角色 |
|---|---|---|
| POS-RAW | 对相同逻辑样本逐位置生成非零系数并执行聚合；缓存预算相同，分别记录物理读取和重复运算 | 弱对照/机制消融，不是贡献裁决的唯一基线 |
| POS-FOLD-NZ | 在负载读取和标签 MSM 前按认证 bid 折叠；仅零和类重采；每个唯一块至多一次逻辑负载读取 | 必选强基线，允许短种子、缓存、MSM 等常规优化 |
| UNIQUE-NZ | 同样本、同认证映射冻结后，按唯一块直接生成非零系数 | 本方案 C2；与强基线比较相同分布，不强制实际随机系数相同 |

三者共用正式公开 verifier，不能让 baseline 使用旧的逐扇区抵消验证器。相同样本由外部测试调度固定；抽样种子、后发系数种子和配置专用随机用途分离。测 C2 核心与包含搜索/结构认证的查询全流程两种口径。

### 3.4 C3 主对照

| 名称 | 必须实现的标准 | 角色 |
|---|---|---|
| FULL-REBUILD | 重建受影响文件引用结构和变化关键词结构；只修改相应状态键；复用已有共享密文/标签，仍执行授权和事务 | 局部化消融；不得无理由重加密全库 |
| LOCAL-PATH-MERKLE | 秩树、页内/页间多证明、局部重平衡和普通逐结构状态提交 | 必选强基线；不把它与本文变化集协议重复画成两条方案曲线 |
| AUTHORIZED-DELTA-MERKLE | 在同一 Merkle 后端上，补丁统一绑定 ΔRef、ΔObj、ΔKW、未变化边界和一次状态迁移 | 本文 C3 配置；须证明相对 LOCAL-PATH 的新增授权关系和验证工作界 |
| LOCAL-PCS-NOPRE | 同一序列封装，按需从当前页生成打开，不存全量单点见证 | 强基线/后端变体 |
| LOCAL-PCS-IMMEDIATE | 同封装，每次更新真实维护受影响缓存见证；初始化及更新因子全计费 | 强基线/维护策略变体 |
| LOCAL-PCS-LAZY | 同封装，维护认证延迟记录；查询使用当前承诺，明确刷新后是否写回缓存；到阈值重建 | 强基线/维护策略变体；终点排空或列明全部未完成费用 |

这三种 LOCAL-PCS 是共同 KZG/PCS 框架内的工程对照，不称 BalanceProofs 完整复现。主比较固定 ROOT-HLA 和 UNIQUE-NZ；FULL-REBUILD 分别匹配 Merkle、PCS 后端，避免混淆重建策略与后端差异。

若 AUTHORIZED-DELTA 最终与 LOCAL-PATH 具有相同消息、验证工作和事务机制，则二者是同一配置：只能报告功能和扩展性，不能人为保留两条重复曲线。C3 的方案差分固定为跨文件引用、共享对象和关键词索引的统一受约束迁移；Merkle/PCS 只是可替换后端。

## 4. 实验数据与固定参数

### 4.1 通用生成规范

主数据由合成生成器产生，不使用合成数据声称真实业务分布。三种分布固定为：均匀独立、Zipf(1.1) 版本族共享、热点/低频尾部偏斜。所有配置重放同一字节、关键词关系、逻辑样本、更新轨迹和损坏集合。

L 为全库逻辑块数，U 为实际唯一块数，重复率 D=1-U/L；q 为本次逻辑样本数，u 为样本中的唯一块数。D 和 q/u 不互相替代。生成器精确控制整数 U（记录舍入误差），先保证所有唯一块至少出现一次，再分配共享引用；查询结果数由关键词成员集合精确控制，并核对关键词总关联数的可行性。所有字节由内容 ID 和负载种子确定性产生；记录唯一块、引用度分位数、页数、填充比例及实际 q/u。

种子分为 data/query/update/corruption/setup，各自独立且记录到 manifest；攻击者不得提前取得挑战随机性。预先生成的测试轨迹仅由调度器持有，按协议阶段发送。受控 q/u 实验可以固定样本映射，必须标记为核心微基准，不冒充自然查询。

### 4.2 三档配置

| 档位 | 数据/重复量 | 用途 |
|---|---|---|
| smoke | 20 文件 × 16 块，4 KiB，D=0.5，r=5，c=4，引用/关键词页容量 8/16；3 个数据种子；每个种子 20 查询、100 次更新 | 后续开发快速验收；不用于尾延迟/贡献裁决 |
| main | 下表三个方向的主点及单因素扫描；每参数点 10 个数据种子，每种子 30 次测量；固定 5 次不计时预热 | 正式受控实验；冷热分组运行，cold 每次独立重置 |
| stress | 通过 main 后，C3 最多 100,000 初始块、100,000 次操作；大结果集和大页按扩展表执行 | 扩展性与空间增长；不自动启动，资源预算冻结后安排 |

不运行参数全笛卡尔积。每次只改变一个因素，三种分布分别报告；仅额外执行明确写出的交互组。N 表示文件数，n 表示每文件逻辑块数，r 表示匹配文件数，c 表示每匹配文件样本数，合法性必须满足 r≤N、c≤n（空文件 c=0）。

### 4.3 C1 配置

主点：N=1,000，n=64，B=4 KiB，D=0.5，每文件 5 个关键词，r=50，c=8，引用/关键词页容量 64/128。C1/C2 配对对照使用相同后端和维护状态。

| 单因素 | 取值 |
|---|---|
| N | 100 / 1,000 / 10,000 |
| n | 16 / 64 / 256 |
| r | 1 / 10 / 50 / 100；500 / 1,000 为扩展点 |
| c | 1 / 4 / 8 / 16 |
| D | 0 / 0.25 / 0.5 / 0.75 / 0.9 |
| 引用页容量 | 32 / 64 / 256；关键词页默认 128，额外扫 32 / 128 / 512 |
| B | 4 / 16 KiB；64 KiB 为扩展点，按真实 s 计费 |

交互组仅增加 `(r,D)∈{10,100}×{0,0.9}`。零结果、空文件、重复整文件和部分末块属于正确性专用集，不混入非空查询的加速平均数。

### 4.4 C2 配置

核心受控点：q=1,024，q/u=1/2/4/8/16/32，故 u=1,024/512/256/128/64/32；固定 u=128 另扫 q=128/256/512/1,024/2,048/4,096。采用真实 4 KiB/133 扇区，三种挑战策略共享每一个样本坐标和映射。均衡与偏斜重复类分别构造，所有唯一类必须被使用。

自然查询使用 C1 主点和 D 扫描，记录实际 q/u，不将目标比例写作观测比例。损坏比例按唯一块为 0.1%/1%/5%，小集合使用 max(1,ceil(rate×U)) 并报告实际数量与比例；分别选随机、低引用、高引用和单文件独有块，在抽样前固定。概率主点做 10,000 次便宜抽样，每种攻击另做 100 个预注册真实密码挑战（含命中及未命中，分层展示，不据其混合比例估计命中率）。

小域穷举 p=7，重复度 1–4；固定支持集提取 u=8/16/32/64；压缩测量 k/u=0/0.25/0.5/0.75/1，攻击状态只含已声明测量、标签及结构，销毁负载和生成种子。小域、线性代数模拟、真实 BLS12-381 结果分开输出。

### 4.5 C3 配置

主点：10 文件 × 每文件 1,000 块，共 10,000 块；B=4 KiB，D=0.5；每文件 5 个关键词；引用/关键词页容量 64/128；每个种子一条 10,000 次操作轨迹。以 10 个文件固定，改变每文件块数产生总量 1,000/10,000/100,000（最后一项属于 stress），以区分目标文件长度与总存储规模。

| 因素 | 固定值/扫描 |
|---|---|
| 更新类型 | 40% 修改、25% 插入、25% 删除、10% 字节 splice；修改中 50% 指向已有块 |
| 关键词 delta | 70% 不变、10% 新增、10% 删除、10% 增减混合；由独立 Oracle 产生可信关系，不假装实现了内容语义提取 |
| 查询:更新 | 95:5 / 50:50 / 10:90，主点 50:50 |
| 局部性 | 均匀 / 80% 更新集中在 20% 页 / 连续突发与页边界，主点均匀 |
| 批量操作数 | 1 / 10 / 100，主点 1；相同批准范围，原子提交 |
| 引用页容量 | 32 / 64 / 256；LAZY 刷新阈值 8 / 32 / 128 个页内变化记录，默认 32 |
| 更新后查询 | 专用回放分支测第 1/10/100 次查询及累计代价，不额外注入主混合轨迹 |

必做交互为三种查询更新比 × 三种局部性，其他参数固定主点。非法位置由生成器按当前 Oracle 状态避免；强制空文件/边界操作单列测试。字节 splice 的后缀重新分块按真实变化数 k 计费，不能拿它要求固定 O(1) 更新。

调参只用独立开发种子，页容量和 LAZY 阈值给双方相同搜索预算；main 冻结参数，不用 main 的最快测量反向挑配置。三个 PCS 策略都报告，最佳已冻结策略是强对照。

## 6. 计量与统计标准

1. 查询端到端从发送初始请求到最终验证结束，包含实际交互等待；分别报告 Owner/Server/Verifier CPU、搜索和结构处理、数据聚合、认证、编码/I/O。setup、外包和状态分发单列；不把理论相加时间当网络实测。
2. 更新从获取旧见证、Owner 准备授权补丁，到 Server 持久化发布并返回确认；首次/持续查询、后台工作和终点排空另列，同时报告完整轨迹总成本。
3. 性能与正确性重放分开。正确性轨迹每步完整恢复并与 Oracle 比较；性能轨迹执行同一操作与密码检查，Oracle 不进入计时也不预热服务端缓存。计数器可开关，报告计数本身的开销；输出真实 TagGen 调用数而非新插入条数。
4. 真实规范序列化记录 request/proof/update/ack 及双向总字节；SRS/初始化通信单列。`modeled_wire_bytes` 仅作估算附表。区分网络栈字节与应用消息字节。
5. 空间按原始文件、填充后逻辑密文、唯一密文、标签、引用、关键词页、认证树、SRS、见证、缓存、WAL/旧快照、Owner 状态分项；另报峰值 RSS 和落盘大小。GC 后净增长与保留快照占用分开。
6. 固定 release、依赖锁定、CPU/内存/存储/线程、缓存预算及参数；记录环境和系统负载。不同配置串行运行，每个数据种子内随机化配置顺序；禁止同时跑多个性能任务造成争用。主报告单线程。
7. warm 与 cold 分开。cold 写清是进程缓存、数据库缓存还是 OS 页缓存；未能控制 OS 缓存时不得标为冷盘。算法 CPU 微基准可用内存数据；持久化/I/O 实验必须实际物化负载，不能把即时生成当读取。
8. 主结果 10 个独立数据种子，各 30 条匹配查询，共 300 条；每个配置处理相同请求。报告每种子中位数、总体 p50/p95与配对差异；按数据种子成组 bootstrap（10,000 次）计算 95% 区间，不把同一数据上的重复当独立数据。C3 按轨迹种子聚类，不把相关操作当独立样本。
9. p95 门槛不以每种子 30 条独立判定；使用全组分布及种子聚类区间。若区间宽或跨门槛，记为证据不足。样本扩展需事先登记且所有配置一起扩展，不选择性追加至显著。
10. 概率实验报告精确二项区间；10,000 次零误接受只能给出统计上界，不能写成安全概率为零。超时/OOM/失败和资源上限全部保留；以失败配置缺失后的幸存者均值宣称优势不予验收。
11. 网络轮次必报；如声称广域收益，再增加受控 RTT=0.5/20/80 ms、带宽=100 Mbps、无丢包的真实仿真链路，包含密码耗时，明确为仿真。不做网络测量时仅声称本机成本和字节差异。

## 7. 验收标准

### 7.1 G0：实现合格，未通过不得跑正式性能

- 所有主配置诚实查询和恢复精确一致，E1 确定性负例按定义拒绝；应接受的合法共享/空文件接受。
- 三种分布各 3 个开发种子、每种子 10,000 步随机更新，所有 C3 主配置通过完整 Oracle 对照；每个崩溃注入边界完成至少 20 条固定种子的独立事务恢复测试。
- 正式公开 verifier 原始负载读取数为 0，私钥访问数为 0；M06 请求替换和阶段顺序检查通过。
- LOCAL 对未变化块 TagGen 为 0；更新到已有对象不新 TagGen；同一事务 a 个新唯一对象应生成 a 个数据标签，签名等其他调用分项。全库 clone 次数为 0。
- Merkle 配置 PCS 构建/见证维护次数为 0；未变化文件与无关关键词不重建。随全库无关文件扩张，固定目标更新的访问对象计数仅允许由认证路径高度等声明结构引起变化，禁止线性全库扫描。
- 各配置独立存储、共享优化预算、真实序列化及原始计量齐全；原论文配置取得第 3.5 节准入证据。

这些要求是待实现的验收目标；此前 6 项小测试不能替代 G0。

### 7.2 G1：结果可信

main 的预注册主点与单因素核心点全部有完整原始数据，区分模拟/结构微基准/真实端到端；10 个种子无选择性丢弃；报告成功和失败配置、冷暖、参数、缓存及后台费用。E9 必须通过。同功能基线缺失、计量漏项或安全失败时暂停比较性结论。

### 7.3 G2：贡献支撑及定量目标

共同规则：收益 `gain=1-T_proposed/T_baseline`，回退 `regression=T_proposed/T_baseline-1`；相同输入做配对。宣称达到收益门槛时，95% 区间下界也需达到门槛；宣称回退不超过上限时，区间上界需不超过上限。主结果与所有扫描同时展示，不能事后更换主指标。多配置最佳对照用独立开发集固定；若报告逐点最优包络，明确其不可部署性。

| 方向 | 固定主要结果指标与项目目标 | 未达到时的结论 |
|---|---|---|
| C1 | 默认先验证组合语义和给出组合安全论证。若有与直接组合明确不同的新机制，在两种分布及 N=100/1,000/10,000 三点上，相对功能匹配强对照：端到端中位数降低≥15%、p95回退≤5%；或实际总查询通信减少≥20%、端到端回退≤10% | 默认 ROOT-HLA 若等同已有直接组合，只能称完整系统构造；C2或PCS的收益不能重复记为 C1 创新。JOINT 未提供独立性质则保留消融 |
| C2 | 相对 POS-FOLD-NZ，在均衡/偏斜受控 q/u=4/8/16 三点均报告核心与集成时间；作为独立性能贡献须集成查询中位数改善≥10%、p95回退≤5%，并在自然 D=0.5/0.75 查询复核同方向收益 | 覆盖/分布证明可仍成立；性能不足则并入 C1 的引理与实现优化，不称独立高性能贡献 |
| C3 | 在三种查询更新比×均匀/热点两种局部性上，比较已冻结的 LOCAL-MERKLE 与最佳 LOCAL-PCS：更新中位数改善≥20%、更新p95不回退、查询中位数/p95回退≤10%、辅助空间增加≤20%；并报告完整轨迹总成本 | 只胜 FULL-REBUILD 不足；若是不同权衡，报告带不确定性的 Pareto 结果，不强行声称全面更快；算法相同则仅作为系统扩展 |

C3 上述统一门槛是较强目标；若仅特定查询更新比例存在收益，应限缩到事先声明的适用范围，保留其他点的负结果。Pareto 判断使用查询、更新、空间和完整轨迹成本，至少一维有超出测量不确定性的改善，不能把统计重叠的小差异称为新优势。

新安全性质可以是独立贡献证据，但必须在**相同信任、泄漏、状态与功能目标**下给出定义、文献差异和证明。不能故意削弱 baseline，再以负例通过率宣传优势。达到上述数字亦不自动证明新颖性；论文是否足够支撑最终还取决于与已有工作的实质区别和证明完成度。
