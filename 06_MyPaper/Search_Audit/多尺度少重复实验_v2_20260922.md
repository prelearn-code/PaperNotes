# 多尺度、少重复实验 v2

日期：2026-09-22。用户要求增大能体现算法差异的数据量、减少重复次数，并优先完善关键实现。本版替代紧凑实验的后续调度，旧结果保持原样。

## 已完成修改

- C1 新增 `--challenge-mode POS-RAW|POS-FOLD-NZ|UNIQUE-NZ` 和 `--root-merkle-only`，可在相同数据、样本种子、认证后端上比较完整查询。`query_totals.csv` 包含 owner 起始阶段和整个查询 wall time；明确标记本地编解码或 TCP relay。
- TCP relay 两端均启用 NODELAY，消除已识别的单端配置缺口。新主矩阵默认使用本地规范消息编解码，以测算法组合成本；不宣称已实现角色独立进程计算。
- C2 新增 `--controlled-skew`，在固定 q/u 下同时测 balanced 与 one-hot-tail 布局。后者先保证每个唯一块出现一次，再将其余引用分配给热点块；记录 layout 列，不能与 balanced 混合汇总。
- C3 取消 LOCAL-MERKLE 在完整补丁授权之外的重复组件签名。回归测试验证它与 AUTHORIZED-DELTA-MERKLE 的消息、工作计数和状态根相同；新 runner 使用 `--distinct-variants`，只测一个名称。不能再声明相对这个别名的加速。
- C3 页更新只在已授权变化区间内找公共前后缀；移除两次完整引用数组复制，保留长度计算改为只访问删除区间。回滚快照仍复制文件，Vec 插删仍可能移动后缀，尚未达到严格变化集复杂度。
- C3 新增 `trajectory.csv`：完整更新/查询循环时间、Oracle 时间、checkpoint 时间、全部终点查询时间、Oracle 检查数及残余延迟日志字节。checkpoint 已含在 trajectory wall 中，不能重复相加；Oracle 单独列出。该循环时间仍含观测开销，不称纯算法内核时间。
- C3 新增 `--oracle-every N`。Oracle 每步应用原始操作，大规模实验每 40 步及最后一步认证恢复并对照；小验证每步检查。`--performance-only` 也保留最终 Oracle 对照。

## 冻结配置

配置：[decision_scale_v2.json](../../../Exp/Search_Audit/workloads/decision_scale_v2.json)。入口：[run_decision_scale.py](../../../Exp/Search_Audit/scripts/run_decision_scale.py)。全部 4 KiB 数据块、真实密码运算；不设运行超时。

| 方向 | 数据规模 | 测量 |
|---|---|---|
| C1/C2 集成主点 | 128 文件 × 64 块，匹配 32 文件，D=0.5 | 均匀/偏斜 × 3 种子 × 3 策略 |
| C1/C2 集成重复率点 | 同上，D=0.75 | 均匀/偏斜 × 3 种子 × 3 策略 |
| C1/C2 集成尺度点 | 512 文件 × 64 块，匹配 128 文件，D=0.5 | 均匀 × 3 种子 × 3 策略 |
| C1 认证消融 | 主点 UNIQUE-NZ | 六种认证/后端组合 |
| C2 核心 | q=1024；q/u=1/2/4/8/16/32 | 均衡与真实热点布局；3 策略；两分布 × 3 种子 |
| C3 尺度 | 4 文件 × 128/512/2048 块，即 512/2048/8192 初始块 | 3 种子；每组 120 更新；五个不重复变体 |
| C3 探索 | 中尺度 uniform 95:5、10:90，以及 hot-80-20 50:50 | 各 seed-0，单种子探索 |

每种子只测 3 次查询、预热 1 次；保留 3 个独立数据种子。总计 63 个单元，顺序串行。当前组间策略顺序固定，性能结论还应检查顺序/缓存效应；3 次查询不能支持稳定的 p95。C3 每 60 次更新 checkpoint，终点日志余量明确列出，不假设 LAZY 已排空。

## 验证与判定边界

2026-09-22 已通过 42 项 Rust 测试、`cargo clippy --all-targets -- -D warnings`。新增公平性别名测试、受控布局支持集与重复度测试通过。

[修订验证结果](../../../Exp/Search_Audit/results/decision_v2_verify_20260922/status.json)：5/5 单元通过，耗时 100.83 秒；覆盖三种完整查询策略、六种认证/后端组合、双布局 C2 核心实验、五个 C3 变体的 Oracle/攻击/恢复及新计时输出。验证不是 63 单元矩阵。C2 函数参数随后做了不改变行为的封装以通过 Clippy，验证目录保存运行时源文件哈希。

以下关键门槛仍未实现，runner 会输出 `paper_claims_ready=false`：

1. C1 角色独立执行；当前仅有对象隔离和规范消息接口。
2. C3 相对最优安全局部组合的独立算法差异。去除重复签名后两个名称确实等价，不能靠增加数据量改变这一点。
3. C3 严格局部复杂度：文件快照和 Vec 后缀移动仍存在。
4. 有界历史恢复：checkpoint 仍保存历史事务并在恢复时重放，尚非当前状态快照。

因此新矩阵能更可靠地回答 C2 的集成性能和现有结构的尺度趋势，但不能独自证明三个贡献全部成立，也不能据此宣称完整复现文献系统。旧 `run_feasibility.py` 的六变体比较与旧结果分析脚本属于上一版；新结果不得混入旧数据。
