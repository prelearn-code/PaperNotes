# 1. 整体研究背景

## 1.1 云存储的规模压力与信任真空

2025 年这一批论文的背景叙述高度一致，都建立在同一组现实数字上：

- **规模**：IDC 统计 2025 年云存储数据将超过 **175 ZB**，其中 **50% 以上是重复数据**（Liu Bingyun）；外包给 CSP 的数据中**近 75% 是冗余副本**（Zhang Qingyang）；个人数据量可达 5200 GB，2027 年全球公有云服务收入预计 **1.34 万亿美元**。
- **控制权丧失**：数据外包后物理失控，CSP 面临硬件/软件故障与黑客攻击导致数据丢失；更麻烦的是 **CSP 为节省空间可能故意删除不常用数据**，且为维护声誉可能**伪造"数据完好"的证明**。
- **审计的信任成本**：公开审计引入 TPA 替代用户验证，但这套设计从诞生起就带着"默认 TPA 诚实"的强假设。Liu 明确指出：TPA 好奇、会产生**恶意审计偏置**，甚至与 CSP 合谋；Miao 补充了一个更实际的问题——**TPA 必须始终在线等待 CS 响应，一旦响应不及时审计就失效**。

## 1.2 三条彼此纠缠的技术主线

### （1）加密与去重的冲突

常规加密把相同明文变成彼此不同的随机密文，直接阻断去重。标准答案是 **收敛加密（CE，Douceur）** 与其形式化 **MLE（Bellare 等）**：密钥由数据内容派生，相同明文得到相同密文。但 MLE 只提供 convergent security，对低熵/可预测数据可被**离线暴力破解（BFA）**。缓解手段是引入密钥服务器控制密钥生成速率，但这又带来**单点故障**与频繁交互的通信开销。

### （2）认证标签自身的冗余

Zhang Qingyang 提出了一个此前被忽视的角度：**收敛加密解决了密文去重，但认证标签仍然冗余**——标签大小与文件数线性相关，甚至可能大于文件本身。用文件哈希作签名密钥可以做到标签去重，但**同一文件标签在审计中复用会暴露"谁拥有同一文件"**（所有权隐私 OP 泄露）；把审计证明放公开链上同样因"同文件证明相同"而泄露 OP。

### （3）审计的粒度与表达力不足

- **粒度太粗**：已有"去重 + 审计"结合方案**几乎全部停留在文件级**（Liu 明确统计了 BDA/BASD/ALDAD/ETDA/BDIA 等一批方案），而真实场景中同一文件内部与跨用户都存在大量重复**数据块**，文件级去重无法提升块级存储效率。
- **表达力不足**：传统 PDP 面向"精确数据完整性"，验证特定未改动数据块存在，**天然不支持近似匹配/语义相似性**（Miao）。而在大规模相似数据集里，个体只关心音频/视频等特定文件、科研机构只关心某领域（心跳、血常规）数据，因此迫切需要**可搜索审计**。

## 1.3 本标准之外的两条线

2025 年这一批还包含两类不属于"云存储审计方案"的工作，但它们构成了整个方向的地基与外延：

- **理论基础线**（Shi Elaine、Bonneau MMR）：去中心化归档到底该怎么定义？见证更新频率的理论下限是多少？这两篇给出的不是方案，而是**定义与下界**。
- **跨域应用线**（Niemi、Sensintaffar、Wang Yuchun）与**新场景线**（Yan Binyuan）：把去重/完整性技术用到癌症登记、DNA 存储、遥感数据、大模型。这些工作的**威胁模型与云安全去重完全不同**——它们的"敌人"是数据质量、生物噪声、带宽约束与模型记忆，而不是不可信的服务器。

# 2. 整体研究现状与共性问题

## 2.1 技术演进主线

| 主线 | 代表工作 | 核心动作 |
|---|---|---|
| 去重 ↔ 审计一体化，粒度下沉 | Liu Bingyun | 把去重从文件级下沉到**块级**（文件内 + 跨用户两重），并用稀疏求和 Verkle 树 + 代理重签名支撑 |
| 去重 ↔ 审计一体化，标签也去重 | Zhang Qingyang | 让**认证标签本身**可去重，并用"确定性用于去重 / 随机化用于公开"分离两种标签 |
| 可搜索审计的统一证明 | Mingyang Song | 用**关键词关联标签 kt + 一次配对验证**同时完成可验证搜索与完整性审计 |
| 可搜索审计的可仲裁化 | Miao Ying | 关键词索引嵌入认证器 + 区块链多任务挑战 + **仲裁者重放复核** |
| 认证数据结构的理论边界 | Bonneau MMR | 用**压缩论证**证明 append-only 累加器的见证更新频率下界，并证明 MMR 本质最优 |
| 去中心化归档的形式化 | Shi Elaine | 提出 iDDA 的**新定义**（近似最优可恢复性 + 复制安全）与层次化构造 |
| 去重技术的跨域迁移 | Niemi / Sensintaffar / Wang Yuchun | 分别用 Simhash+S-W、层次化链/块去重、轻量 ViT 语义去重解决医疗/ DNA /遥感场景 |
| 新场景的数据完整性 | Yan Binyuan | 为大模型提出"风险建模 + 语义哈希 + CKKS + DP 审计"的四层框架 |

## 2.2 尚未解决的共性问题

1. **"信任外包"被不断转移而非消除**。Liu 用智能合约替代 TPA，但需要 **N 个可信代理在线**参与代理重签名，并附加"**CSP 不与代理或任何用户合谋**"的强假设——把 [19] 的"用户实时在线"问题变成了"代理在线"问题。Zhang 用合约替代 TPA，但**所有权隐私明确不覆盖 CSP**（CSP 必须知道 $s_F$ 才能去重）。Miao 干脆让 CS 自己推导挑战、自己验证，防线只剩区块链不可篡改与事后仲裁。
2. **密钥管理与文件数解耦只做了一半**。Zhang 做到了加密密钥与文件数无关（IBBE 分发收敛密钥、无密钥服务器交互 → 密钥生成阶段**零通信**），但**用户存储仍是 $(F+1)|\mathbb G_1|$，随机文件标签 $\zeta$ 仍随文件数线性增长**。
3. **低熵数据的暴力破解面被搬走而非堵死**。Zhang 用随机 $k_l$ 替代 MLE 密钥加密数据，但 CSP 长期持有密文 $c$ 与掩码 $K_l=k_l\oplus H_2(F)$，且检索时用 $K_C'=H_2(F)$ **自校验**，因此仍可对低熵文件做离线字典攻击：猜 $F'\to H_2(F')\to k_l'\to$ 解密 $c\to$ 用 $H_2$ 自校验。
4. **形式化安全证明的覆盖不完整**。Zhang 与 Miao 两篇均只有非形式化论证（Zhang 三个定理均为论证式；Miao 的 Thm1 证明放在附录但核心防线是"自证 + 仲裁"）；Liu 的安全证明只覆盖机密性、OP 与存储正确性，未分析区块链分叉等。
5. **动态更新普遍缺位**。三篇云存储方案（Liu、Zhang、Miao）**均未涉及数据动态更新**；Liu 亦未涉及多副本与相似（非完全相同）数据去重。
6. **理论成果与工程实践之间没有桥**。Shi Elaine 与 Bonneau 两篇给出了漂亮的下界与渐近界，但**都没有原型实现或实测数据**；Shi 的提取器是准多项式时间、纠删码冗余 $R=e^{O(1)/\varepsilon}$ 在实际 $\varepsilon$ 下常数可能很大；Bonneau 的下界是渐近形式，不给每个元素的见证变化次数分布，工程上难以为 FlyClient、OpenTimestamps 外推实际更新频率。
7. **"相似"一词在不同论文里指完全不同的东西**。Miao 的"相似数据"实际用**关键词共现**（布尔索引向量）刻画，并非向量相似度；Wang Yuchun 的"相似"是 **768 维语义嵌入的余弦相似度**；Sensintaffar 的"相似"是**允许若干核苷酸不同的链**；Ha（2026）的"相似"是 **N-transform 特征**。四者不可互换，跨论文比较"相似性检测效果"没有意义。

# 3. 主题一：安全去重与完整性审计的一体化

> 论文：Liu Bingyun、Zhang Qingyang

## 3.1 研究背景

云上冗余是常态（175 ZB / 50% 以上重复；外包数据近 75% 冗余），去重是 CSP 最直接的降本手段。但要同时满足三件事就变得困难：

- **机密性**要求加密，而加密破坏去重 → 用收敛加密/MLE 解决，但 MLE 对低熵数据可暴破；
- **完整性**要求审计，而审计需要认证标签 → 标签本身也冗余；
- **计费公平**要求去重收益可验证 → 而谁去重、去了多少，只有 CSP 自己知道，这给了 CSP **恶意去重**（直接删掉部分"不常用"的唯一数据块）的空间。

此外，已有"去重 + 审计"方案几乎全部是**文件级**去重（BDA、BASD、ALDAD、ETDA、BDIA 等），但真实场景里同一文件内部与跨用户都存在大量重复**数据块**。

## 3.2 研究现状

**（1）完整性审计线**：POR（Juels–Kaliski）、PDP（Ateniese）、Shacham–Waters；私有审计用户自负计算负担；公开审计引入 TPA 并依赖"TPA 完全可信"的强假设，而 TPA 可能与 CSP 合谋；后续有方案让 TPA 检查后把证明与审计日志作为交易上链，以及面向智能交通的代理导向完整性审计。

**（2）加密去重线**：CE（Douceur 用明文哈希作密钥）→ MLE（Bellare 等首次形式化）；此后多数机制易受**离线 BFA**；有方案用密钥服务器生成加密密钥抗 BFA，但**存在单点故障**；也有口令保护密钥、密钥服务器组 + 周期性更换成员；客户端去重省开销但需 PoW，且**易受 BFA**；Halevi 的 PoW 协议防止攻击者窥探文件标签行骗——**但这些机制只考虑去重，不关心去重后数据的完整性与可用性**。

**（3）去重 + 审计结合线（Liu 的逐条梳理）**：

| 方案 | 具体不足 |
|---|---|
| Yuan & Yu [33] | 在**明文**上去重，无法保机密；要求所有用户上传认证标签 |
| Xu [23] / BEDA | 对明文与认证标签去重，但**不保机密性** |
| Yuan [22] / BASD | 保机密，但**不防 OP 泄露** |
| Zhang [34] | 区块链双副本 + 公审 + OP 保护，但**有数据泄露风险、不能抗初始上传者的 DFA** |
| Song [20] / ETDA | OP 保护 + 无 TPA，但**直接用文件内容哈希作签名密钥**，低熵文件密钥不安全、审计结果不可靠 |
| Miao [35] | 基于身份的区块链去重审计，可抗 DFA |
| Gao [21] / ALDAD | 用初始上传者随机密钥生成标签，但**不能保证后续上传者的审计结果、也无法监督 TPA 恶意** |
| Zheng [36] / DIADD | 支持动态操作与轻量认证器，但**未考虑 TPA 审计偏置与低熵密钥易被暴破** |
| Song [19] / BDIA | 用随机因子解决低熵密钥安全，但**用户侧计算开销高且审计要求用户实时在线**，资源受限设备不可行 |

**（4）标签去重与密钥管理线（Zhang）**：Yuan [11] 首个基于去重的完整性审计，但要求所有用户为同一文件计算并上传标签，本地开销大；Liu [13] 用 MLE 密钥作标签密钥实现标签去重，但**低熵数据下无法保证审计结果准确性**；Gao [14] 用初始上传者密钥替代 MLE 密钥，**只保证初始上传者、不保证后续上传者**；Yuan [5] 用智能合约执行审计，但**认证器数与文件数线性相关**；Tian [6] 用两个 SSP 解决单点故障并互审，但**用户必须保持在线以周期性更新验证标签**；密钥服务器路线（Li [9]、Zheng [10]、Zhang [28] 密钥服务器组）**始终摆脱不了对密钥服务器的依赖与单点故障**。

## 3.3 存在的问题

| 问题 | 具体表现 |
|---|---|
| **粒度太粗** | 现有去重 + 审计方案几乎全部文件级，无法提升块级存储效率 |
| **初始上传者伪装攻击（DFA）** | 初始上传者可上传与密文不匹配的认证标签欺骗后续上传者 |
| **低熵暴力破解（BFA）** | 以文件内容哈希作签名密钥的低熵文件可被离线暴破 |
| **所有权隐私（OP）泄露** | 确定性文件标签暴露"谁拥有同一文件"；公开链上相同文件的审计证明可关联 |
| **TPA 恶意偏置** | TPA 与 CSP 合谋给出偏置结果，或把 OP 暴露给审计者 |
| **认证标签冗余** | 标签大小与文件数线性相关，甚至大于文件本身 |
| **恶意去重无监督** | CSP 为省空间直接删掉部分唯一数据块，用户无法察觉 |
| **用户侧开销与在线要求** | 用户侧计算重且审计需实时在线，资源受限设备不可行 |

## 3.4 解决方式

### 3.4.1 Liu Bingyun（BA-FGDIA）：块级细粒度去重 + 可验证去重块数

七个多项式时间算法（System Initialization / Duplication Detection / Initial Uploading / Subsequent Uploading / Integrity Auditing / Log Checking / Data Retrieval），四实体：CSP、用户、**N 个可信代理 TP**、区块链。

**（1）细粒度怎么划分粒度**：文件 $F$ 切成 $n$ 块 $\vec F=\langle m_1,\dots,m_n\rangle$，做**两重块级去重**——文件内 internal dedup（$m_i=m_j$）与跨用户 external dedup。

- 对密文块 $CC_i=\mathrm{Enc}(h_5(m_i),m_i)$ 生成部分去重标签 $\mathrm{tag}_i'^{(id,F)}=pk_c^{sk_1^{(id)-1}+sk_1^{(id)}h_3(CC_i)}$；
- CSP 用配对消去用户私有成分，得到**用户无关**的最终标签
  $$\mathrm{tag}_i^{(id,F)}=e(\mathrm{tag}_i'\cdot pk_1^{(id)-\varsigma^{-1}},pk_1^{(id)})=e(pk_c^{h_3(CC_i)},g)$$
  故 $m_i=m_j^*\Rightarrow\mathrm{tag}_i^{(id,F)}=\mathrm{tag}_j^{(id^*,F^*)}$，**可跨用户比对**。
- 检测结果经加密重构矩阵 $\mathbb M$ 压缩成比特串 $R$ 回传，用户重建 $\mathbb R_{n\times n}$，算 $\vec{\mathbb F}=\vec F^T\cdot\mathbb R$：$\vec{\mathbb F}=\mathbf 0$ 全原始；$\vec{\mathbb F}[i]=0$ 非重复；$\vec{\mathbb F}[i]=\vec F[i]$ 外部重复；$\vec{\mathbb F}[i]=\vec F[j],i\ne j$ 文件内重复。
- **计费策略**：重复块越多、外包费用越低——既激励去重，又抑制 CSP 恶意删块。

**（2）PoW 后续上传（固定大小证明）**：CSP 把重复块的部分加密密钥集 $\mathcal B$ 交给用户；用户算重复密文上传；CSP 对向量承诺位置计算开值并用**固定大小**验证式校验用户确实持有这些块
$$\prod_{j=1}^{\eta}e\big(V_j^{x_j'},\prod_{i\in\omega_j}\gamma_{\mathbb N-i}^{x_{ji}}\big)=e(\bar\Phi,g)\cdot e(\gamma_0,\gamma_{\mathbb N})^{\sum_{j=1}^{\eta}x_j'\sum_{i\in\omega_j}c_ix_{ji}}$$
用**稀疏求和 Verkle 树 SSVT**（内节点含双向量承诺 $V,W$）建密文树。

**（3）区块链承担什么**（三重角色）：
- **随机源**：SC1 取链上最近 $t$ 个区块哈希 $\{B_1,\dots,B_t\}$ 生成 $\theta_1,\theta_2$ 与挑战块数 $\lambda$；
- **存证**：挑战 $\mathrm{Chal}$、审计辅助信息 $\varkappa$、去重块数证据 VI、审计日志 $\log=\{h_3(\mathrm{Tag}),VI,\mathrm{Proof},\mathrm{Result}_1\}$；
- **代替 TPA 验证**：SC2 执行
  $$e(\Theta,g)=e\big(H(\varphi+\Pi)\cdot W^{\varphi},pk_0^{(id)}\big),\quad \Pi=\sum_i\mathrm{Tag}\cdot\delta_i\cdot\omega[\delta_i]\cdot h_3(c_{\delta_i})$$
  被去重的挑战块经 N 个代理**代理重签名**（CRT + 秘密多项式共享 + Lagrange 系数 $\xi_{0,t}=\prod_{j\ne t}j/(j-t)$ 聚合）。

**（4）反恶意去重（去重块数可验证）**：用可逆映射 $\Gamma$ 与可逆迭代 $\tau=\rho\circ\gamma$ 构造 $VI=\{\Lambda,\Upsilon,K\}$——$u=h_1(c'_{in}\|\theta_1\|\theta_2\|\mathrm{Tag}\|\mathrm{label})$，$\Upsilon_0=\Gamma(u)$ 迭代 $I$ 次得 $\Upsilon$，$\Lambda=h_1(\Gamma^{-1}(\Upsilon_I))$，阈值陷阱 $K=SH(\Upsilon_I,\mathrm{label}\|c'_{in})$。用户 Log Checking 校验三个等式，任一不成立即判定 **CSP 恶意删除了重复块**。

**（5）数据恢复**：$C_F'=C_F+C_F^T\cdot\mathbb M$ 恢复文件内重复块；再用计数 Bloom 过滤器 CBF 检索外部重复块的备份密文填充；用户用链上 $\varkappa$ 校验 $\sum_i h_3(c_i')=\sum_i h_3(c_i)$ 后解密。支持批量审计。

**（6）安全与实测**：半诚实用户/CSP/代理模型；**明确要求 CSP 不与代理或任何用户合谋**。Thm1 机密性（DL，含抗 BFA）、Thm2 OP 保护、Thm3 存储正确性（Game0 归约 CDH、Game1 归约 DL）。环境 Java + JPBC、Hyperledger Fabric v2.4.1（**不需要 gas**）。SC2 验证仅 $2T_e+2T_{Mul}+2T_{exp}+T_H$，**不随数据块/文件数增长**，明显低于 BASD/ETDA/ALDAD；用户后续存储 $3|Z_p|+(n-c_{in})l$ 呈**负增长**。

### 3.4.2 Zhang Qingyang：确定性用于去重、随机化用于公开

核心思路一句话：**去重判定用确定性标签，对外公开用随机化标签**。四实体：KGC（可信）、用户、CSP、区块链（合约审计 + 押金托管/罚没），**无 TPA**。

**（1）认证标签去重（如何共存）**：
- 去重判定用**确定性文件标签** $\mathrm{tag}_{t,f}=g_1^{K_C}$，$K_C=H_2(F)$ 是收敛/消息锁定密钥；
- 对链/他人公开的是**随机化文件标签** $\zeta_{t,f}=g_1^{K_C\cdot r_t}$（$r_t$ 独立随机），同文件不同用户的 $\zeta$ 与 $\mathbb G_1$ 中随机元素不可区分；
- **是否用 MLE**：用了收敛密钥 $K_C$，但**没有用它直接加密数据**（避免低熵暴破）——数据加密密钥 $k_l$ 是**随机**选取的，收敛密钥只做掩码 $K_l=k_l\oplus K_C$、$c=\mathrm{Enc}(k_l,F)$；
- 标签签名密钥 $\epsilon=H_3(k_l)$，认证标签
  $$\tau_i=\big[H_4(c_i\|i)\cdot\chi^{\sum_{j=1}^{s}c_{i,j}}\big]^{H_3(k_l)}$$
  真拥有者都能恢复 $k_l=K_l\oplus K_C$，故生成**完全相同**的标签，CSP 只存一份 → **标签去重**。

**（2）密钥管理用 IBBE 而非密钥服务器**：用 Delerablée 的恒定密文广播加密把 $K_C$ 加密给"拥有该文件的用户集合 $s_F$"，$K_{IBBE}=v^{k_F}=e(g_2,h)^{k_F}$。用户只存自己私钥 + 文件标签，**不需要密钥服务器、也不需要与其交互**。后续上传者加入时做**用户集合的增量广播加密头更新**（$C_{F_2}^{(new)}=C_F^{k_F}$，验证 $e(C_{F_2}^{(new)},h)=e(C_{F_2},h^{\gamma+H_1(ID_B)})$）。

**（3）审计证明随机化**：合约从链上取不可伪造随机源 $r_3=H_1(t\|\mathrm{num}(t))$、$r_4=H_1(t\|\mathrm{nonce}(t))$，CSP 计算
$$\hat\Psi=\Big(\prod_{i=1}^{l_2}\tau_{a_i}^{b_i}\Big)^{s_t\cdot x_t},\quad \hat\Gamma=\Big(\prod_{i=1}^{l_2}H_4(c_{a_i}\|a_i)^{b_i}\Big)^{x_t}$$
合约验证 $e(\hat\Gamma\cdot\chi^{\hat\vartheta},pk_{t,f})=e(\hat\Psi,g_1)$。**证明乘入了用户随机审计密钥 $x_t,s_t$，故不同用户的证明互不相同**，公开在链上也无法判断两人拥有同一文件。合约内还有**押金经济机制**：用户与 CSP 各交押金，审计成功则用户押金作审计费付给矿工，失败则没收 CSP 押金。

**（4）安全与实测**：KGC 可信、**无 TPA**、**额外假设 CSP 不与任何用户合谋**；设计目标明确写"**除 CSP 之外的实体**无法确定哪些用户拥有相同文件"。Thm1 机密性 + OP、Thm2 标签去重、Thm3 DL 下 CSP 无法解析 $\epsilon=H_3(k_l)$。**密钥生成阶段零通信**（无密钥服务器交互）；**审计阶段用户计算量为 0**；后续上传 8 MB 约 **2.2 s**；上传阶段因无需在链上建索引表而 **0 gas**。

# 4. 主题二：可搜索查询与完整性审计的统一证明

> 论文：Mingyang Song、Miao Ying

## 4.1 研究背景

两篇针对的是同一个空白，但切入角度不同：

- **Mingyang Song（DSN 场景）**：去中心化存储网络（Sia、Filecoin、FileDAG、Storj、Swarm）中，完整性审计是 PoS 的基础；用户隐私要求外包前加密，因此"加密数据上的关键词搜索"成为必需。但**已有研究只分别做完整性审计或可验证可搜索加密，没有任何工作同时支持两者**。而 DSN 的**链上空间有限**，若两种功能各自独立生成证明与验证，链上存储与节点计算负担将翻倍，必须定制设计。
- **Miao Ying（大规模相似数据场景）**：传统 PDP 面向"精确数据完整性"、不支持近似匹配/语义相似；大规模相似数据集（数百万高维向量或带相似关系的互联文件）令现有 PDP 不适用。已有的关键词可搜索审计方案**依赖 PKI**（Gao [17]、Xue [19]），证书管理负担大，且其索引结构**无法抵抗"同关键词文件求和攻击"**。

## 4.2 研究现状

**（1）审计一侧（Song）**：PDP（同态线性认证标签）、PoR；云场景有基于同态哈希 + 记录表的动态更新、无证书签名的群组数据共享。DSN 审计：Sia 最早用 Merkle 树；**Storj 后改为第三方审计者——违背去中心化原则**；**Filecoin 因 Merkle 树审计存在轮数限制而改用 SNARK**；有工作用多项式承诺、子向量承诺（支持动态更新）、简洁数据结构产出紧凑审计日志——**但多为静态 PoS，用户初始设定后无法动态更新**。

**（2）可搜索加密一侧（Song）**：可验证 SE 有 UC-secure SSE（用 MAC 实现可验证性）、多关键词模糊搜索、符号树可验证模糊关键词搜索、多用户方案——**全部依赖可信第三方做公开验证**。区块链方向有把索引库发布到链上由用户自查或用合约强制可靠性，但**直接公开 keyword–file identifier 对无法保证文件插入阶段的前向安全**（有工作用精巧的混合索引设计解决）。面向 DSN 的唯一先行工作引了一组**不共谋服务器作为仲裁者**保存索引库并重新执行搜索来公正判定——**违反 DSN 去中心化本质**。

**（3）可搜索审计一侧（Miao）**：群签名匿名审计（群管理员掌握身份）、基于身份签名的多副本多云审计、多副本共享认证树 + 批量验证、可净化签名、无证书签名 + 盲化实现条件身份隐私、环签名匿名（**增加验证开销**）、代数签名加速批量审计。

**（4）去 TPA / 区块链方向（Miao，逐条列出不足）**：
- **挑战可被提前获知**：有方案用区块头公钥哈希或身份密码 + 区块链 nonce 作挑战种子，但**因区块链公开透明无法抵抗"挑战信息猜测攻击"**；
- **挑战被被挑战方控制**：有方案的**挑战信息由 CS 控制、无法保证随机性**；
- **依赖 TPA 在线**：多数方案仍要求 TPA 始终在线；
- **通信代价高**：有方案要求 CS 把全部密文交给审计者；
- **索引不能抗同关键词求和攻击**：关键词可搜索审计方案（含 Bloom 过滤器模糊匹配以隐藏审计频率的那一类）**均存在此弱点**；
- 表 I 逐条对比了 9 个方案（2015–2023）在认证类型、参与实体、优点与局限上的差异——结论是**没有任何一个同时做到：不依赖可信 TPA + 关键词可搜索 + 可追溯 + 抗挑战猜测**。

## 4.3 存在的问题

**Mingyang Song 的两个关键问题**：
1. **任何第三方服务器都不能引入 DSN**，否则与去中心化特性不相容（直接否定"仲裁者服务器"路线）；
2. 所有数据存储与删除事件必须永久上链以维持生态，而**链上空间有限**，必须用最小开销同时支持"可验证搜索"与"完整性审计"两种验证。

此外，DSN 的存储节点是个人设备，存在三类不诚实行为：①用背景知识推断其存储文件的内容与关键词；②硬件故障导致数据丢失后**伪造完整性证明、冒领存储费**；③搜索涉及已丢失文件时**返回错误结果并附伪造证明**（少返回文件或复用旧结果）。

**Miao Ying 的三个挑战**：
1. **可搜索审计的诚实执行问题**——搜索陷门只含不确定信息（如文件编号），CS 很可能只用部分匹配文件而非全部参与审计；
2. **无 TPA 的审计可信性问题**——验证任务由被挑战方 CS 执行，如何保证其诚实并给出可信结果；
3. **争议解决的公平性问题**——数据丢失但 CS 未在链上正确上报，或数据完好而 DO 讹诈索赔，需要公正裁判。

## 4.4 解决方式

### 4.4.1 Mingyang Song：关键词关联标签 + 一次配对验证

八元组算法 (Setup, KeyGen, Insert, Delete, Search, Proof, Verify.Search, Verify.Audit)；三实体（客户端、存储节点、区块链）；**证明由其它存储节点验证（排除生成者），不引入可信第三方**。原语为**合数阶双线性配对**、三个哈希、PRF、AES-256，安全性归约到 **CDH**。

**（1）统一证明的核心——关键词关联标签 kt**：首个状态时
$$kt^{(w_i)}=\big[H_2(ID_F)\cdot H_2(st_d\|T_i)\big]^{sk}$$
后续状态时
$$kt^{(w_i)}=\Big[H_2(ID_F)\cdot\frac{H_2(st_d\|T_i)}{H_2(st_{d-1}\|T_i)}\Big]^{sk}$$
**比值形式使同一关键词全部文件的 kt 连乘后中间状态逐项约掉**，只剩 $\prod H_2(ID_F)$ 与最新状态项 $H_2(st_d\|T)$——这正是"一次配对同时验证标识集合与文件完整"的关键；把文件标识与搜索 token 一起签入 kt，还可防止存储节点用其它关键词的文件替换搜索结果。

**（2）一次验证（式 8、9）**：验证节点计算
$$\zeta_1=\prod_{ID_{F_\alpha}\in Res}\prod_{i=1}^{n}H_2(ID_{F_\alpha}\|i)^{\pi(\theta\|ID_{F_\alpha},i)},\quad \zeta_2=\prod_{ID_{F_\alpha}\in Res}H_2(ID_{F_\alpha}),\quad \zeta_3=\prod_{ID_{F_\alpha}\in Res}\varphi_\alpha\cdot\varphi,\quad \rho=\sum\psi_\alpha$$
$$e(\zeta_3,g)\overset{?}{=}e\big(\zeta_1\cdot\zeta_2\cdot H_2(st_d\|T)\cdot\mu^{\rho},\ pk\big)$$
该式成立即**同时**表明"搜索结果 Res 正确（不多、不少、不被替换）"与"所有被搜索文件完好"。

**（3）前向安全靠状态指针链**：每次插入客户端**选新状态 $st_d$** 并保持隐藏，节点即使拿到过去的 $T$ 与全部旧状态也无法关联；$\bar T_i=H_2(T_i\|st_d)$；$ptr^{(d-1)}=\mathrm{SE.Enc}(H_3(st_d),st_{d-1})$，搜索时沿指针逐级解密回溯。

**（4）删除**：客户端算 $del=H_2(ID_F)^{sk}$ 发送 $(ID_F,del)$；节点把每个索引项的 $kt$ 更新为 $kt/del$ 并把文件标记 invalid，但**保留 kt 与指针**以维持同关键词其它文件仍可搜索。

**（5）实测**：C++ + OpenSSL/PBC/GMP；Enron 数据集派生 DB1（4,108 文件 / 8.24 MB）、DB2（12,035 文件 / 25.83 MB）、DB3（55,064 文件 / 127.62 MB）。因无同类方案，自行组合两个基线（可验证可搜索加密 + Merkle 树审计 / 可验证可搜索加密 + 多项式承诺审计）。结论：外包阶段计算与通信均低于基线、gas 显著更低；搜索与审计阶段**存储节点时间与验证时间显著更低、链上 gas 显著更低**；客户端时间略高于基线（因其在查询时才生成 search token 以增强关键词安全性）。

### 4.4.2 Miao Ying：索引嵌入认证器 + 仲裁者可重放复核

三实体（CS、DO、BC），**无 TPA**，引入额外仲裁者角色。原语为无证书签名、PRP/PRF、双线性配对。

**（1）相似数据如何组织**：$v$ 个文件、每文件切 $n$ 块；对 $m$ 个关键词各生成长度 $v$ 的**二进制索引向量** $v_{w_k}$（例：10 文件 × 7 关键词，$v_{w_1}=\{1,0,1,0,0,0,1,0,0,1\}$）。为保内容隐私，行地址用 PRP $\pi_o(w_k)$，向量用 PRF 掩码 $ev_{\pi_o(w_k)}=v_{w_k}\oplus f_l(\pi_o(w_k))$；并为匹配/审计生成
$$\Omega_{w_k,ij}=\big[H_3(ID_i\|j)^{-1}\times H_4(\pi_o(w_k)\|j)\big]^{x}$$
陷门 $T_{w'}=\{\pi_o(w'),f_l(\pi_o(w'))\}$ 与**匹配文件数 $n_{w'}$** 一并交给合约——$n_{w'}$ 把"应参与审计的文件数"固定下来，用于应对"CS 只用部分文件审计"。

**（2）可搜索与审计如何统一**：把关键词索引直接嵌入认证器与验证方程，使搜索结果集合 $S_{w'}$ 成为审计挑战的作用域。无证书认证器 $\sigma_{ij}=sk_{ID}\times[H_3(ID_i\|j)\times g^{\sum_k a_kb_{ijk}}]^{x}$（块先盲化 $b_{ij}=m_{ij}+H_2(sk_{ID}\|ID_i\|i\|j)$）。验证方程把"搜索匹配结果"与"数据完整性"绑定在同一配对等式中；因每个 $\Omega$ 内含 $H_3(ID_i\|j)^{-1}$ 且只对被匹配行求和，**攻击者把多个同关键词文件的索引项相加（same keyword files summation attack）无法伪造出可通过的证明**。

**（3）多任务挑战让 DO 离线**：合约约定 $Ag=\{t_{start},t_{end},\Delta t,c\}$，任务数 $\mathcal T=\lceil(t_{end}-t_{start})/(12\Delta t)\rceil$，第 $i$ 次挑战取自对应区块区间；CS 从链上区块取种子生成挑战。

**（4）仲裁如何设计**：合约记录索引、陷门、$n_{w'}$、挑战与证明。争议时**仲裁者依链上区块哈希自行重算** $\widetilde{k_{t1}}=H_2(1\|B_i)$、$\widetilde{k_{t2}}=H_2(2\|B_i)$、$\widetilde{j_t}$、$\widetilde{v_{ij_t}}$，独立复核验证方程：成立 ⇒ CS 诚实；不成立 ⇒ 数据已丢失，CS 须赔偿。透明性由 Thm4 保证（索引/陷门/挑战/证明/结果全部上链），仲裁者可完整重放。

**（5）实测**：Java + PBC，Windows 10 / i7 2.5 GHz / 8 GB。索引生成在块段数 500 时本方案 **13.683 s** vs [17] 23.134 s、[19] 22.969 s（**降约 40%**）；认证器生成在块数 4500 时 138.798 s vs [39] 146.338 s（降约 5%）；**证明生成因抗同关键词求和攻击而高于 [17]**（c=300、$\xi=60$、$s=3000$ 时 160.662 s）。合约部署约 1,237,740 gwei，四函数中 **addProof 最贵**。

> **必须注意**：Miao 的审计闭环存在"**自证**"问题——挑战由 CS 自己从区块哈希推导、证明也由 CS 生成、并由 CS 调用合约内 SelfVerify 自行判定 true/false 后上链，防线主要靠区块链不可篡改与仲裁者事后复核，而非"挑战方—证明方分离"的密码学可靠性。此外该文的"相似数据"实为**关键词共现**，并非向量相似度。

# 5. 主题三：去中心化存储与认证数据结构的理论基础

> 论文：Shi Elaine、Bonneau Joseph（MMR）

## 5.1 研究背景

这两篇回答的是"**这个方向的天花板在哪里**"，而不是"再造一个方案"。

**（1）去中心化归档的动机（Shi）**：
- 今天运行以太坊 archival node 备份历史交易日志需 **2TB–12TB** 且持续增长；而共识参与者只需维护最新状态（今天仅 **100–200 GB**）即可正常工作，因此**共识奖励本身不足以激励节点归档完整历史日志**；
- 其它动机：Internet archive（数百 PB）、Wikipedia（含全部历史与媒体 10+ TB）；
- 三条"梦想性质"（desiderata）：① **无许可、低门槛**（家用电脑闲置磁盘即可参与，$n\gg S$，数据库增长时节点无需新增磁盘）；② **近似最优可恢复性**（任意 $\mu$ 个通过审计的节点总空间 $\ge(1+\varepsilon)n$ 就能完整重建）；③ **复制安全**（要拿 $\alpha$ 倍公平奖励就必须承诺 $(\alpha-\varepsilon)S$ 空间，防止大空间节点只存一份数据冒充任意多假名领无界奖励）。

**（2）累加器见证更新的可用性瓶颈（Bonneau）**：
- 需要维护对只增不减集合的密码学承诺（已注册公钥集合、已签发 x.509 证书集合、链上全部交易）；
- 但大多数已知累加器（Merkle 树、RSA 累加器、双线性累加器）**每加入一个新元素就要改变所有现有元素的 witness**（每元素 $O(n)$、总计 $O(n^2)$）；
- 若每个持有元素的用户都必须在每次更新时取回新 witness，**更新频率直接决定可用性**；若每个元素的 witness 只变常数次，用户可在这之后**下线**；
- 已有若干工作为需要低更新频率的应用提出定制构造，但都"重新发明"了同一数据结构——**Merkle Mountain Range（MMR）**：Merkle 树列表，新元素加入最小的树，出现两棵同大小完整树时合并；元素 witness 只在其树被合并时更新，得到 $\Theta(\lambda\log n)$ 的承诺与累积 $n$ 个元素共 $\Theta(n\log n)$ 次 witness 变化。

## 5.2 研究现状

**（1）既有抽象为何不足以解决去中心化归档（Shi 的核心判断）**：PoR / DAS / PoRep / VID **都不足以解决 iDDA**，因为它们至少隐含以下假设之一：①节点被审计存储整个数据库/整块；②对每一块单独跑一个实例；③需要阈值比例诚实玩家；④数据库静态。

| 抽象 | 具体不足 |
|---|---|
| **PoR** | 假设被审计方存储**整个**数据库（云场景）；**不提供复制安全** |
| **DAS** | 源于区块链轻客户端，隐含对每个出块单独跑一个实例 ⇒ **每节点空间与数据库规模线性**，违反低门槛；同样无复制安全 |
| **VID** | 依赖**阈值诚实多数**，不适合无许可环境（敌手可造任意多假名）；同样线性空间 |
| **PoRep** | 通常假定静态数据库、节点可存整个数据库；对未编码数据不保证通过审计时可提取全部数据 |
| **多项式承诺** | 可用冗余极大的多项式承诺，但发布者必须在线计算 opening proof，非批处理下计算量至少与数据库大小线性 |

**"每块一实例"为何不满足要求**：要么几乎所有节点都要存每块的片段 ⇒ 每节点存储随数据集线性；要么只有一部分节点负责某块 ⇒ 若这些节点全被腐化则易受**选择性审查攻击**；即使 $\mu$ 个节点通过审计且名义总空间超过数据大小，也**可能因身份被敌手选择而无人负责某一块**，导致无法恢复。

**（2）已有下界为何不适用于 append-only（Bonneau）**：已有累加器下界（Camacho & Hevia 的信息论下界、Christ & Bonneau 的 $\Omega(n/\log n)$）**只适用于支持删除的数据结构，并在证明中使用了删除能力**，恰在 append-only 情形失效；且它们只说明 $\Omega(n/\log n)$ 个元素**至少变一次**，不能说明多数元素会**变化多次**（后者才有"用户能否下线"的实践含义）。

**（3）MMR 的再发现史（Bonneau）**：Todd 2013 年提出并命名 MMR（为提交比特币全部区块）；Reyzin–Yakoubov 2016 独立发现（分布式 PKI）；Garg 等 2018 再次发现（RBE）；Crosby–Wallach 2009 的 Merkle History Trees 与 Google Transparency 2022 的 compact ranges 类似。应用包括 OpenTimestamps、FlyClient（已被 Grin、Minima、Nervos、Neptune、Zcash 采用）、Axiom / Herodotus / Picasso 的链上紧凑包含证明、DataTrails / Witness 的数据时间戳，以及 IoT 区块链中的 k 叉推广。

## 5.3 存在的问题

**（1）Shi 明确列出的四个技术障碍**：
1. **朴素做法开销不可接受**：每次更新重跑静态方案，发布者开销 $\tilde O(BN)$、每节点开销 $O(BS)$。
2. **层次数据结构不能黑盒套用**，原因有二：
   - **安全定义缺乏组合性**——$\varepsilon$-best-recoverability 含隐式"记账"要求，各层各自满足该性质**不代表其并集在全球意义上满足**（各层达到匹配所需的节点数 $\mu$ 可能不同）；
   - **底层密码学缺乏组合性**——需要 PoRep 具备某种"自适应顺序可组合性"，而 Pietrzak 只在 standalone、诚实编码者情形下证明；其 decoder 在 preparation stage 无法回答 $H(\varphi_0^{DB},\cdot)$ 的查询，故证明策略在组合场景失效。
3. **空间分配的两难**：均匀采样率 $p=S/n$ ⇒ 小层仅 $\Theta(S/n)$ 比例身份负责，敌手用**拒绝采样**只挑未命中该层的身份即可整体抹掉它；每层相同块数 ⇒ 小层冗余过大，恢复要求总空间 $\Theta(n\log n)$ 而非 $(1+\varepsilon)n$。
4. **必须去除 SNARK**：用 SNARK 证明 shard digest 正确性开销大，且该 SNARK 需对含随机预言机查询的计算做证明，而 ROM 中的 relativized succinct arguments 已被证明不存在。

**（2）Bonneau 要回答的问题**：**append-only 累加器的最优见证更新频率是多少？** 即是否存在构造能同时做到亚线性全局存储与低见证更新频率，以及 MMR 是否最优。

构造侧的取舍困境（原文 Table 1）：

| 构造 | 累加器大小 | 总 witness 更新数 |
|---|---|---|
| 朴素数据库 | $\Theta(n)$ | 0 |
| 经典累加器 | $\Theta(1)$ | $O(n^2)$ |
| $k$-buffering + 累加器 | $\Theta(k)$ | $O(n^2/k)$ |
| $k$-bucketed 累加器 | $\Theta(n/k)$ | $O(kn)$ |
| buffering + bucketing | $\Theta(n/k+k)$ | $O(n)$ |
| **$k$ 叉 MMR** | $O(k\log_k n)$ | $O(n\log_k n)$ |
| **$(\log n)$ 叉 MMR** | $O(\log^2 n)$ | $O(n\log n/\log\log n)$ |

前五种都受**线性权衡**限制；$k$ 叉 MMR 打破了该权衡，但此前**没有理论解释"为什么不能再好"**。

## 5.4 解决方式

### 5.4.1 Shi Elaine：iDDA 的新定义 + 层次化构造

**（1）新定义（本文最重要的贡献）**：语法上是 (setup, Init, Join, Update, Audit)，参与方为 publisher、存储节点集合、auditor；**正确性**要求即使存在腐化节点，诚实节点也总以概率 1 通过审计。

- **Definition 1（$\varepsilon$-best-possible-recoverability）**：存在压缩算法 $C$、提取器 $E$ 与准多项式函数 $q(\cdot)$，$C$ 的输出长度 $\le\max(B\cdot(n-(1-\varepsilon)S\mu),0)$ bits，且
  $$\Pr\big[(DB^{\mathrm{ext}}\neq DB^*)\wedge(b=1)\big]\le\mathsf{negl}(\lambda)$$
  直觉：若 $\mu\le n/((1-\varepsilon)S)$ 个节点通过审计并领酬，则它必须知道至少 $(1-\varepsilon)\mu S$ 块有用信息；**特例**：当 $\mu S\ge n/(1-\varepsilon)$ 时定义强制 $C$ 输出为空，即必须能提取整个数据库。
- **Definition 2（$\varepsilon$-replication-security）**：若 $A_1$ 输出状态空间 $\le\mu\alpha BS$，则 $A$ 通过随机抽取的单个身份审计的概率 $\le\alpha-\varepsilon$。直觉：**想拿 $\alpha$ 倍公平奖励就必须消耗约 $\alpha$ 倍空间，即使原始数据本身可压缩**；随机化挑战时点可防"审计前临时重建、审计后删除"。该性质**蕴含 $\varepsilon$-Nash 均衡**。

**（2）构造的三项关键技巧**：

- **解决空间分配：混合空间分配**。$\gamma(n)=S/n$，下界 $s_{\mathrm{lb}}(n)=\gamma\cdot 2^L/(\omega(1)\log n)$，每层采样块数 $s_\ell(n)=\lceil\max(\gamma\cdot 2^\ell,s_{\mathrm{lb}})\rceil$。即最大的 $\lfloor\log_2(\log n\cdot\omega(1))\rfloor$ 层为 **large levels**（均匀采样密度），其余为 **small levels**（每层相同块数）。Fact 6.1：small levels 只占 $n\cdot o(1)$ 块、节点为此只花 $S\cdot o(1)$；large levels 占 $n(1-o(1))$ 块。这样既有更高的小层采样率防选择性审查，又把小层浪费限制在 $S\cdot o(1)$（可被 $\varepsilon$ 松弛吸收）。
- **解决组合性（关键技巧）**：每次某层重建时，要求存储节点用**所有层摘要的并 $(\varphi_0,\dots,\varphi_L)$ 加节点 id** 作为随机预言机种子重算所有层的 replication code（代价 $SB$/update），从而**在不要求 PoRep 具备组合性的前提下完成安全证明**；随后再用优化把代价摊销降回 $\tilde O(1)\cdot B$。
- **去除 SNARK**：审计分两阶段——**离线挑战**由节点用 Fiat–Shamir 自采样、只保证 $\varphi^{\mathrm{shard}}$ 近似正确；**在线挑战**由挑战者从数据相关位置随机采样 $\kappa$ 个并验证向量承诺开证明。

**（3）主定理与下界**：
- **Theorem 1.1（主定理）**：ROM 下存在 iDDA 方案同时满足两个定义，成本摊销于 $N-n_0$ 次更新——每节点下载带宽 $B\cdot O(1+S\log\log\lambda/N)$、每节点计算 $O(B\log N)\cdot\omega(1)$、publisher 计算 $B\cdot e^{O(1)/\varepsilon}\log N$、audit 成本 $B\log\lambda\log N\cdot\omega(1)$、节点空间 $\le BS(1+o(1))$。
- **近最优性论证**：若 1% 的节点在更新时什么都不做，则它们对新块毫无信息；敌手选择性腐化其余 99% 即可让该块被擦除，即使这 1% 节点的合计存储已足以存下整个数据集——因此**每节点每次更新至少常数开销是必然的**。
- **Theorem 8.12（空间下界）**：$|st^{\mathcal A}|\ge(1-o(1))\cdot B\cdot(\beta-5\zeta')\cdot\mu S$。

### 5.4.2 Bonneau（MMR）：压缩论证证明下界并证明 MMR 最优

**（1）证明方法：压缩论证（compression argument）**——从第一性原理出发，**无条件（信息论）成立，仅用简洁性 + soundness**，不依赖任何计算假设：

- **Lemma 1（One-shot witness changes）**：累加器简洁、$|U|=\Omega(\mathrm{poly}\,\lambda)$、任意常数 $c\in(0,1)$ ⇒ "one-shot 更新少于 $c|S|$"的概率可忽略。证明用 Alice/Bob 通信游戏：Alice 把秘密集合 $S$ 编码成位向量 $v$（$u_i\notin S$ 记 0；$u_i\in S$ 但其 witness 相对最终累加器不验证记 1），只需发 $\le n-0.1(1-c)n+\mathrm{polylog}(\lambda)=n-\Omega(n)$ bits；但由 Shannon 编码定理，传达 $U^*$ 的随机元素需 $n-\log(2p(\lambda))$ bits，矛盾。
- **Lemma 2（Multi-shot witness changes）**：若 $d=\omega(\mathrm{Size}(\pi,\lambda,m_0+dm))$，则对任意常数 $c<1$，至少 $c$ 比例的 witness 在 $A_{m_0+dm}$ 下不再成立（压倒性概率）。
- **Theorem 1（主下界）**：任意常数 $\alpha\ge0$，充分大 $n$，
  $$\Pr_{\substack{\mathsf{pp}\leftarrow\mathsf{Setup}(1^\lambda,\mathsf{ord})\\ X\subseteq\mathcal U:|X|=n}}\big[\text{至少发生 }\alpha n\text{ 次 witness 更新}\big]\ge1-\mathsf{negl}(\lambda)$$
  证明把有序 $X$ 切成大小 $d^i$ 的连续段构造层次结构，对每层用 Lemma 2（$c=0.99$），各层所取子序列**互不相交、不重复计数**，$h$ 层合计 $\ge0.99hn=\alpha n$。因 $\alpha$ 可任取常数，即 **$\omega(n)$ 总更新、平均每元素 $\omega(1)$ 次**。
- **Corollary 2（更强累加器的更强下界）**：若 $\Pi$ 适应 $2^{\lambda^\beta}$ 规模集合，则
  $$\Pr\Big[\text{至少 }\tfrac{c\beta n\log n}{\alpha\log\log n}\text{ 次 witness 更新}\Big]\ge1-\mathsf{negl}(\lambda)$$

**（2）对比结构：k 叉 MMR**：维护一组存放不相交子序列的完整 $k$ 叉 Merkle 树；每种大小的树数 = $n$ 的 $k$ 进制表示对应位；累加器 = 各 Merkle 根按树大小递减排列；加入元素时先建单元素树，然后迭代地每凑齐 $k$ 棵同大小树就合并。**Theorem 2**：$k$ 叉 MMR 简洁且累积 $n$ 个元素需 $O(n\log_k n)$ 次 witness 更新（Reyzin–Yakoubov 证明过 $k=2$ 的特例）。**Corollary 3**：$k=\log^c n$ 的 $k$ 叉 MMR 需 $O(\log^{c+1}n)$ 存储与 $O(n\log n/(c\log\log n))$ 次更新。

**（3）最优性结论**：对可累积至多 $2^{\lambda^\beta}$ 规模集合的 $k$ 叉 MMR，Corollary 2 的下界 $\tfrac{c\beta n\log n}{\alpha\log\log n}$ 与 $\log n$ 叉 MMR 的上界 $O(n\log n/\log\log n)$ **渐近匹配**，故 **MMR 在大集合情形下关于 witness 更新次数"本质最优"**。

**（4）安全模型**：**无信任（trustless）设定**——明确与那类依赖秘密状态、管理者可破坏 soundness 的"静态/免更新"构造相对立。前提是累加器的 soundness 与 **succinctness**（polylog 累加器值）；对确定性构造成立，对随机化构造通过预先约定随机币也成立；下界以"**随机选取**被累积集合 + 压倒性概率"陈述，而非最坏情况。

# 6. 主题四：去重与近重复检测技术的跨域应用

> 论文：Niemi Tapio、Sensintaffar Alex、Wang Yuchun

## 6.1 研究背景

这三篇都不是密码学方案，而是**把去重/近重复检测当作领域工具**。它们的"敌人"不是不可信服务器，而是各自领域的现实约束：

- **Niemi（癌症登记）**：瑞士自 2020 年起强制要求所有机构与执业医师上报癌症病例，Vaud 癌症登记处（地区登记自 1970 年代运营）文档量剧增；医疗文档含大量重复/冗余文本，主因是**人工复制文本或系统自动生成的更新文档**；同一份文档常由不同发送方（诊所、公立/私立医院、病理实验室）以不同格式发送。不处理的后果是**统计计数被重复计入、AI/ML 模型性能下降、存储需求增加、编码员工作量上升**。检测的规模难点：Data Set 3 有 224,398 篇文档，字符串相似度全量两两比较需 **超过 210 亿对**，不可行。
- **Sensintaffar（DNA 存储）**：IDC 预测 2029 年全球数字数据达 **291 ZB**，其中图像占比极大且需保留多个分辨率的多个版本；传统存储密度增长跟不上数据生成速度、寿命最多约 30 年。DNA 存储理论密度约 **455 EB/gram**、可保存数百年，但**极易出错**（插入/删除/替换、同聚物与 GC 含量违规），且存在**误差传播**：实验显示在第 **2444** 个核苷酸注入一个插入错误后，**只有最前面若干行能完整恢复，其余图像完全崩坏**。有利条件是 DNA 链之间存在**天然物理隔离**——只要元数据正确，误差传播就被限制在单条链内，因此**缩短有效链长**即可缓解。
- **Wang Yuchun（遥感）**：多卫星、多角度、多时相观测导致同一地表区域被反复拍摄——不同卫星在相近时间窗从不同视角拍摄造成**空间冗余**，同一区域被多时间隔观测造成**时相冗余**。冗余不仅增加存储与传输成本，还**可能掩盖关键特征、影响学习模型的训练效率与精度**，并与绿色计算目标矛盾。关键约束是**低轨（LEO）卫星网络的带宽与实时性**：多模态去重与云端去重方法依赖高带宽与充足算力，难以满足星上/实时需求。

## 6.2 研究现状

**（1）Niemi 梳理的方法谱系**：
- **传统哈希指纹**：文档完全相同则指纹相同，对完全重复高效；但**微小差异导致指纹完全不同，无法估计相似度**，不能做近重复检测。
- **LSH 方法**：MinHash（Broder 2000）与 Simhash（Charikar 2002）源于网页近重复检测，在数十亿文档规模下仍有足够性能；LSH 指纹允许在**不访问原文**的情况下计算文档差异。
- **两两相似度比对**：Levenshtein 距离、Jaccard 相似度、Smith-Waterman（S-W）文本比对（原为生物基因序列设计，后被用于文本相似部分查找）。
- **领域缺口**：近重复文档检测研究集中在 IT 领域；医学领域**据作者所知只有一项**研究——Gabriel 等（2018）基于 MinHash 的近重复临床笔记检测，其吞吐仅 **11.7 docs/sec**。
- **通用方法不适用的原因（4 条需求）**：新增文档的近重复检测需高效；指纹须能**不依赖全局词表**独立计算；须对小细节（专有名词、编码、数字）敏感；须能为读者高亮差异。

**（2）Sensintaffar 梳理的 DNA 编码与纠错**：
- **编码方案**：简单二进制映射（A,C→1 / T,G→0，靠交替核苷酸避免同聚物）；**base-4 编码**（A→00, C→01, T→10, G→11，核苷酸用量减半，但不处理同聚物与 GC 含量）；生物约束感知方案如 **GF(47)**、**旋转码（rotation codes）**、Wei 等的映射以减少引物—载荷冲突、Brunmayr 等的 motif 生成工具。
- **误差传播缓解**：**IMG-DNA** 引入 barrier 阻止传播，但**降低了容量**；Lin 等提出**非均衡纠错码**降低 ECC 开销。
- **不足**：随着生物技术发展、DNA 链长将增加，基于"加 ECC / 加 barrier"的方案会**越来越低效**（以容量换鲁棒性）；而 JPEG/PNG 等图像压缩方案虽核苷酸用量少，但**核苷酸之间存在强依赖，对 DNA 误差传播极其敏感**。

**（3）Wang Yuchun 梳理的图像去重谱系**：早期 CBIR/手工特征（HOG、LBP）**在多尺度与复杂结构上表达能力受限**；CNN 哈希学习与 ViT 语义嵌入仍面临**图像模糊与不确定性**；DFHN 结合模糊逻辑与 DNN；Haar 小波 + CNN 说明"针对特定图像差异设计特征提取策略"的潜力；多模态检索**依赖高带宽与大量计算，难以满足 LEO 实时要求**；Transformer 系（含 CrossHash 跨尺度深度哈希）**主要聚焦分类与分割，在带宽受限的去重场景中应用不足**；传统路线 pHash/SIFT 在噪声干扰下精度低，Siamese 网络与 triplet loss 亦被试用；云端深度哈希有 SwinFpnHashCLR（多尺度哈希 + Hamming 距离 + Otsu）；PXDedup 基于 patch 但**标准 CPU 上吞吐低**；安全近重复去重（Li 等）面向车联网取证图像用**云-雾协同 + 加密**。**归纳不足**：pHash/SIFT 噪声下精度低；CNN 受**局部感受野**限制难捕捉长程依赖；ViT 计算复杂度高不适用于 LEO；多模态方法难以适应异构遥感场景；**缺乏面向资源受限环境的系统性方案**。

## 6.3 存在的问题

| 论文 | 具体失效模式 |
|---|---|
| **Niemi** | ①**文件级指纹不足**——相同文本内容在 PDF 中可有不同表达（创建日期、生成软件、字体等元数据不同）；②**Simhash 单独使用误报高、召回不满**——模拟集 specificity 仅 0.70、FP=447、PPV=0.71；人工核验集 sensitivity 0.92、FN=138（假阴性率 8%）；③**纯句法方法无法处理"微小但语义关键"的差异**——标准表单中姓名/社保号略有不同，6% 的近重复候选被人工判为"非近重复"；④**自动方法无法判断哪一份是"正确"版本**，必须人工裁决 |
| **Sensintaffar** | 图像存入 DNA 后，**单个核苷酸的插入/删除/替换经误差传播使整条链及其后续像素块崩溃**；JPEG/PNG 压缩码流的强核苷酸依赖使问题更致命；ECC/barrier 类方案在链长增长趋势下效率下降且牺牲容量 |
| **Wang Yuchun** | ①**复杂成像因素**（云覆盖、光照变化、地表覆盖异质性）使相似性判断困难，且不同区域的相似图像可能因研究目的需要保留；②**分类与去重的耦合失效**——即使整体分类准确率很高，某些高度相似图像仍可能因特征落在**类中心附近的边界区域**而被判为不同类别；③**两两比较代价**——全局 CNN 去重与哈希去重在同一数据上均需 **28,876,200 次比较**，耗时 122.12 s / 50.22 s |

## 6.4 解决方式

### 6.4.1 Niemi Tapio：三阶段流水线（哈希 → Simhash → Smith-Waterman）

- **预处理**：PDF 文本抽取 + 正则预处理（去多余空格、换行、条码、非字母数字特殊字符）；**刻意不使用 NLP**，因为需要保留所有句法差异。
- **三阶段（Appendix C 的 9 步算法）**：① 抽取与预处理文本，用传统哈希指纹检测**完全重复**；② 对每篇文档计算 **Simhash** 指纹（切 shingle → `hashlib.md5` 得 64 位哈希 → 逐位"1 的个数 − 0 的个数" → 负位取 0、非负位取 1），用索引结构找出**仅差 $k$ 位**的指纹作为近重复候选；③ **只对候选对**计算 **Smith-Waterman 相似度**并用阈值判定（把误报压到近零）。
- **参数（具体值）**：Simhash $k=3$；shingle 宽度 **6 词**、重叠 **3**；S-W 阈值 $th=0.94$；Data Set 2 上为提升敏感度采用 Simhash 阈值 0.35。
- **归一化相似度定义**：$S_C(A,B)=\frac{A\cdot B}{\|A\|\|B\|}$；$S_{sim}(A,B)=1-\frac{\text{Simhash distance}(A,B)}{\max_{X,Y\in D}\text{Simhash distance}(X,Y)}$；$SWsim(A,B)=\frac{\#matches}{\#matches+\#mismatches}$。
- **输出目标**：不只是"存/不存"的二元决策，而是**可人工裁决的证据**——用 Python difflib 检测差异并在原始 PDF 中**并排高亮**显示给医学编码员；差异分 4 类（医疗数据 / 行政数据 / 无可见差异 / 非近重复）。
- **实测**：
  - Data Set 1（人工核验金标准）：3,042 对，含 **1,252 完全重复 + 398 近重复**；Data Set 2（模拟）；Data Set 3（生产，224,398 篇）。
  - **本文方法（Simhash + S-W）**：AUC **0.96**（Set 1）/ **0.86**（Set 2）；sensitivity 0.92 / 0.72，specificity **1.00 / 1.00**，PPV **1.00 / 1.00**，NPV 0.91 / 0.77。
  - 生产集：完全重复 **12,256 份 = 5.46%**；近重复候选 762 份 = 0.34%；S-W 阈值 0.94 过滤后 **540 份 = 0.24%**。
  - 人工评估 298 个近重复对：**医疗数据差异仅 6 对 = 2%**；行政数据 **83%**（患者级 21%、医生/诊所级 11%、其他如信件日期/页眉页脚/档案号 51%）；无可见差异 26 对 = 9%；判为非近重复 19 对 = **6%**。
  - 速度：约 225,000 份文档总耗时 **941 s = 228.2 docs/sec**，**远快于 Gabriel 等的 11.7 docs/sec**。
  - 结论：最多 **5.7%** 的文档存在一个或多个完全/近重复；据此推算**每年至少 4,400 份文档**可免于人工且易错的处理。方法已投入 Vaud 癌症登记处日常文档处理。

### 6.4.2 Sensintaffar（Pixel-DNA）：两级层次化近似去重

正文描述为**三个阶段**（图像编码 / 第一级去重 FLD / 第二级去重 SLD；摘要称 "four-phase"，**原文自身表述不一致**）。

- **阶段 1：图像编码**。图像切 **N×N 像素块**（默认 **N=5**）；用图像分割分别按**水平路径**与**垂直路径**遍历，选择使核苷酸总数最少的方向；块内每像素 24 bit → **12 nt**（base-4），3 色 × 25 像素 = 600 bit → **300 nt/链**。
- **阶段 2：第一级去重（FLD，链级）**。重复链被替换为指向首次出现索引的**指针链**；引入 **acceptable difference**（允许两条链有若干核苷酸不同仍判为重复）→ 使 FLD 变为**有损**。把连续重复的指针链合并为 **deduplication block**，并用**动态编码**压缩：新增 **multiplier、$size_i$、$size_p$** 三个各 1 nt 的数据点（base-4 编码），解码公式 $\mathrm{Len(StopIndex)}=(1+multiplier)\cdot size_i+1$、$\mathrm{Len(StrandPointer)}=(1+multiplier)\cdot size_p+1$。重复块可抽成 **combination group** 置于链列表开头，**未来可对其加过量 ECC 而只产生少量额外数据**。
- **阶段 3：第二级去重（SLD，链内 12 nt chunk 级）**。出现频率最高的 chunk 进入**查找表**；用 **recipe chunk**（1 nt 指令 + 数据）替换，指令取值 **A = Duplicate Chunk；C = Unique Chunk；T = Long Sequence of Duplicate Chunks；G = Long Sequence of Unique Chunks**，后两者各用 3 nt 表示数量。
- **实测**：Python 3.8.10；数据集为 Open Images Challenge 2019（约 **10,000 张 JPEG**）+ 2K/4K/8K PNG，整体约 **108,000 张图像、36.1 GB**；指标为 SSIM、PSNR、**核苷酸数量**；误差注入遵循湿实验的错误分布，错误率 0%–2%。
  - **Pixel-DNA 随错误率上升鲁棒性几乎不受影响**，且**错误率上升时容量反而提高**（错误产生重复核苷酸模式，提高去重比）；
  - **去重允许的差异数从 0 增到 4 时容量可提升约 34%**，同时 PSNR/SSIM 略微下降（引入恢复误差 vs 链长变短提升抗误差传播，两者相互抵消）；
  - 拆分贡献：**容量上 SLD 贡献最大**（减少每一条链的核苷酸数），**鲁棒性上 FLD 贡献最大**；
  - 错误影响：FLD/SLD 遇**插入/删除**错误时整条链及后续像素块都可能损坏；**FLD 遇替换错误最坏只损坏一个像素**；**SLD 对替换错误仍脆弱**（指令核苷酸或长度指示核苷酸被改动会导致整链丢失）；
  - **Pixel-DNA 叠加在 JPEG/PNG 上**容量略改善但鲁棒性不变——因 JPEG/PNG 在核苷酸间建立强依赖，作者**不采用**该组合。

### 6.4.3 Wang Yuchun：先分类、再类内去重

- **特征提取（轻量 ViT，1.8M 参数）**：图像划分为 patch（正文写 10×10、又说"a total of 484"，对应 224×224 输入），经卷积投影到 **768 维**；用**单层 Transformer 编码器**（**12 头自注意力 + 前馈网络**）；轻量化设计——**移除位置编码、移除 CLS token、用 GAP 聚合**；理由：遥感图像的全局语义主导分类性能，位置信息常冗余，GAP 天然提供平移不变性。
- **分类（兼任嵌入空间正则化）**：两层 MLP $768\to384\to19$；作者强调分类模块**不只用于标签预测，更重要的是引导 Transformer 学到结构良好的嵌入空间**——语义相似的图像聚在一起——这正是后续余弦相似度去重的前提。
- **去重**：特征归一化为单位范数，用余弦相似度 $\frac{x\cdot y}{\|x\|\|y\|}$，阈值 $\tau$（正文 **0.92**，但第四节实验又写 0.95，**存在表述不一致**）。**关键流程设计**：分类之后**在每个类别内部**做两两相似度计算——正是"先分类"把全局两两比较切成类内比较，从而削减比较次数。
- **实测**：
  - 数据集：**WHU-RS19**（19 类、1,005 张、600×600，约 50 张/类）、**UCMerced Land Use**（21 类、2,100 张、256×256，100 张/类）。
  - 特征提取速度（100 张 224×224）：本文 **0.458 s / 4.58 ms 每图**；ViT-B/16（86M 参数）0.933 s / 9.33 ms（**2.04×**）；LBP 5.892 s / 58.92 ms（**12.87×**）。
  - 分类：WHU-RS19 上 **98.36%**（B-CNN 82.83%、ResNeXt-50 83.27%、TAE-Net 88.04%）；UCMerced 上 Macro-F1 **97.27%**（ResNet-50 91.65%、Swin-B 91.62%）。
  - 去重（Table IV）：本文 **6.3880 s / 1,516,200 次比较 / 找到 2,577 个重复**；全局 CNN 去重 122.1222 s / 28,876,200 次；哈希去重 50.2196 s / 28,876,200 次。即**运行速度提升约 19.12 倍、比较次数减少 94.75%**；**去重率 85.2%**。

> **三篇与云安全去重的根本差别**：云安全去重（CE/MLE、DupLESS、PoW、加密近重复去重）以"不可信云 + 多用户互不信任"为前提，核心矛盾是"既要跨用户去重、又不能泄露内容"，等价性判据是**密码学标签的相等性**，因此**对近重复天然无能为力**（密文雪崩效应）。这三篇恰恰以近重复为主战场，必须在**明文/特征域**工作，判据分别是 Simhash + Smith-Waterman、允许差异的近似匹配、语义嵌入余弦相似度阈值，**全文没有加密、密钥派生、所有权证明或任何对抗性服务器假设**。

# 7. 主题五：大模型场景的数据完整性与加密

> 论文：Yan Binyuan

## 7.1 研究背景

大模型把数据完整性与隐私问题从"存储层"推到了"全生命周期"：

- LLM 在训练/推理全流程持续处理敏感用户数据，攻击面覆盖"收集—预处理—预训练—微调—推理"；
- 现实事件被用作动机：SOTA LLM 会**逐字复述训练数据**，GPT-4 级模型在 **1.5%** 的情形下输出 PII；ChatGPT 2023 年 3 月泄露事件暴露了 **1.2%** 付费用户的支付记录；医疗场景中模型反演攻击从微调临床 LLM 重构出 **25%** 的患者记录；金融聊天机器人在 **34%** 的情况下会被 prompt injection 套出机密情报。文章把 LLM 形容为"**数字海绵**"（digital sponges）；
- **现有防御碎片化**：差分隐私只缓解训练期泄露、**忽略推理威胁**；加密只保护推理数据；同态加密虽保隐私却带来难以承受的开销（非线性操作下延迟 >100ms、精度下降 >5%）；
- **关键空缺**：没有任何统一方案能同时做到"阻止训练阶段记忆 + 支持实时完整性校验 + 支持泄露事后取证"；
- **传统哈希失效**：标准哈希无法捕捉 LLM 数据流水线中的**语义操纵**（语义保持型改写会绕过哈希校验）。

## 7.2 研究现状

该文未设独立 Related Work 章节，梳理散见于引言与各节：

| 技术类别 | 具体不足 |
|---|---|
| **差分隐私** | 能缓解训练期泄露，但 "ignore inference threats"，完全不覆盖推理期威胁 |
| **加密 / 密码学数据共享**（RSA、ElGamal + 哈希） | 可保护推理数据，但**标准哈希对语义操纵失效** |
| **同态加密**（可信研究环境的披露控制） | 能保隐私，但处理非线性操作时引入 crippling latency（>100 ms）与 >5% 精度下降 |
| **区块链个人数据保护机制** | 不能解决完整性/语义校验与训练记忆问题 |

综合结论：现有方案 "fragmented and inadequate"，缺少统一框架。

## 7.3 存在的问题

1. **流水线的完整性漏洞缺可追溯定位手段**——训练数据投毒、推理数据注入两条路径缺乏阶段级的威胁定位；
2. **传统哈希对语义扰动不敏感**——缺少语义级、低开销、抗扰动的完整性与来源校验机制；
3. **推理期服务器可见明文输入/输出**——存在 prompt 窃取、未授权上下文日志、推理结果泄露风险，而已有 HE 方案延迟与精度不可接受；
4. **训练记忆导致的敏感数据泄露缺少"预防—检测—溯源"闭环**——DP 与审计日志各自孤立。

## 7.4 解决方式

原文自称基于 ChatGLM-3 的**四层整合安全框架**，含 SecureInfer 与 PrivacyShield 两个子系统：

**（1）风险建模层**：把数据流拆为 5 个阶段 $D_1$–$D_5$（收集/预处理/预训练/微调/推理）；用 **STRIDE** 聚焦 **Tampering 与 Repudiation**，用复合函数量化风险 $R_i=f(T_i,A_i)$（$T_i$ 为篡改成功概率、$A_i$ 为溯源不足带来的验证成本）；用 **Attack Tree** 建模两条攻击路径（训练数据投毒：Collection Injection → Preprocessing Tampering → Corpus Camouflage；推理数据注入：Prompt Hijacking → Context Interference → Output Pollution），对每个节点挂载可审计属性向量（数据变更哈希、操作来源、时间戳），构成可追溯威胁识别图 $T_{attack}=(N,E,\alpha)$。

**（2）语义完整性校验层**：$\nu=\mathrm{SBERT}(x)$ → $h=\mathrm{MinHash}(\nu)=\min_{i=1}^{k}\{\pi_i(\nu)\}$ → 全部训练样本摘要组织成 Merkle 树，根哈希锚定到**区块链或 TEE**；推理期对 prompt 与输出走同一套处理，用 **Jaccard 相似度** $\mathrm{sim}(h_{test},h_i)=\frac{|h_{test}\cap h_i|}{|h_{test}\cup h_i|}$ 超阈值判定语义偏移。宣称对语义保持型扰动鲁棒、$O(\log n)$ 验证、天然提供来源可追溯性。

**（3）端到端同态加密推理层（SecureInfer）**：基于 **CKKS**；客户端加密 $\tilde x=\mathrm{Enc}_{CKKS}(x)$，服务器用 **Chebyshev 多项式近似非线性激活** $\sigma(x)\approx\sum_{i=0}^{n}a_ix^i$ 支持同态矩阵乘与近似激活求值，**从不解密**、直接返回 $\tilde y$；优化两项——输入截断与嵌入缓存、基于 **ECDH** 协商 CKKS 内部对称密钥。

**（4）训练期隐私保护与审计层（PrivacyShield）**：用 Opacus 做 **DP-SGD**——逐样本梯度 L2 范数裁剪 $\hat g_i=\frac{g_i}{\max(1,\|g_i\|_2/C)}$，再注入 $\tilde g_i=\hat g_i+\mathcal N(0,\sigma^2C^2\mathbf I)$；日志记录取证元数据 $A=\{(x_i,t,\|\hat g_i\|,\mathrm{hash}(x_i))\}$；推理期用 Sentence-BERT 余弦相似度做**泄露检测**，超阈值则截断输出、标记并记录。三者构成"预防（DP 扰动）—检测（相似度拦截）—溯源（日志回溯）"闭环。

**（5）实测与必须注意的问题**：
- 平台：**LLaMA 2-13B**、4× A100 80GB、PyTorch 2.1、TenSEAL；数据为**自建合成数据集 100,000 条**。
- 语义哈希：语义扰动峰值 noise=0.5 时**精度 85%、召回 87%**；**每次验证延迟 <0.3 ms**。
- HE 推理：密文 **102 ms** vs 明文 **35 ms**（**2.9×**），精度下降 **2.4%**；梯度反演攻击成功率仅 4%（随机猜测 32%、embedding matching 28%）。
- DP + 审计：泄露率 **68% → 27%**（$\sigma=1.5$）；溯源成功率 训练 100% / 推理 94% / 验证 73%；误报率 <5%。
- **内部矛盾（务必留意）**：①对抗改写检测 **78%** 却称"一致超过 80% 阈值"；②溯源三者平均 **89%** 却称"平均 >90%"；③引言批评现有 HE"延迟 >100ms 不可接受"，而本文自测 **102ms**，几乎落在同一区间；④摘要称框架 "ChatGLM-3-based"，**实验却全部在 LLaMA 2-13B 上完成**。
- **证据强度**：密码学组件使用真实库（TenSEAL/CKKS、Opacus），但攻击为 TextAttack + 自研脚本的**仿真攻击**、数据为合成数据；**无重复实验次数、无方差/置信区间、无统计显著性检验**；**唯一对比基线是"明文推理"与"无 DP 保护"**，未与任何已有语义校验方案或 HE-LLM 推理系统横向对比。

# 9. 趋势判断与尚待填补的空白

## 9.1 四条已经清晰的趋势

1. **去重的粒度正在从文件级下沉到块级，并且开始往"标签也去重"走**。Liu 把去重做到块级并进一步做到**去重块数可验证**（用可逆迭代构造 $VI$，用户可判定 CSP 是否恶意删块）；Zhang 则解决了**认证标签本身冗余**的问题。二者合起来说明：去重 + 审计这条线已经从"能不能同时做"走到"怎么把两侧的冗余都消掉、并让消掉的过程可验证"。
2. **"确定性用于功能、随机化用于公开"成为隐私保护的标准范式**。Zhang 的 $(\mathrm{tag}_{t,f},\zeta_{t,f})$ 是最干净的实例：同一个 $K_C$ 派生出确定性标签供 CSP 去重、随机化标签供链上公开；审计证明同样乘入用户随机密钥 $x_t,s_t$。Song 则用状态指针链 + 每次插入新状态 $st_d$ 实现同类目标（前向安全）。
3. **理论侧开始给这个方向"划边界"**。Bonneau 用无条件信息论下界证明了 **MMR 本质最优**（$\omega(n)$ 下界对 $O(n\log n/\log\log n)$ 上界渐近匹配），终结了"能不能更好"的猜测；Shi 则指出 PoR/DAS/PoRep/VID **四类既有抽象都不足以刻画去中心化归档**，并证明了"每节点每次更新至少常数开销"是硬下界。这类工作把工程直觉变成了可依赖的约束。
4. **去重技术正在成为通用工具而非云存储专属**。三篇跨域工作说明：一旦把"等价性判据"从密码学标签相等性换成 Simhash+S-W、近似匹配、语义嵌入阈值，同一套思路就能解决**数据质量（医疗）、存储介质鲁棒性（DNA）、星上带宽（遥感）**三类完全不同的问题——且在这些场景里，去重率越高反而**同时**意味着鲁棒性越好（Sensintaffar：链越短隔离越强）。

## 9.2 五个仍空白的方向

1. **块级去重 + 动态更新 + 多副本的正交打通**。Liu 做到了块级细粒度，但**未涉及数据动态更新与多副本**；Zhang 是文件级；Miao 明确只支持单一数据拥有者、未覆盖数据共享。**"块级去重 + 动态更新 + 多副本 + 群组共享"四者同时满足的方案在 2025 这一批中不存在**（2026 批同样不存在，见配套文件 §9.2）。
2. **"自证式审计"的密码学补救**。Miao 的挑战由被挑战方 CS 自己从区块哈希推导、证明也由 CS 生成、并由 CS 调用合约自行判定——防线只剩区块链不可篡改与事后仲裁。这与 Song 的做法（**证明由排除生成者的其它节点验证**）形成鲜明对比。**如何在"无 TPA"约束下恢复"挑战方—证明方分离"**，是这个方向最实际的理论缺口。
3. **密钥管理解耦的最后一公里**。Zhang 做到了加密密钥与文件数无关（IBBE + 无密钥服务器交互 → 零通信），但**用户存储仍是 $(F+1)|\mathbb G_1|$，随机文件标签 $\zeta$ 仍随文件数线性增长**。同时，低熵数据的暴力破解面被"搬走"而非"堵死"：CSP 长期持有 $c$ 与 $K_l=k_l\oplus H_2(F)$，且 $K_C'=H_2(F)$ 自校验反而给了攻击者一个**可离线验证猜测的预言机**。**"既能离线自校验、又不对低熵数据构成字典攻击"** 需要新的机制。
4. **理论成果到工程实现的桥**。Shi 与 Bonneau 两篇都无原型与实测：Shi 的提取器是准多项式时间、纠删码冗余 $R=e^{O(1)/\varepsilon}$ 常数可能很大；Bonneau 只给总量界不给逐元素分布，工程上难以为 FlyClient、OpenTimestamps 外推实际更新频率。**把这些渐近界落成可测量的参数表**是明确可做的工作。
5. **大模型场景的证据强度**。Yan Binyuan 那篇提出了一个合理的四层框架，但存在**无形式化证明、合成数据、无 SOTA 基线、多处内部数字自相矛盾（78% 称超 80%、平均 89% 称 >90%、HE 延迟自评 102ms 却批评他人 >100ms、摘要 ChatGLM-3 而实验 LLaMA 2-13B）**等问题；其"端到端同态加密推理 13B 模型仅 102 ms"在 HE 文献中极不寻常，很可能只有少量算子被同态化。**这个方向目前缺的是可复现、有外部基线的实证**，而不是更多框架图。
