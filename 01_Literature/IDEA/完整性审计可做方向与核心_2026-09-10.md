## 1. 方向 A：局部更新下的复制审计组合安全

### 1.1 核心

文件或归档的一部分更新后，不应只证明"新标签对应新数据"。要证明：**敌手在保留历史编码、联合压缩多个编码实例、并根据已见编码选择后续输入的情况下，仍不能以显著少于承诺的资源通过当前复制审计。**

要低成本复用未变化的编码，就必须解决跨实例的空间安全组合；实例 ID、版本号、Merkle 根都只解决命名与定位，不自动解决资源下界。

### 1.2 为什么这是审计主体问题

普通动态 PDP/PoR 关心当前数据能否验证或提取。复制审计还额外约束攻击者的**空间投入**：若允许用一份基础数据加少量状态即时生成多个副本，逐副本标签合法也无法给出复制资源保证。

同时要注意反向边界：**"保留旧版本＋补丁"不自动是攻击。** 只要它满足协议要求的可恢复性与资源约束，那就是合法存储表示。要防的是没有兑现目标保证的实现，而不是禁止一切压缩。

### 1.3 已被覆盖的部分（不能当创新）

- PoRep 与复制存储证明已研究合谋、资源投入与复制安全（Fisch；Damgård–Ganesh–Orlandi, CRYPTO 2019）。
- Mirror（USENIX Security 2016）已研究由服务器生成副本，故"客户端不生成所有副本"不新。
- iDDA（ePrint 2025/969，ITCS 2026）已在正式论文中提出自适应顺序组合障碍，并已优化摊销更新成本。

### 1.4 必须兑现的三个贡献

1. **受限组合安全模型与定理。** 先做两实例、两轮、单向依赖：敌手看过第一实例编码后选择第二实例输入。明确持久状态 S、挑战后计算预算 T、外部下载预算 Q、有效实例集合与退休时点；给出跨实例空间保证，或该模型下局部复用的不可行性/代价下界。
2. **允许局部复用的编码机制。** 候选骨架是输入先承诺、实例独立随机性、明确生命周期、只重编码变化实例及必要依赖闭包。这些本身都是已有工具，真正贡献必须是**为什么在相关辅助信息下仍有可证明的资源保证**。
3. **同保证下的可衡量优势。** 目标可以是最好更新时间、编码读写量、峰值临时空间或实际常数；不要预先承诺所有指标都降到常数。

### 1.5 必须击败的基线

静态方案全量重编码、独立分段封装、**最终优化的 iDDA**（不是它的中间方案）。普通动态 PDP/PoR 只作较弱保证的性能参照，并须单独标明安全差异。

### 1.6 停止条件

如果最后只是分段、加版本号、加 Merkle 根，或只能给出单实例不可伪造证明，则不足以独立成为一篇论文。

## 2. 方向 B：聚合审计的信息损失（本次重点，扩展见配套文档）

### 2.1 核心

**如果服务器能预先把数据 D 变成无法恢复 D 的状态 z，并只靠 z、标签和索引回答全部未来挑战，那么协议实际审计的是 z，而不是 D。** 新 nonce、区块链存证或更多随机抽样都不能自动消除这种结构性缺陷。

### 2.2 关键区分（写论文时必须分开）

- **信息论损失**：多个 sector 永远只以固定的和出现，丢失了不可逆的维度。
- **计算上不可提取**：例如只保留 g^d，可能并未省下同等比特，但在离散对数假设下无法有效恢复 d，却仍能生成全部应答。

两者不能都不加区分地称为"物理存储压缩"。

### 2.3 为什么值得做

已有具体公式线索，且可以用较小成本迅速验证或否证：

- Song 2025（TC）：响应结构为 ψ=Σ_i v_i Σ_j c_{i,j}，系数不随 sector 下标变化。
- Li Hang 2026（ICAIDE）：响应数据依赖经过 H_agg=Σ H(c_i)。
- OTGPDP 2025（CMC）：验证关系允许由原标签直接构造响应。

### 2.4 已被覆盖的部分（不能当创新）

- Shacham–Waters 2008 已把紧凑聚合证明与可提取性联系起来。
- Paterson–Stinson–Upadhyay 2012 已用 response code 给出精确提取阈值与统计方法。
- KDPoS 2018 已在关键词审计中使用变化系数、满秩矩阵与纠删码提取。
- Zhu 2026 已有"删数据、留哈希和标签仍能过验证"的分析。

因此：**"可提取性""满秩条件""给抽样补均匀探索"都不能作为新概念。**

### 2.5 三个主要贡献（详见扩展文档）

1. 面向聚合审计的**应答充分状态分析方法**（分析规则＋可靠性定理＋可复核证书）。
2. 在**多个实际方案**上发现并复现新攻击（Song、OTGPDP 优先，Li Hang 次之）。
3. 构造**可提取性保持的聚合审计机制**（静态多 sector、公开验证、批量聚合、完全恶意服务器）。

### 2.6 停止条件

若最后只是一处公式漏下标加标准 PoR 替换，应写成密码分析短文，不要硬扩为完整新原语论文。

## 3. 方向 C：去重回收与重编码中的存续文件可提取性

### 3.1 核心

在块级去重存储中，删除一个文件、合并编码条带或回收未引用块之后，**应证明每个仍有效文件的恢复条件继续成立**。只证明"剩余块标签是真的""引用计数格式正确""新根经过签名"，并不自动证明该文件可从当前存储状态恢复。

这不是"去重＋动态＋多副本"的功能组合。研究对象是**共享恢复依赖改变时，审计的提取保证如何局部更新并保持**。

### 3.2 失效机制（务必说明不是本报告首次发现）

文件 A 与 B 共享数据块 x，B 另有私有块 y，且 x、y 与其他数据可能被跨文件编码进同一条带。删除 A 后，有的块没有直接引用，却仍参与保护 B 的编码关系。若云只按直接引用回收、未正确维护剩余条带，就会出现"列出的块各自真实，B 的恢复能力却下降"的状态。

RAD 2018（NAS）原文已明确讨论该现象：被删除块即使不再被文件引用，仍可能处于保护其他块的编码条带中，直接回收会破坏容错，需要重编码。PFP 已研究 per-file parity。

### 3.3 已被覆盖的部分

- Message-Locked PoR with Secure Deduplication（CCSW 2016）已研究去重与可恢复证明的结合。
- 透明去重审计已有一次验证同时检查所有者数量与完整性。
- 动态 PoR 已支持更新与当前数据提取，最新版本绑定不是空白。

### 3.4 最小模型与新机制落点

先不引入访问控制、TEE、链上支付与物理多副本。只考虑一个去重域、授权文件删除、明确的线性纠删码、完全恶意的存储与元数据管理者。

设唯一数据向量 x，编码符号 y=Gx，文件 f 对应投影 L_f x。线性模型下恢复文件需要 rowspan(L_f) ⊆ rowspan(G_R)。

**这个线性代数条件本身不是创新，也不是审计证明。** 云给出满秩编码矩阵，不等于它仍保存该矩阵对应的数据。需要把经过认证的存续文件关系、合法转换关系与当前数据的 PoR 应答绑定起来。

**核心贡献门槛**：在不让所有无关所有者重新上线、不重审整个唯一块库的条件下，证明局部验收后原保证仍对每个存续文件成立。局部成本按实际受影响依赖闭包 d 衡量，**不要不加条件地承诺 O(log n)**——最坏情况下共享图可能连接全库。

### 3.5 必须击败的组合基线

1. 对唯一块库做标准动态 PoR，另行认证各文件的有序 recipe。
2. RAD/PFP 的编码管理＋上述动态 PoR。
3. 每个文件独立 PoR（测量重复标签与重复审计成本）。
4. 通用 SNARK/STARK 证明整次重编码转换，再接标准 PoR。

### 3.6 停止条件

若结果只是引用计数签名、Merkle 更新或按引用次数加权抽样，停止以此为核心创新。

## 4. 方向 D：客户端单遍处理下源数据绑定的恶意外包预处理（仅备选）

### 4.1 核心

当同一个恶意云既生成编码/标签又保存数据时，**客户端轻量验收必须保证以后能提取的是客户端原始文件，而不只是云任意选定的一份承诺数据**。

### 4.2 为什么只列备选

该方向高度拥挤：

- Benabbas–Gennaro–Vahlis（CRYPTO 2011）已把可验证委托用于 PoR。
- Outsourced Proofs of Retrievability（CCS 2014）及其 2018 期刊版已存在（原文待补核）。
- OTGPDP 2025 直接让恶意云同时生成标签与存储。
- MIDAS 2026 明确考虑不可信边缘节点。
- DAS 已考虑恶意 committer；FRIDA（CRYPTO 2024）用满足一致性条件的 IOPP 构造纠删码承诺与 DAS，透明设置、多对数开销。

### 4.3 若要做，唯一值得保留的窄问题

明确系统型 RS 编码；客户端单遍计算 c=H(ctx∥M) 并只保留小状态，无逐块公钥运算；单个恶意云同时编码与存储。需要证明：初始化验收及后续高成功率 ⇒ 提取器输出 M′ 且 H(ctx∥M′)=c。

必须精确规定客户端是否还能做域运算、随机指纹、第二遍读取——**不能把这些都笼统叫"只哈希"**。

哈希绑定原输入不证明编码正确；编码正确不证明以后仍存储。用通用证明连接 H(M)=c 与 E=Enc(M)，再做 PoR，是必须比较的已有组合。

## 5. 已被检索否决或降级的方向

| 看起来可做的方向 | 为什么不能直接作为核心创新 |
|---|---|
| 关键词审计＋自适应查询＋满秩提取 | KDPoS 2018 已有；response-code 理论更早给出一般提取条件 |
| 热门查询审计，再加少量均匀探索 | 通常是标准 PoR/抽样分析；且 Song 已另审未搜索文件 |
| "第一次允许恶意助手" | MIDAS、OTGPDP 及外包 PoR 已有直接或强相关覆盖 |
| 统一搜索证明本身 | Song 2025 已做；只能研究新的安全缺陷或在明确新目标下改进 |
| 标签、副本、身份全部上链 | 存证与执行机制，不自动强化数据提取或复制安全 |
| 只换无证书、格密码或 TEE | 原语/信任根替换，未必触及新审计问题 |
| 按唯一块/引用次数抽样 | 抽样总体与加权策略本身太薄；不能混淆块损失率与文件损失 |
| 动态＋多副本＋访问控制＋后量子 | 功能组合，查重空间过大，没有独立核心机制 |
| 静态复制证明简单分段、加版本号 | 必须比较现有分段封装，并证明跨实例资源安全 |
| 仅补写缺失的形式化证明 | 若只是补全已有标准归约，不足以自动成为新的研究贡献 |
| 真实查询流受限的提取预算 | 不能仅靠 rank(A)=n 立项；需新紧界或非平凡协议，当前降级 |

关于最后一条的细化：在线性编码 x=Gm 下应关注**已接受应答**对应的 rank(A_acc G)，而非发出挑战数或坐标覆盖率；服务器可能选择性拒答；跨版本应答不能直接拼秩；过去日志可重建旧文件不意味着当前服务器仍保存文件。只有新的紧成本界或非平凡协议才值得另立题。

## 6. 全部方向共用的硬性约束

这些是前面检索中反复出现的判断，写作与实验时都适用：

1. **样本文献未覆盖 ≠ 全领域不存在。** 功能表中加一列不足以立题。
2. **公开挑战不自动不安全。** 关键在承诺是否先冻结、随机性是否可预测或可偏置、是否允许挑选挑战、验证是否真由合约执行。
3. **标签不可伪造、数据可提取、复制空间保证、物理故障域分散是四种不同性质**，必须分别声明与证明。
4. **验证方程正确、随机损坏检出率，都不能替代可提取性。** 检测概率 P_detect=1−(1−α)^c 只是参数选型依据。
5. **约 459/460 个样本不等于固定抽查 4.6%。** 该数字对应独立有放回抽样、损坏比例 1%、检出率 99%；比例随总块数变化，无放回要用超几何概率。
6. **"保留旧版本＋补丁"不自动是攻击**；合理的回收也允许改变数据表示。
7. **密码学复制证明不自动证明地理分散。** 不同副本有不同标签也不自动证明投入了多份空间。
8. **区分预印本与正式发表年份。** iDDA 为 ePrint 2025/969、正式版 ITCS 2026。
9. **不要把使用环结构的格方案笼统说成已被攻破**；"格哈希＋经典配对"也不能据格哈希一项声称整体抗量子。
