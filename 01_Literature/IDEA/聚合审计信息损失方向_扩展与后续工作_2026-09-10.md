## 1. 方向核心

**如果服务器能预先把数据 D 变成无法恢复 D 的状态 z，并只靠 z、标签和索引回答全部未来挑战，那么协议实际审计的是 z，而不是 D。**

换句话说：某方案可能有完整的正确性证明、完整的抗伪造论证、以及很高的随机损坏检出率，但**"通过审计"与"数据仍然可提取"之间仍然可能脱节**。挑战加入新 nonce、把结果上链、增加抽样次数，都不能自动修复这种结构性缺陷。

### 1.1 必须先承认的两条边界

1. **短证明不等于信息丢失。** 标准 PoR（Shacham–Waters 2008）本来就允许单次证明很短，通过多次不同挑战实现提取。要找的是"**所有未来挑战都无法突破某个固定摘要或投影**"，而不是"证明很短"。
2. **"响应秩不足"不等于整篇方案不安全。** 服务器还保留标签、文件哈希、索引与编码信息。必须分析**完整保留状态**，而不是只看某个公式的矩阵秩。

## 2. 三类失效机制（扩展后的分类）

这是方向扩展的核心内容：把"信息损失"从一句直觉，拆成可以逐项检查、可以分别证伪的三类机制。

### 2.1 固定投影型（信息论损失）

数据永远只经某个固定线性映射 Bx 进入应答。若 B 的像空间维度低于原数据维度，且没有其他约束，服务器保留 Bx 即可回答任意未来挑战，而原数据已被不可逆地压缩掉。

**检查要点：** 先确定数据进入应答的完整路径（含哈希、公开群编码、线性投影），再判断约束条件与辅助信息是否足以恢复。**不能只看响应公式的秩。**

### 2.2 摘要替代型

全部响应只依赖 H(m_i) 一类的逐块摘要，与原始块脱离。服务器可预存摘要、删除原数据，在任意新挑战后重新生成同分布应答。

**关键限定：** nonce 与服务器签名只绑定新会话，**不会迫使服务器重新读取原数据**。

**已验证实例（2026-09-11 更新）：** Li Hang 2026 是这一类目前唯一同时满足"等式可通过""摘要状态确实更小"的实例。其验证式 `e(g^s, Π_{i∈Q}g^{r·H(c_i)}) = e(g^r, g^{s·H_agg})` 在双线性下等价于 `H_agg ≡ Σ_{i∈Q}H(c_i) (mod q)`，服务器只需预存逐块摘要。L2 结果与限定见 `tmp/reproductions/aggregate-audit/results/lihang2026/l2-final-20260911/analysis.md`。

**但该实例的模型地位特殊：** 原文形式模型要求服务器在审计过程中诚实执行挑战—响应，因此它属于"安全模型覆盖不足/主张超出模型"，**不能与 Song、OTGPDP 并列为原模型内攻击**。三类机制各有一个实例，恰好说明分析结果必须附带模型边界，而不能只报"攻击成功"。

### 2.3 公开标签型

利用公开标签和群运算即可生成响应，但无法有效恢复原始域元素。典型形态是服务器保留原标签 t_i，直接由 t_i 与公开系数构造出满足验证等式的响应。

**关键区分：** 这里未必省下同等数量的比特（见 §4.2），所以必须与 2.1 的信息论损失分开陈述。

## 3. 三个主要贡献（论文成立所必需）

论文结构建议为**"方法—攻击—机制"**三贡献，实验与原型作为第四项支撑。这样分别回答：为什么失效、哪些方案确实失效、怎样在保留效率的前提下解决。

### 3.1 贡献一：面向聚合审计的应答充分状态分析方法

**要建立的东西：** 从实际协议公式中构造**可检查的失效证据**，而不只是抽象说明"应该能恢复数据"。

研究对象是服务器保留的完整状态：

```
Z = { 数据摘要或投影、标签、索引、公开辅助信息 }
```

检查两个条件：

- **充分性**：服务器能否仅凭 Z 回答全部合法挑战？
- **可提取性**：原数据能否从 Z 有效恢复？

前者成立、后者不成立，就是需要解释的审计漏洞。

针对受限的同态审计表达式，建立三类检查规则（对应 §2 的三类机制）：固定投影型、摘要替代型、公开标签型。

**真正的贡献是"分析规则＋可靠性定理＋可复核证书"**，例如工具输出具体保留状态、作弊应答算法以及提取失败依据。不能把"算一下矩阵秩"或"给攻击起个新名字"算作创新。

**2026-09-11 已获得正负对照：** 分析判据可写成"响应是否在每个独立方向上给出聚合，且足够多次挑战后该方向集合满秩"，并由 `results/baseline/baseline-final-20260911/` 验证——同一"只存块和"的证明者在独立底数构造下 0/80 接受，在共用底数构造下 80/80 通过。这使"能区分可靠构造与候选方案"从设计目标变成已测事实。

**证书已可机器校验：** `tmp/reproductions/aggregate-audit/scripts/analysis_certificate.py` 为四个案例生成证书并强制"证书计数＝运行记录计数"，同时要求非原模型内的案例显式写出不主张什么。产物见 `certificates/aggregate-audit-certificates.json`。这是当前最接近"可复核证书"这一贡献要求的产物。

**创新门槛：** 不能声称"首次定义可提取性"——2012 年的 response-code 工作已经给出一般分析框架。新增能力必须是**针对聚合审计表达式的、可执行的失效判定**。

这一项提供真实研究对象，证明贡献一不是为某个公式量身定制。目前有三类候选，**证据强度不同，必须如实标注**：

以第一类为例：若响应始终为

```
ψ = Σ_i v_i Σ_j c_{i,j}
```

服务器就可能只保存 `z_i = Σ_j c_{i,j}`。**增加挑战次数只能获得更多关于 z_i 的信息，不能恢复已经被固定求和消掉的 sector 差异。**

这一贡献不能停在"等式看起来能通过"。必须完成完整链条：

合法初始化 → 构造作弊状态 → 删除原数据 → 接受大量新挑战 → 检查实际恢复。存储统计必须包括标签与元数据，并区分"省存储"和"计算上无法提取"。

**成立门槛：** 多个独立方案上的新结果，并准确区分原模型内攻击与模型不足。三篇论文出现同一个笔误，不自动等于三个独立发现。

### 3.3 贡献三：构造可提取性保持的聚合审计机制

这是最贴近"完整性审计主体创新"的部分。目标不是给原方案加区块链或 SNARK，而是重新设计**数据如何进入挑战响应、响应如何被认证、多个对象如何安全聚合**。

**建议先限定的范围：** 静态多 sector 文件、公开验证、批量聚合、完全恶意服务器。第一版不要同时加入动态更新、去重、匿名与访问控制。

机制应满足三个相互关联的要求：

1. **挑战改变时能访问原数据的不同有效方向**，而非反复证明同一个固定投影。
2. **验证必须约束可用于提取的数据响应**，不能让公开标签单独成为足够的应答材料。
3. **聚合后仍能把有效响应用于相应文件的提取**，防止文件之间抵消错误或混用状态。

一个探索方向是：挑战相关的 sector 投影 ＋ 与认证信息绑定的响应 ＋ 可提取的跨文件聚合。但**随机投影、独立底数、向量承诺各自都不是新技术**；只有设计出具体机制并超过现有组合，才算这一项贡献。

**必须证明的是：足够高的审计成功率能够推出对已承诺原文件的有效提取**，而不仅是标签不可伪造。效率要与标准 SW-PoR、逐文件验证、已有批验证及"承诺证明＋PoR"比较，完整计入响应、标签、客户端状态与提取成本。

**当前状态：这是研究目标，不是已经得到的新构造。** 若最后只是把同一底数换成独立底数、恢复标准 PoR，属于修复，不足以单独宣称新的聚合机制。

### 3.4 第四项支撑（不作为核心贡献）

原型与实验。可以列为第四项成果，但**不应单靠"做了实验"凑核心贡献**。自动分析方面已有 ACABELLA 等邻近研究；若开发工具，须说明针对审计提取性的新增能力。

### 4.2 三个容易说错的技术点

1. **在 Z_N 上不能直接套用素数域高斯消元。** 原文使用复合阶群；必要时要处理整数关系、可逆元或明确的分析前提。
2. **存储节省要看实际位长，并且必须实测。** 若使用整数和，和的位长可能是 n+log s 位，而不是 n·log s 位；若使用模运算，要按原文的指数模数分析。**不能武断写成"总存储严格缩小 s 倍"。**

   **2026-09-11 实测更正：** `results/state-accounting/acct-final-20260911/` 用大参数后端做规范二进制测量后，两条旧结论需要修正——① Song 的"攻击状态比原数据更大"是缩减参数下 JSON 框架造成的假象，真实尺寸下内容部分确实被压缩（`n·s → n` 个域元素；8 sector 内容 8×、总计 3.33×；`s=100` 内容 100×、总计 34×）；② Zhang 的"约 50×"只算每块内容且用压缩编码，计入两边都有的标签后为 20.4×（未压缩）／33.3×（压缩）。**只有 OTGPDP 的标签状态确实更大**（34,461.8 B vs 689.9 B），因为它的缓存是原标签本身。论文中给出倍数时必须写明**编码口径**（压缩／未压缩）与**是否计入标签**。
3. **不能要求构造哈希碰撞。** 若策略保留了原文件标识 ID_F=H(C)，应明确它通过的是**审计**，不能通过**真实下载后的重哈希**——这恰好说明审计与可提取性之间存在脱节。

- 覆盖全部八个算法（Setup、KeyGen、Insert、Delete、Search、Proof、Verify.Search、Verify.Audit），而不只实现 Eq.(7)(10)。

- 原文使用复合阶群 N=pq 与 C++/PBC/GMP/OpenSSL；**不能直接替换为素数阶曲线并称为忠实复现**。若先用不同群做结构验证，明确标成独立变体。
- 明确 sector 的字节编码、s 是否允许大于 1、原文实验 s 取值、模数、响应是否取模。
- 把搜索过文件的统一证明与未搜索文件的独立审计分开（原文不等于只审热点文件）。
- 攻击目标首先针对原文所称完整性（Definition 5），不把未声明的 PoR 定理强加给作者。

**OTGPDP：**

- 覆盖全部八个算法（Setup、DataProcess、MetaGen、MetaVer、Challenge、Proof、Verify、DataUp）。
- 攻击者可用自己的合法服务器密钥，但**不能拿到客户端私钥**。
- 出版方 HTML 写 CBF 计数"大于 1"，标准成员检查通常是"大于 0"。**必须核对 PDF**；先记录逐字版本的诚实表现，不擅自改掉条件。
- 原文中 p 同时出现在群阶、CBF 大小公式及 DataUp 描述中，需逐处核验；更新中的数据/标签混用与计数增减**不能自行补成新协议**。
- 若逐字实现不能正确运行，分开报告"原文可执行性问题"与"显式修正变体下的攻击"。
- 原文为 PDP：标签应答攻击应分别评估其不可伪造/可检测声明与我们额外关心的提取性。

### 5.4 诚实对照与实现要求

- 检索作者主页、补充材料与代码仓库，记录链接、版本与许可证；未找到只写"未找到公开实现"。
- 在本目录建立隔离环境，新增依赖不写入全局环境。
- **真实群元素不能用"暴露离散对数的整数对象"替代**；哈希到群、成员检查、序列化、配对一致性需独立测试。
- 诚实测试覆盖：单文件、多文件、多关键词、空搜索结果、重复查询、合法增删改及更新后审计。原文不支持的操作不硬加。
- 原样失败的情况保留并分析；允许归档明确说明的修正变体，但**禁止修改原验证器以迁就攻击或让测试变绿**。
- 区块链适配器只负责原文规定的发布、读取与挑战生命周期；使用本地适配器时明确未复现共识与链上成本。

### 5.5 作弊进程隔离规则

诚实初始化后，将允许保留的状态序列化。作弊证明者在新进程运行，只能读取这些状态与新挑战，**不能访问原数据、客户端秘密、恢复真值或生成原数据的种子**。

原始数据与实验种子由测试控制器保存用于结果比较，不向作弊进程暴露。清点缓存、日志、临时文件与进程参数，避免"删除变量但仍保留完整数据引用"。

**只能主张指定存储/访问模型内的结果，不能用进程隔离假装证明任意现实攻击者的安全。**

### 5.7 可提取性与资源核算

- **Song：** 分析全部保留信息（文件哈希、标签、索引、客户端侧信息、可能的编码约束），不能只因某响应矩阵秩不足就断言完整状态不可恢复。

  **2026-09-11 已补严格论证：** `tmp/reproductions/aggregate-audit/evidence/song2025/extractability-argument.md` 给出三条结论：(a) 应答映射严格经过 `Z`（充分性引理，故审计不提供关于"是否仍持有 C"的信息）；(b) `s ≥ 2` 时 `C ↦ 块和` 非单射，且存在产生完全相同标签与应答的 `C ≠ C'`；(c) 原文 Definition 5 的表述因此被否证。同时明确**不主张**整体状态的信息论不可提取性——`ID_F=H(C)` 确实携带信息，只能写成"在 `H` 原像困难假设下、且不考虑分布先验"的条件命题，并列出两项未完成工作（针对哈希约束的求原像尝试、候选集规模上界）。**该文档原先放在运行目录内，因重跑被清空，已移到 `evidence/` 稳定位置。**
- **不要求构造哈希碰撞**；策略若保留原 ID，应明确它通过审计、不通过真实下载后重哈希。
- **OTGPDP：** 分清存储空间节省与计算不可提取。g^d 可能与 d 一样长；小取值域的 d 可能被穷举恢复，不能一概归因于离散对数困难。
- 区分外包数据 D 与原始明文 D\*；客户端是否持有解密密钥、掩码种子，以及这些辅助信息是否帮助提取，必须在模型中写清。
- **恢复程序失败不是不可提取性证明。** 须给出适用输入分布下的不可区分性/信息量/计算假设论证，或明确这里只是恢复测试失败。

### 5.8 结论分级

## 6. 风险与本方向的最终判断

### 6.1 主要风险

1. **攻击可能不成立。** 原文可能还有未注意到但成立的额外检查（编码约束、签名覆盖、CBF 语义）。
2. **可能只是单点笔误。** 若最终只得到"某式少了一个下标"，适合密码分析短文，不足以独立成为完整论文。
3. **可能被否定但仍有价值。** 若三篇都挡住攻击，得到一个有说服力但**负面**的结论，仍是有效研究产出，只是要如实收窄。
4. **环境风险。** 复合阶配对后端（PBC）在新平台构建困难；须预留时间并记录构建过程。

### 6.2 本方向的最终判断

**这是当前最值得先启动的方向：线索具体、成本最低、结论最快，能直接决定贡献二是否成立。**

但必须清醒：**"已发现新的代数策略"与"可形成一篇论文"之间仍有明显工作量。** 只有当（a）拿到多个独立方案上的新、已复现实例，且（b）配上有用的统一分析方法或非平凡修复时，贡献二才真正成立。

若最终无法获得非平凡的新机制，应诚实转为"统一分析＋新攻击＋证书化分析工具"的系统密码分析论文，**不要把标准修补包装成机制创新**。

### 6.3 2026-09-11 更新后的实际判断

三条贡献的当前状态：

| 贡献 | 状态 | 已兑现的证据 | 仍缺什么 |
|---|---|---|---|
| 一：应答充分状态分析方法 | **基本可写** | 三类机制各有一个逐式定位的案例；可检验判据（每方向聚合＋满秩）；认证可提取基线的正负对照；可机器校验的证书 | 面向"受限表达式"的形式化判定规则与可靠性定理；工具需支持"证据不足"并覆盖更多表达式形态 |
| 二：多个实际方案的新攻击 | **已兑现（两例原模型内、均完成 L2）** | Song 2025（IEEE TC，固定 sector 投影，缩减参数复合阶配对 L2）与 Zhang 2025（IEEE TC，块和投影 + 验证式不绑定挑战，缩减参数素数阶配对 L2，含单块 O(1) 状态）；另有两例方法案例（OTGPDP 显式变体、Li Hang 模型错位） | 注意 Zhu 2026 已公开该攻击**类别**，因此新颖性来自统一判据、证书、跨方案实例与模型边界分级，而非"首次发现"。**另有一处结构性弱点：两个原模型内实例同属 §2.1 固定投影型**，审稿人可指为"同一类缺陷出现两次"；若要论证"跨机制",需一个 §2.2 摘要替代型或 §2.3 公开标签型的**原模型内**实例 |

**因此当前可负责任的论文形态是系统性密码分析**（贡献一为主、贡献二以两例原模型内实例支撑、附正面对照与证书化工具），而不是"新聚合机制"论文。升级为含贡献三的完整原语论文需要满足其一：把修复判据做成能证明提取性的具体构造并给出成本优势；或补一个**非固定投影型**的原模型内实例，使贡献二真正跨机制。
